# CogniGuard 架构分析与重构建议

## 一、当前架构问题分析

### 当前目录结构
```
CogniGuard/
├── frontend/                    # 前端
├── backend/                     # 后端（含agents、API等）
├── hsw_st_minimal/             # 水印与来源追踪保护机制
├── fopd_c2rag_mvp/             # 学生画像与版权检索保护机制
├── guardrails/                  # NeMo Guardrails配置
├── data/                        # 数据目录
└── scripts/                     # 脚本工具
```

### 主要问题

1. **保护机制模块定位不清晰**
   - `hsw_st_minimal`、`fopd_c2rag_mvp`、`guardrails` 这些核心保护机制散落在根目录
   - 它们既不属于前端也不属于后端的传统分类
   - 作为独立的算法/服务模块，应该有更清晰的定位

2. **模块职责混淆**
   - 这些保护机制是**后端服务的核心能力组件**，但放在根目录让人误以为它们是独立项目
   - `fopd_c2rag_mvp` 名字带 "mvp"，但实际是生产级保护层

3. **缺乏层次感**
   - 无法快速理解项目的核心架构（三层保护+TPCS横向治理）
   - 新开发者需要阅读 README 才能理解模块关系

## 五、关键决策点

### Q1: 保护机制应该放在 backend/ 里面吗？

**建议：不要**

理由：
- 你的保护机制是**核心学术贡献**，不是普通的后端业务逻辑
- 它们是**跨项目可复用的算法库**，不应与特定后端框架耦合
- 独立成层有利于**论文写作、开源发布、独立测试**

### Q2: 三层保护需要物理分离还是逻辑分离？

**建议：物理分离**（方案A）

理由：
- 每层有独立的依赖（FOPD需要sklearn，HSW-ST需要transformers）
- 每层可以独立运行和测试
- 方便不同研究人员并行开发
- 符合你 README 中强调的"三层闭环架构"

### Q3: fopd_c2rag_mvp 应该拆分吗？

**建议：拆分**

理由：
- FOPD（学生画像保护）和 C2-RAG（教师资源保护）是两个独立的创新点
- 它们对应不同的保护层（第1层 vs 第2层）
- 当前合并在一个 MVP 中是为了快速验证，长期应分离

### Q4: guardrails 的定位？

**建议：作为横向治理层**

理由：
- 你的 README 明确说明 TPCS 是"横向治理控制器"
- Guardrails 不属于三层中的任何一层，而是跨层的政策执行
- 应该放在 `protection/guardrails/` 或 `governance/`

3. **论文写作需要独立的实验章节**

#### 2. 更新 .gitignore


#### 3. 移动现有日志
```bash

```

#### 4. 更新启动脚本

如果你用脚本启动服务，需要修改日志输出路径：

**server.py 或启动脚本：**
```python
# 原来：

# 改为：

```

**package.json（前端）：**
```json
{
  "scripts": {
    "dev": "vite 2> logs/frontend-vite.err.log | tee logs/frontend-vite.out.log"
  }

```

### logs/ vs outputs/ 的区别

| 目录 | 用途 | 内容示例 | 是否提交Git |
|------|------|---------|------------|
| **logs/** | 运行时日志 | 错误堆栈、调试信息、访问日志 | ❌ 不提交 |
| **outputs/** | 结构化结果 | 实验数据、指标JSON、图表PNG | ✅ 可选提交（看需求） |

**区别：**
- `logs/` 是**瞬态的**、人类阅读的、用于调试的
- `outputs/` 是**持久的**、机器可读的、用于分析的

### 日志轮转建议（可选）

如果长期运行，日志文件会越来越大，建议：

**方案1：Python logging 配置**
```python
import logging
from logging.handlers import RotatingFileHandler

handler = RotatingFileHandler(
    'logs/backend-server.log',
    maxBytes=10*1024*1024,  # 10MB
    backupCount=5            # 保留5个历史文件
)
```

**方案2：外部工具**
- Linux: `logrotate`
- Windows: PowerShell 定时任务清理
