# CGC 可选语义安全判别器

## 结论

这类组件在现代安全系统中很常见，但它应该是 CGC 的可选第二阶段适配器，不应替代 CGC 的固定规则和治理状态。

类似思路包括：

- NeMo Guardrails 的 self-check / rail 判别流程；
- Llama Guard、ShieldGemma、Granite Guardian 等安全分类模型；
- WildGuard 等同时关注有害请求、拒答和过度拒答的安全判别研究；
- 许多生产 Guard 服务采用规则筛查后再调用语义分类器。

这些方案的共同结构是：规则层处理硬约束和可审计字段，语义层处理同义改写、隐晦表达和跨语境泛化。

## CGC 中的职责

```text
用户输入
   ↓
CGC 固定规则层
   ├─ 高置信有害：block
   ├─ 明确安全：allow
   └─ 边界样本
          ↓
     可选语义安全判别器
          ↓
     allow / refuse / block
```

语义判别器只输出风险标签和置信度，不拥有：

- 身份和 Capability；
- 隐私、版权和水印预算；
- provenance 和上下文边界；
- 审计、回滚和跨模块冲突解决。

这些仍由 CGC Controller 管理。

## 已实现接口

代码：`backend/app/protection/cg/semantic_safety_adapter.py`

当前提供模型无关接口，可以注入：

1. 冻结的 Hugging Face 安全分类模型；
2. 经过 calibration split 训练的 TF-IDF/Logistic Regression 基线；
3. 本地安全小模型或外部安全服务。

接口不会在生产运行时自动下载或训练模型。

## 评价方法

语义判别器必须单独报告：

- Calibration / validation / held-out test 划分；
- 有害召回率、正常误拦率、Precision、F1、Balanced Accuracy；
- 按直接伤害、虚构、历史、定义、游戏、隐私、间接注入分组；
- 阈值—Recall—FPR 曲线；
- 第一阶段规则、第二阶段判别器和总延迟。

当前已完成 MiMo-native execution of the NeMo self-check policy：完整 JailbreakBench F1=0.853、XSTest F1=0.931，但 JailbreakBench 正常误拦率为 33%。因此它暂不直接接管 CGC 主路径，下一步只作为高风险/边界样本的可选二阶段，并使用 calibration split 校准调用条件。
