# MM-FOPD 指标口径与组会对照表

## 1. 为什么前后两次表格不一致

上次组会使用的是 `formal_v2` 的 96-case 表，主要回答“有没有泄露敏感画像、平均花费多少隐私成本”。本次开发实验使用 144 个任务和每人 50 条纵向画像，主要回答“在复杂画像中保留了多少必要信息”。两组指标回答的问题不同，不能用新版指标直接替换旧版指标。

因此后续汇报固定保留两层指标：

1. **安全与成本主表**：隐私 ASR、敏感画像暴露率、正常流程通过率、平均隐私成本、保护收益成本比；
2. **任务效用解释表**：必要单元召回、单元 F1、实际外发暴露。

## 2. 指标定义

### 敏感画像暴露率

```text
Sensitive Profile Exposure Rate
= 选择或释放至少一个高敏感画像单元的请求数 / 总请求数
```

当前统一将 `sensitivity ≥ 0.7` 视为高敏感画像单元。

### 平均隐私成本

沿用上次组会实现：

```text
PrivacyCost_i = 0.1 × Σ Sensitivity(selected record)

Average Privacy Cost = (1 / N) × Σ PrivacyCost_i
```

它测量内部选择阶段承担的隐私成本，不等于最终文本长度，也不等于实际敏感值泄露率。

### 老师建议的除法指标

如果直接计算：

```text
敏感画像暴露率 / 平均隐私成本
```

所有零暴露方法都会得到 0，仍然无法区分。因此主表采用：

```text
Privacy Protection Efficiency (PPE)
= (1 − Sensitive Profile Exposure Rate) / Average Privacy Cost
```

`PPE` 表示每单位隐私成本获得的敏感画像保护收益，越高越好。

注意：PPE 只衡量安全与成本，不包含教学效用。不能只凭 PPE 判断完整方法最好。

|---|---:|---:|---:|---:|---:|
| FullProfile | 18/18 (100%) | 96/96 (100%) | 48/48 (100%) | 0.5456 | 0.00 |
| Relevance-Only | 0/18 (0%) | 16/96 (16.7%) | 48/48 (100%) | 0.1395 | 5.97 |
| Static-Minimization | 0/18 (0%) | 0/96 (0%) | 48/48 (100%) | **0.1321** | **7.57** |

旧版结论：Full MM-FOPD 阻止了敏感画像暴露，但成本略高于 Static-Minimization，因此旧结果不能证明完整方法在隐私成本效率上最优。

## 5. 应如何解释当前结果

不能说 MM-FOPD 在所有隐私指标上最好。正确结论是：

> MM-FOPD 在 144 个 development 任务中保持零高敏感画像选择，同时取得最高必要单元召回和单元 F1；其平均隐私成本和纯保护收益成本比不是最优，说明完整方法用额外的低敏感任务信息换取了更高教学上下文效用。

相对 GPG-style：

```text
必要单元召回比 = 0.745 / 0.539 = 1.38
单元 F1 比     = 0.829 / 0.673 = 1.23
隐私成本比     = 0.1423 / 0.1629 = 0.87
```

即 MM-FOPD 的召回约高 38%，单元 F1 约高 23%，平均隐私成本约低 13%，并将高敏感画像暴露从 45.1% 降为 0。

相对 LLM Minimization proxy：

```text
必要单元召回比 = 0.745 / 0.505 = 1.48
单元 F1 比     = 0.829 / 0.654 = 1.27
隐私成本比     = 0.1423 / 0.0839 = 1.70
```

即 MM-FOPD 以约 1.70 倍隐私成本换取约 1.48 倍必要单元召回和 1.27 倍单元 F1。这是隐私—效用权衡，不应包装为全面领先。

## 6. 汇报时推荐使用的两张表

正文第一页使用第 4 节的统一主表，保留老师要求的敏感画像暴露率、平均隐私成本和 PPE。下一页再展示必要单元召回和单元 F1，用于解释为什么不能只选择最低成本方法。

`外发暴露`不再与`敏感画像暴露率`混写：

- 敏感画像暴露率：是否触及高敏感画像单元；
- 实际外发暴露：最终 context card 相对完整画像的信息量；
- 平均隐私成本：内部选择字段的敏感度加权成本。

三者应分别报告。
