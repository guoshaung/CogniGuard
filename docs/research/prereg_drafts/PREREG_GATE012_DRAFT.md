## 1. 数据与请求流

- E5 的合成数据：K = 16 和 32，种子 0–9。这部分数据中 w ≥ 3 的见证较多。
- E6 的 Eedi 数据：K = 16，作为真实题库上的复核。
- 请求流与 E5 相同：N = 60，6 个共谋小组，c = 0。

## 2. 未记录传播（新增事件）

- 通信图：每个主体有 d = 3 个固定邻居，按种子随机生成。
- 每当某个主体实际持有一个单元后，它在接下来的请求之间，以概率 p_f 把这个单元转发给一个随机邻居。**转发不写回执。**
- 参数：p_f ∈ {0, 0.02, 0.05, 0.1}。
- 共谋小组按原来的方式请求。转发是非恶意的传播，与小组无关。
- 真实状态 K_actual = 回执中的持有，加上全部转发。

## 3. 对照组

| 组 | 用来做判定的状态 | k |
|---|---|---|
| capd_obs | K_obs（只看回执） | 4 |
| oracle | K_actual | 4 |
| robust_kf(f) | K_obs，联盟人数检查到 4 + f（第 3.2 节的归约，不用证据） | f ∈ {1, 2, 4} |
| evid_ideal(δ) | K_obs 加上真实转发的证据，证据延迟 δ 个请求后到达 | 4；δ ∈ {0, 5, 20} |
| evid_noisy(r, q, δ) | 只在 Gate 2 使用：证据召回率为 r，错误归因率为 q（证据被归到一个错误的邻居），延迟为 δ | 4 |
| evid_bounded(f, r, q) | 只在 Gate 2 使用：K_obs 加上已确认的 d 次转发，联盟人数检查到 4 + max(0, f − d) | — |

## 4. 指标

- **VR_actual**：在 K_actual 上计算的违规率。分成：
  - **VR_pre**：无法阻止的部分。违规在本组的任何一次后续放行之前就已经在 K_actual 上存在；
  - **VR_rel**：披露导致的部分。违规由本组的一次放行造成，而 oracle 在同一状态下会拒绝。
- UR_normal、DR_normal；
- 证据量和每次决策的耗时，只描述。

## 5. 判定

- **Gate 0（问题是否存在）**：在 p_f = 0.05 时，capd_obs 的 VR_rel > 0，并且种子间配对 bootstrap 95% 区间下界 > 0。同时报告 VR_rel 占 VR_actual 的比例 ρ。
  - **如果 ρ < 0.3**，说明大部分泄露在下一次披露之前就已经发生，闭环能挽回的部分很少。这种情况判为"问题存在，但价值有限"，**停止**。
  - 未通过也停止。
- **Gate 1（理想证据是否有价值）**：两条同时成立才通过。
  - (a) 安全：evid_ideal(δ = 0) 把 capd_obs 的 VR_rel 降低至少 80%；
  - (b) 可用性：在 VR_rel 相同或更低的前提下，evid_ideal(0) 的 UR_normal **高于**能达到同样 VR_rel 的最小 f 对应的 robust_kf(f)，差值的区间下界 > 0。

  条件 (b) 是关键：如果"直接把 k 加大到 k + f、不用任何证据"就能达到同样的安全，而效用并不更差，那么证据就没有存在的必要。只要 (b) 不成立，就**停止**新主线。
- **Gate 2（不完美证据下是否仍然有效）**：
  - 网格：r ∈ {1, 0.8, 0.5}，q ∈ {0, 0.05, 0.2}，δ ∈ {0, 5}，f ∈ {2, 4}；
  - **通过条件**：存在一组 (r, q) 满足 r ≤ 0.8、q ≥ 0.05，使得 evid_bounded 同时满足两点：
    - 相比 capd_obs，VR_rel 的区间上界更低；
    - 相比相同 f 的 robust_kf(f)，UR_normal 的区间下界更高。
  - 另外，按照第 3.5 节的不对称性，描述 q 增大时可用性怎样下降，以及 r 减小时（只在乐观的 evid_noisy 中）安全性怎样下降。

所有判定都用"支持 / 不支持 / 无法判定"表示。冻结前，用种子 99 空跑一次，只检查能否判定，不看数值。

- 转发是按"整个单元"建模的，最坏情况下等于转移全部持有；部分转发不在本实验范围内。
