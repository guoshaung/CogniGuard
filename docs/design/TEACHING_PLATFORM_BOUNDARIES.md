# 教学平台接入边界与整理范围

本轮整理的目的，是让平台接入代码与保护执行职责清楚，而不是预先承诺所有平台有相同接口。
SDK `cogniguard.integrations.education` 保持公共导入；原有教育调用逻辑位于
`cogniguard.applications.education.protected_access`，经 `runtime.gateway` 执行会话、
预算和最终交付。应用层 `profile_consent` 负责会话内字段同意，旧接入路径保留同一对象的兼容导出；策略和可信身份仍由宿主提供。
教学生成器接收的是 `TeachingInput`，不是原始画像或教师资源。

## 现有能力和边界

1. 教育 pipeline 对授权画像、受控资源和最终答案提供现有保护链。其行为与能力边界见
   [Rails 接入约定](RAIL_INTEGRATION.md)。并非任意外部平台自动受保护。
2. runtime 的 session token 是匿名会话凭据，不是学生身份认证。新会话、跨设备、
   账号级预算、不同 Agent 的可信身份和生产身份映射需要宿主实现。
3. 同意目前按会话、字段类型、Agent 标签和用途限定；只有指定的教育入口采用该策略，
   不等于所有课堂请求或外部 Agent 都已支持。[详见](PROFILE_CONSENT.md)。
4. SDK 的生成器是同步调用；DeepTutor 的回合是异步的，还含流式及持久化事件。
   直接把整个 SDK 当生成器并不能确保其检索、工具、日志和回放都经过领域保护。
5. 最终输出检查依赖已登记的画像和资源证据；没有接上检索及资料上下文时，
   不能把输出检查误称为完整的版权或隐私保护。

## 下一次平台接入应验证的实际边界

- 从服务端认证结果建立学生、课程、Agent 和资产的可信映射，禁止把前端自述当授权。
- 对画像访问先做授权与字段选择，对资源检索先做资源权限与受控释放；调用工具及其他
  Agent 时执行对应授权。需要先识别平台上所有可能绕开的入口。
- 对交付的正文、流式事件、来源和可回放内容分别建立可验证的交付边界；未确认安全
  的原始片段不能直接流给学生。区分平台内部留存与实际向接收方交付。
- 明确平台会话与 CogniGuard 会话的生命周期、账本及并发一致性；重试、撤权和回放
  使用同一可信状态。多设备或多宿主需要额外设计，现有本地 SQLite 不提供分布式保证。
- 用合成资料测试正常、拒绝、权限撤销、重放及失败关闭；再决定是否允许真实资料。

DeepTutor 与 SMART RAG 的身份、检索、工具、流和部署均不同。跨平台应该复用领域策略
及已经验证的网关能力，平台专属适配应根据实际调用链实现；当前只有一个候选平台，
不提前引入没有真实复用点的通用插件框架。DeepTutor 的当前检查状态见
[接入检查点](DEEPTUTOR_INTEGRATION.md)。
