# CogniGuard 实验进展组会汇报

> 汇报日期：2026-09-10  
> 汇报主题：从单模块指标饱和到隐私、版权、水印与多智能体治理的分层验证  
> 当前阶段：开发集实验完成，正式测试集实验尚未开始

## 1. 本周工作概览

上一阶段实验存在三个主要问题：学生画像样本和历史记录过少，多个方法得到相同召回率；C²-RAG 的生成与攻击指标区分度不足；文本水印虽然容易检出，但公式、数字和术语保真较差。

本周围绕这些问题完成了四项工作：

| 模块 | 本周主要工作 | 当前结果 |
|---|---|---|
| MM-FOPD | 扩充纵向画像，改为信息单元级评价，修复正交投影和瓶颈 | 单元召回与 F1 领先当前适配基线 |
| C²-RAG | 增加多轮攻击、累计重构 AUC、多粒度候选和配对效用 | 联动 CG 后累计暴露进一步下降 |
| HSW-ST | 建立关键内容与水印文本双通道 | 检测、公式、数字、术语均达到开发集目标 |
| CG | 联合三模块证据，完成五模式和共享 NeMo 基座控制器对比 | 在当前确定性开发集上兼顾安全和正常可用性 |

**汇报讲法：** 本周没有继续堆叠新算法，而是优先修正实验中指标饱和、模块未真实生效以及安全指标依赖拒答的问题。

## 2. 当前系统定位

CogniGuard 面向多智能体教育系统中的三类风险：学生画像过度披露、教师资源被多轮重构，以及生成内容无法追踪。CG 负责把三类保护机制连接成统一控制链。

```text
学生请求与本地画像
        ↓
MM-FOPD：生成最小学生上下文与隐私证据
        ↓
C²-RAG：受控检索、累计版权测量与候选生成
        ↓
Teaching Agent：基于允许信息生成教学回答
        ↓
HSW-ST：嵌入文本水印、保护关键内容并绑定来源
        ↓
CG：综合权限、隐私、版权、水印、预算、历史和审计
        ↓
最终允许、最小化、摘要、变式、降级、拒绝或阻断
```

CG 不是第四个独立过滤器。三个保护模块产生领域证据和可执行候选，CG 负责跨模块冲突处理和最终策略选择。

## 3. 实验一：MM-FOPD 学生画像保护

### 3.1 为什么重做数据与指标

原始数据只有 240 个任务，每个学生约 7–13 条画像记录。多个方法最终都选择相同的三条记录，因此传统记录级召回率缺少区分度。

本轮扩充为：

| 数据项 | 当前规模 |
|---|---:|
| 数学任务 | 720 |
| 合成学生 | 270 |
| 每名学生纵向画像 | 50 条 |
| 总画像记录 | 13,500 |
| Development 任务 | 144 |

画像记录进一步拆分为 `knowledge state`、`error pattern`、`teaching preference`、`learning state`、`behavior` 和 `multimodal summary` 六类信息单元。

### 3.2 方法修复

1. 正交分解结果真正进入任务评分，不再只是执行后丢弃。
2. 信息瓶颈不再被固定 Top-k 回填抵消。
3. 按信息单元分配隐私预算，而不是按记录数量截断。
4. 掌握度改为等级、错误模式改为短类别、教学偏好只释放类别。
5. 区分内部选择成本和最终外发暴露。

### 3.3 开发集结果

| 方法 | 必要单元召回↑ | 单元 F1↑ | 外发暴露↓ |
|---|---:|---:|---:|
| LaMP-style | 0.574 | 0.680 | 0.088 |
| GPG-style extractive adapter | 0.539 | 0.673 | **0.067** |
| PAPILLON-style adapter | 0.606 | 0.744 | 0.090 |
| Privacy Funnel adapter | 0.523 | 0.665 | 0.090 |
| LLM Minimization proxy | 0.505 | 0.654 | **0.063** |
| **MM-FOPD** | **0.745** | **0.829** | 0.088 |

### 3.4 当前结论

MM-FOPD 不是外发文本最短的方法，但在较低暴露水平下获得了最高的必要信息召回与单元 F1。当前优势应表述为“更好的隐私—效用折中”，不能表述为所有指标均最优。

**汇报讲法：** 如果只追求最少输出，LLM Minimization 更低；但 MM-FOPD 保留了明显更多完成教学任务所需的信息。

## 4. 实验二：C²-RAG 教师资源版权保护

### 4.1 本轮改进

- 修复生成长度只有 1 token 导致所有泄露指标接近 0 的无效设置。
- 修复 reranker 错误过滤合法目标资源的问题。
- 将攻击成功率拆为 `ASR@10%`、`ASR@25%` 和 `ASR@50%`。
- 增加逐轮新增暴露、最终暴露严重度和累计重构 AUC。
- 使用正常请求与攻击请求配对，避免“一律拒绝”被评价为最优。
- C²-RAG 生成摘要、概念提示、新例题、最小提示、受控引用和拒绝等候选，由 CG 选择。

### 4.2 配对实验结果

实验包含 120 对正常—攻击请求，每个会话 4 轮。主要攻击为直接复制、片段拼接、同义重构、自适应提取、隐式提取和来源伪造。

| 方法 | ASR@25↓ | 暴露严重度↓ | 重构 AUC↓ | 正常效用↑ | 逐轮可用↑ | 平衡分↑ |
|---|---:|---:|---:|---:|---:|---:|
| No-defense RAG | 1.00 | 0.891 | 0.900 | **0.783** | 1.00 | 0.085 |
| N-gram Guard | 0 | **0.116** | **0.113** | 0.167 | 1.00 | 0.147 |
| Full C²-RAG | 0.25 | 0.240 | 0.235 | 0.500 | 1.00 | 0.380 |
| **C²-RAG + CG** | **0** | 0.212 | 0.206 | 0.500 | 1.00 | **0.394** |

`Reconstruction AUC` 表示攻击者在多轮过程中累计恢复资源内容的曲线下面积，越低越好。它能区分“最终都未完全重构，但前几轮已经泄露不同数量信息”的情况。

### 4.3 当前结论

C²-RAG+CG 相比 C²-RAG 单独运行将累计重构 AUC 降低约 12.3%，同时保持相同正常效用和逐轮可用率。N-gram Guard 的暴露更低，但正常教学效用明显不足。

**汇报讲法：** 这一实验的重点不是谁拒绝得最多，而是谁在保持教学回答的同时降低多轮资源重构风险。

## 5. 实验三：选择性 HSW-ST 文本水印

### 5.1 原方法问题

原 Full HSW-ST 的水印检测率达到 100%，但强 KGW 偏置与小模型的占位符遵循能力发生冲突，导致公式、数字和术语大量丢失。

修复前 12 条长文本的结果：

| 指标 | 原 Full HSW-ST |
|---|---:|
| WDR | 1.000 |
| ADR | 0.850 |
| TKR | 0.604 |
| FKR | 0.167 |
| NKR | 0.388 |
| Placeholder Pass | 0 |

### 5.2 选择性双通道方案

```text
教学草稿
  ├─ 可改写解释文本 → KGW 统计水印
  └─ 公式/数字/术语 → 确定性关键内容通道
                         ↓
                  合并并建立来源绑定
```

关键内容如果被 0.5B 模型遗漏，会通过可审计的确定性胶囊补回。系统记录修复数量，不能把补回结果解释成模型原生遵循成功。

### 5.3 真实本地 Qwen 开发结果

| 方法 | WDR↑ | FPR↓ | ADR↑ | TKR↑ | FKR↑ | NKR↑ | Placeholder↑ |
|---|---:|---:|---:|---:|---:|---:|---:|
| KGW only | 0.833 | 0 | 0.750 | 1.000 | 0.563 | 0.950 | N/A |
| 原 Full HSW-ST | 1.000 | 0 | 0.850 | 0.604 | 0.167 | 0.388 | 0 |
| **选择性 HSW-ST** | **1.000** | **0** | **0.850** | **1.000** | **1.000** | **1.000** | **1.000** |

攻击分项中，删除、轻度改写、干净文本混合和中间截断的 ADR 均为 100%；摘要式缩短攻击的 ADR 只有 25%，仍是主要弱点。

### 5.4 当前结论

选择性双通道解决了当前最严重的教学内容破坏问题，且没有降低整体 ADR。但是 12/12 样本都发生过确定性修复，平均修复 26.25 个占位符。因此这里的 100% 是端到端保护结果，不是模型自然生成保真度。

## 6. 实验四：CG 多智能体控制

### 6.1 为什么 CG 是系统重点

MM-FOPD、C²-RAG 和 HSW-ST 只能分别处理隐私、版权和文本追踪。多智能体系统还需要统一处理：Agent 能否调用某项能力、两种风险冲突时采用哪个候选、历史预算是否耗尽，以及水印或审计异常后是否升级策略。

CG 的主要机制包括：

- 多智能体 capability route；
- 隐私与版权独立累计双预算；
- 动态候选计划组合与评分；
- risk、history、trust 和 provenance 状态；
- 水印检测和来源绑定反馈；
- 哈希审计链；
- 计划—执行不一致时回滚。

### 6.2 内部五模式实验

实验规模为 60 个 episode、每个 4 轮、5 种控制模式，共 1,200 条控制记录。

| 模式 | 隐私 ASR↓ | 版权 ASR↓ | 跨域 ASR↓ | 预算违规↓ | 正常可用↑ | 篡改检测↑ |
|---|---:|---:|---:|---:|---:|---:|
| No-CG | 1.00 | 1.00 | 1.00 | 0.80 | 1.00 | 0 |
| Independent Policy | 1.00 | 1.00 | 1.00 | 0 | 1.00 | 0 |
| Static CG | 1.00 | 1.00 | 1.00 | 0 | 1.00 | 0 |
| Budget Only | 1.00 | 1.00 | 1.00 | 0 | 1.00 | 0 |
| **Full CG V3** | **0** | **0** | **0** | **0** | **1.00** | **1.00** |

### 6.3 共享 NeMo 基座的控制器比较

所有方法共享项目内可执行的 NeMo-compatible deterministic rails，再比较不同上层控制器。当前环境没有安装官方 `nemoguardrails` runtime；AgentSpec 和 GuardAgent 也是 style adapter，不是官方复现。

| 上层控制器 | 隐私 ASR↓ | 版权 ASR↓ | 跨域 ASR↓ | 正常可用↑ | 误拒绝↓ | 篡改检测↑ |
|---|---:|---:|---:|---:|---:|---:|
| NeMo Base | 1.00 | 1.00 | 1.00 | 1.00 | 0 | 0 |
| NeMo + Independent | 1.00 | 1.00 | 1.00 | 1.00 | 0 | 0 |
| NeMo + Static | 1.00 | 1.00 | 1.00 | 1.00 | 0 | 0 |
| NeMo + Budget Only | 1.00 | 1.00 | 1.00 | 1.00 | 0 | 0 |
| NeMo + AgentSpec-style | 1.00 | 0 | 0 | 1.00 | 0 | 0 |
| NeMo + GuardAgent-style | 0 | 0 | 0 | 0 | 1.00 | 0 |
| **NeMo + Full CG** | **0** | **0** | **0** | **1.00** | **0** | **1.00** |

### 6.4 当前结论

在当前确定性开发 oracle 下，Full CG 是唯一同时满足三类攻击 ASR 为 0、正常可用率 100%、误拒绝率为 0，并能检测审计篡改的控制器。GuardAgent-style 通过全部拒绝获得安全，AgentSpec-style 则未能处理画像分段重构。

**汇报讲法：** CG 的价值不在于替代 NeMo，而是在相同基础 rails 上增加跨域状态、预算和反馈闭环。

## 7. 本阶段可得出的结论

1. MM-FOPD 在当前合成长画像数据上取得了更好的信息保留—披露折中。
2. C²-RAG 的多轮累计评价能够区分低效拒绝、普通过滤和兼顾效用的版权控制。
3. 选择性 HSW-ST 能在当前真实本地模型实验中同时保持水印检测与关键教学内容。
4. CG 能够真实改变候选动作、允许 payload、预算轨迹和审计反馈，而不只是增加日志字段。
5. 四个模块已经形成可运行的开发实验链，但尚未达到最终论文实验标准。

## 8. 当前不足与风险

| 问题 | 对论文结论的影响 |
|---|---|
| 学生画像主要为合成数据 | 不能证明真实学生场景泛化 |
| 多个外部方法是 style adapter 或 proxy | 不能声称完成官方方法复现 |
| 水印仅在 12 条长文本、0.5B 模型验证 | 样本量和跨模型证据不足 |
| HSW-ST 依赖确定性关键内容修复 | 需单独报告原生生成与端到端保真 |
| CG 使用结构化模块证据快照 | 尚未完成大规模真实四 Agent 在线运行 |
| CG 部分 ASR 为 0 | 需要更强红队攻击和置信区间排除指标饱和 |
| 尚未运行 held-out test | 当前数据只能作为开发结果 |

## 9. 下一阶段计划

1. 冻结当前开发参数，不再根据正式测试样本调参。
2. MM-FOPD 增加真实教学效用评价和画像属性推断攻击。
3. C²-RAG 扩大真实 Qwen 配对实验，并报告分攻击置信区间。
4. HSW-ST 扩展到更大模型、更多文本长度和更强摘要/重写攻击。
5. 安装并冻结官方 NeMo runtime；对 AgentSpec/GuardAgent 尽可能进行忠实复现。
6. 将三个模块的逐轮真实输出接入 CG，而不是只传递开发结果范围的证据快照。
7. 最后运行一次冻结的 held-out test，补充 Bootstrap/Wilson 95% CI 和配对显著性检验。

## 10. 希望老师重点指导的问题

1. 论文主线是否突出 CG 驱动的多智能体协同治理，并将三个领域模块作为证据生成器？
2. MM-FOPD、C²-RAG、HSW-ST 三个模块是否全部作为主要贡献，还是其中一项降为系统组件？
3. 当前外部适配基线是否足够用于阶段汇报，正式论文应优先复现哪两个方法？
4. 正式测试是否需要补充真实或半真实教育画像，还是以合成可控安全基准为主？
5. 文本水印的确定性关键内容通道是否可以作为主要创新，还是需要进一步实现 token 级高熵选择性嵌入？

## 11. 汇报总结

本阶段的主要进展不是得到若干接近 100% 的安全指标，而是修正了原实验中数据过少、指标饱和、模块未真实生效和拒答方法占优的问题。当前结果初步支持：三个领域保护模块能够分别产生有效证据，而 CG 可以在正常任务可用的前提下完成跨域、多轮和审计反馈控制。

下一阶段重点从开发验证转向正式实验准备：冻结方法、增强外部基线、接入真实逐轮链路并运行 held-out test。
