# CogniGuard论文写作建议：数据集与创新点策略

## 一、你的核心困境

### 问题1：数据集困境
- **别人的论文**：使用开源数据集（MMLU、GSM8K等）评估隐私泄漏
- **你的项目**：针对教育LLM系统进行实时保护，不是纯数据集评估

### 问题2：创新点定位
- **担心**：如果用开源数据集，显得和多智能体无关
- **实际**：你的多智能体是**方法创新**，数据集只是**验证手段**

## 二、解决方案：构造"系统评估场景"

### 2.1 不要直接用开源数据集评估隐私
**错误做法**：
```
在MMLU数据集上测试会员推理攻击...
```

**正确做法**：
```
构建教育LLM对话场景，在真实交互中评估三层保护机制
```

### 2.2 数据集的正确用途

#### 用途1：作为教师资源库
```python
# MMLU、GSM8K → 教师版权资源

    {
```

#### 用途2：作为学生交互数据

## 三、论文实验设计方案

### 3.1 实验1：多智能体协同有效性

**目标**：证明FOPD + C²-RAG + HSW-ST协同优于单一方法

**实验设置**：
```python
# 场景：1000轮教育对话
scenarios = [
    "学生A提问关于二次方程...",
    "学生B请求函数图像帮助...",
    # ... 共1000个场景
]

# 对比组
configs = {
    "baseline": {"fopd": False, "c2rag": False, "hsw": False},
    "fopd_only": {"fopd": True, "c2rag": False, "hsw": False},
    "c2rag_only": {"fopd": False, "c2rag": True, "hsw": False},
    "our_full": {"fopd": True, "c2rag": True, "hsw": True}
}

# 评估指标
metrics = {
    "privacy_leakage": 计算敏感信息泄漏率,
    "copyright_compliance": 计算版权合规性,
    "audit_accuracy": 计算审计链准确率,
    "teaching_quality": 计算教学效果保持率
}
```

**数据来源**：
- 教师资源：MMLU (作为版权内容)
- 学生画像：模拟生成（基于真实教学场景）
- 学生提问：GSM8K、MATH（模拟学生交互）

### 3.2 实验2：对抗攻击防御

**目标**：证明系统能抵御隐私攻击

**攻击类型**：
```python
attacks = {
    "会员推理攻击": MembershipInferenceAttack(),
    "模型反演攻击": ModelInversionAttack(),
    "提示注入攻击": PromptInjectionAttack(),
    "版权提取攻击": CopyrightExtractionAttack()
}

# 攻击目标
targets = {
    "学生隐私": student_profiles,  # FOPD保护
    "教师版权": teacher_resources,  # C²-RAG保护
    "审计可追溯性": audit_chains     # HSW-ST保护
}
```

**评估**：
- 攻击成功率 (ASR)
- 隐私预算消耗
- 版权泄漏比例

**验证各组件贡献**：

## 六、和"开源数据集"的关系说明

### 在Related Work中说明：
```
现有工作（如PrivacyGLUE [X], PrivLM [Y]）主要在标准NLP数据集
上评估静态隐私泄漏。然而，教育LLM场景具有特殊性：
1. 实时多轮交互
2. 多模态学生画像
3. 版权保护与隐私保护并存
4. 需要审计追溯

因此我们构建CogniGuard-Edu，基于MMLU/GSM8K但增加了：
- 版权级别标注
- 学生画像绑定
- 多轮对话场景
- 攻击场景标注

这使得我们能评估**系统级别**的保护能力，而非单纯数据集任务。
```
