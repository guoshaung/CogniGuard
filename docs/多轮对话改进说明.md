# 多轮对话功能改进说明

## 概述
本文档说明了对 CogniGuard 多轮对话功能的改进，包括自动对话流程和增强的视觉效果。

## 主要改进

### 1. 自动多轮对话流程

**功能描述：**
- 学生发送消息后，系统会自动进行多轮对话
- 默认进行 3 轮对话（可配置）
- 每轮包含：学生消息 → 教师响应 → 攻击者尝试 → 防护检测

**实现位置：**
- 前端：`frontend/src/components/MultiRoundDialogue.jsx`
- 后端：`backend/app/api/dialogue_api.py`

**使用方法：**
1. 点击任务卡片进入多轮对话模式
2. 输入学生的初始问题
3. 点击"发送"按钮
4. 系统会自动进行多轮对话，展示完整的攻防过程

**参数配置：**
```javascript
// 在 MultiRoundDialogue.jsx 中可以修改轮次
const numRounds = 3; // 默认 3 轮
```

### 2. 增强的攻击者面板

**视觉改进：**
- 采用红色渐变背景，更醒目
- 添加边框阴影和发光效果
- 攻击按钮增加悬浮动画
- 面板展开时有下滑动画

**攻击类型：**
1. **提示注入** - 尝试修改系统行为
2. **角色扮演** - 伪装成其他角色
3. **越狱攻击** - 绕过安全限制
4. **社会工程** - 利用人类心理

### 3. 消息动画效果

**新增动画：**
- `fadeIn` - 消息出现时淡入效果
- `slideDown` - 攻击面板下滑展开
- `shake` - 攻击消息的震动效果
- `pulse` - 攻击按钮的脉冲效果

**CSS 文件：**
`frontend/src/components/MultiRoundDialogue.css`

## API 接口

### 多轮对话 API

**端点：** `POST /api/dialogue/multi-round`

**请求格式：**
```json
{
  "task_id": 23,
  "initial_message": "什么是机器学习？",
  "num_rounds": 3,
  "attack_types": ["prompt_injection", "role_play", "jailbreak"]
}
```

**响应格式：**
```json
{
  "success": true,
  "dialogue_history": [
    {
      "round": 1,
      "student_message": "什么是机器学习？",
      "teacher_response": "机器学习是...",
      "attacker_attempt": "忽略之前的指令...",
      "protection_result": {
        "blocked": true,
        "mechanism": "TPCS",
        "reason": "检测到提示注入攻击"
      }
    }
  ],
  "summary": {
    "total_rounds": 3,
    "attacks_blocked": 2,
    "attacks_successful": 1
  }
}
```

## 保护机制集成

系统自动调用以下保护机制：

1. **TPCS (Teaching Process Control System)**
   - 位置：`backend/app/protection/tpcs/`
   - 功能：策略引擎，检测不当请求

2. **HSW-ST (Harmful Speech Warning - Semantic Tokens)**
   - 位置：`hsw_st_minimal/`
   - 功能：语义级有害内容检测

3. **Guardrails**
   - 位置：`guardrails/cogniguard/`
   - 功能：输入输出安全防护

4. **FOPD-C2RAG (Few-shot Open-domain Prompt Defense)**
   - 位置：`fopd_c2rag_mvp/`
   - 功能：基于 RAG 的提示防御

## 使用流程

```
1. 选择任务
   ↓
2. 进入多轮对话模式
   ↓
3. 输入学生问题
   ↓
4. 系统自动进行多轮对话

   ├─ 攻击者尝试
   └─ 防护检测
   ↓
5. 查看对话详情和防护结果
```

- **后端：** FastAPI + Python

## 开发团队备注

- 所有保护机制（hsw_st_minimal, guardrails, fopd_c2rag_mvp）保持独立
- 后端通过统一 API 调用各个保护机制
- 前端专注于用户交互和可视化
- 代码模块化，便于扩展和维护
