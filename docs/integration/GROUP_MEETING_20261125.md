## 1. CA-PD 数学定义（v0.1，未改）

- **秘密** σ = (𝒮, s\*, π, g)，|𝒮| = K；对外只公开承诺 HMAC_salt(s\*)。
- **单元** u 对应谓词 φ_u，看到 u 即知 s\* ∈ 𝒮_u；单元集 A 给出 𝒮_A = ∩ 𝒮_u。
- **泄露量** L(A) = log₂(V_g(π|A) / V_g(π))；单调闭包 L\*(A) = max_{B⊆A} L(B)。均匀先验加恒等增益时 L(A) = log₂(K / |𝒮_A|)。
- **阈值** τ（默认 log₂K − 1，即猜中把握 ≤ 1/2）；**见证** W：使 L\* > τ 的极小单元集；全体见证 𝒲_τ。
- **引理 1**：L\*(A) > τ ⇔ A ⊇ 某个 W ∈ 𝒲_τ。
- **k-安全状态**：对每个秘密、每个 |C| ≤ k 的接收者集合 C，A_C = ∪_{i∈C} K_i 不包含任何见证。
- **放行规则**：给接收者 r 放行 R，当且仅当放行后的状态仍是 k-安全的。由于此前状态已安全，只需检查**包含 r** 的联盟。
- **定理（草案）**：在 A1 计量可靠、A2 谓词充分、A3 先验正确、A4 联盟有界且回执完整时，任何 ≤ k 人联盟的泄露 ≤ τ。实验逐条报告假设被违反的比例（E3b-v2：A1、A2 均不成立，见第 4.4 节）。

## 2. 判定归约与动态规划

**归约**：令 H = K_r ∪ R，M = W \ H（缺失单元）。存在违规联盟 ⇔ 存在至多 k − 1 名其他主体，其持有在 M 上的并覆盖 M。这是 M 上的**最小集合覆盖**，问的是覆盖数是否 ≤ k − 1。

```
CheckRelease(registry, r, R, K, k, m_max = 20):
    H ← K[r] ∪ R
    for each target t touched by R:
        for each witness W of t:
            M ← W \ H
            if M = ∅:            return DENY          # r alone completes W
            if |M| > m_max:      return DENY          # conservative ("too_large")
            masks ← dedup{ bits(K[a] ∩ M) : a ≠ r, K[a] ∩ M ≠ ∅ }
            best[0] ← 0; best[S] ← ∞ for S ≠ 0
            for x in masks:                             # 0/1 knapsack over subsets
                for S from 2^|M|−1 down to 0:
                    if best[S] < ∞: best[S|x] ← min(best[S|x], best[S] + 1)
            if best[2^|M|−1] ≤ k − 1: return DENY     # coalition {r} ∪ helpers
    return ALLOW
```

- 复杂度 O(|masks| · 2^m)，|masks| ≤ min(N − 1, 2^m − 1)，**与 k 无关**。
- 去重掩码不改变最小覆盖数（相同掩码的两个主体可互换）。
- 不是原创算法：集合覆盖 DP 是标准做法。创新点在问题建模、到"有界联盟覆盖"的归约，以及运行时约束（预留、提交复核、跨进程锁）。

## 3. 两个比较的数学解释

### 3.1 为什么 CA-PD 比配额（WS04）可用性高

WS04 配额规则：每个用户对每个见证 W 至多持有 c_W = ⌊(|W| − 1)/k⌋ 个单元。于是任意 k 人合计至多 k·c_W ≤ |W| − 1 个单元，凑不齐 W。这是**充分不必要**条件：它为最坏的持有分布预留余量，与实际谁持有什么无关。

CA-PD 的条件是**精确的**：只在确实存在一个 ≤ k 人、能补齐见证的联盟时才拒绝。对任一给定状态，配额允许的放行一定是 k-安全的，所以 CA-PD 也允许（单步支配）。两条轨迹会分叉，所以这不是逐轨迹的定理；E10 在 42/42 个单元格上实测成立。

| 见证大小 w | 配额 c_W（k = 2 / 3 / 4） | 后果 |
|---|---|---|
| 2 | 0 / 0 / 0 | 任何人都拿不到任何一个单元。w2 层差值 +0.51 至 +0.56 **由构造决定**，不作主证据 |
| 3 | 1 / 0 / 0 | k = 2 时配额与 CA-PD 实际放行量相当（w3plus 差约 0）；k ≥ 3 时配额归零 |
| 4 | 1 / 1 / 0 | — |

E10 主证据（E5 合成，w3plus 层，c = 0）：k = 3、4 时 UR 差 +0.39 至 +0.57，95% 下界都 > 0.35。另外，CA-PD 的每用户基尼系数**低于**配额（差 −0.005 至 −0.09）。

**公平性说明**：配额是**无状态**的，每个用户只需本地计数；CA-PD 需要全局回执（`DisclosureStore`）和跨进程锁。所以 CA-PD 的效用优势是"用集中状态换来的"，论文中要写明。

### 3.2 命题 4：何时与全局并集账本等价

**命题 4**：若 k ≥ max_W |W|，则 k-安全 ⇔ 全局并集安全（全体持有之并不含任何见证）。

**证明**：若全体之并覆盖 W，对 W 的每个单元任取一个持有者，至多 |W| ≤ k 人，即为违规联盟。反向显然。∎

**适用条件与后果**：
- 现有基准的 w：合成 2–4，Eedi、Sum Leaks 几乎都是 2。所以 k ≥ 3 时 CA-PD 与 union_view(0) 的 UR 完全相同（合成 K = 16：0.956 对 0.956；Eedi K = 16：0.935 对 0.935；Sum Leaks 0.979 对 0.979）。
- CA-PD 只在 k < |W| 时多放行。代价是不再防守超过 k 人的联盟：k = 2 时全体小组 VR 为 0.38–0.60（都在 g > k 的小组上，保证之外）。
- **论文写法**：要么构造 w > k + 1 的真实场景（如多步教学设计、多表连接）来检验，要么把这一局限写进正文。不得宣称"比全局账本更可用"。

## 5. 治理架构与来源证据接口

```
请求 ─► AccessRegistry.is_authorized ─► Meter(文本→单元) ─► check_release(K_aug, k+f−d) ─► 预留 ─► commit 复核
                                                         ▲
             DisclosureStore.holders_of (回执) ──► augment_knowledge ◄── Observation(pe-1.0)
                                                         │                 指纹 / 检索 / 凭证 / 水印 / 可信事件
                                                         └── trusted_event_credits → d（仅可信事件）
```

来源证据接口已升级并冻结为 **pe-1.0**（`PROVENANCE_INTERFACE.md`；联动状态见 `INTEGRATION_STATUS.md`）。核心规则：
1. 区分**内容身份**（有哪些单元）、**发行身份**（来自哪张回执）、**传播事件**（谁何时传给谁）、**当前保留知识**（门看到的持有）。
2. 内容证据只能**增加**持有 → 门只会更严；检出错误只损害效用。
3. 只有可信通道日志的 `trusted_event` 才能计入 d；水印、指纹、凭证一律不能扣减 f，也不能授权。
4. 复用 `DomainEvidence(domain="provenance")`、`check_release`、`ReleaseGate`、`DisclosureStore`，不建第二套流水线。

## 8. 案例

**教育（四 Agent）**：教师拥有"期末考哪道题"这一秘密（Eedi 真实题目，抽样构造的秘密）。助教 Agent 回答学生 A、B 的问题时，每条回答对应若干谓词单元（知识点、错误认知、答案数值）。单独看都安全；A 拿到"考分数乘法"、B 拿到"答案是 3/8"，两人合起来就锁定题目。CA-PD 在给 B 放行时发现 {A, B} 能补齐见证，于是降级为摘要。若 B 的作业里检出了 A 收到的内容（持有证据），B 的持有被补记，门只会更严。

**软件工程资产保护**：仓库所有者的未公开模块设计被拆成接口签名、配置键、调用顺序等单元；两个编码 Agent 与外部审查 Agent 分别提问。现有 `code-domain adapter` 把代码片段映射到同一个 `ReleaseGate`。共享工作区是未中介通道：若有可信的工作区访问日志（trusted_event），可在 f 预算内放宽；仅凭水印或指纹检出，只能补记持有，不能放宽。
