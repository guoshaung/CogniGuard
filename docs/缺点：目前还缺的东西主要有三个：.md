缺点：目前还缺的东西主要有三个：

1. **Agent I/O schema**

   每个 agent 的输入输出要统一标注：有没有学生数据、有没有教师资源、有没有生成内容、有没有工具调用、有没有外部模型调用。否则 planner/coder/drawing/eval 进来以后，CG 不知道该管什么。

2. **Tool / Action Governance**

   编码智能体、画图智能体这类 agent 不只是生成文本，还会调用文件、运行代码、访问图片、下载资源、调用 API。现在 CG 更像“策略判断器”，还需要补一个动作级控制层，比如：

   ```
   agent_action -> CG policy check -> allow / degrade / block / audit
   ```

3. **Artifact-agnostic provenance**

   HSW-ST 现在偏文本生成内容审计。以后如果有代码、图片、评分报告、计划草案，都需要统一追踪：

   ```
   plan / code / image / eval_report -> watermark or hash commitment -> audit chain
   ```

一句话总结：
**别把新 agent 塞进三个机制；要把新 agent 放进生命周期流程里，然后让 FOPD、C2-RAG、HSW-ST、CG 横向保护它们。**

这样你的论文主线会更稳：CogniGuard 不是某一种固定 agent pipeline，而是一个可以保护不同教育多智能体工作流的生命周期治理框架。
