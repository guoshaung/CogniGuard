# CogniGuard 图像水印服务器实验与数据方案

> 版本：2026-08-02  
> 目标：先把当前可运行的 EditGuard 单图包装基线整理成可复现、可审计的基线实验；随后补齐外部官方方法才开展正式多方法对比，并为后续 DFG-LocGuard 训练提供冻结基准。  
> 结论先行：服务器资源充足值得利用，但“多跑到出现一个好结果”不能作为论文方法。正式实验必须固定数据、划分、攻击、种子和预算，报告全部有效运行与置信区间。

## 1. 当前实现边界

### 1.1 已经具备的部分

- `code/` 中的 EditGuard 模型代码及本地 checkpoint 可作为真实的嵌入、盲检、版权比特恢复和篡改定位基线。
- `dfg_locguard/api/` 已把单图嵌入、验证和 AIGC 攻击包装为独立 API；主系统通过 `backend/app/protection/image_watermarking.py` 调用它。
- 嵌入载荷已与 `owner_id + semantic_metadata + host image hash` 绑定，并登记到服务端来源注册表。验证时必须分开报告原始 64 位 `exact registry` 与闭集 `corrected@1`：后者只允许注册表码本中唯一的汉明距离 1 候选，不能冒充原始载荷精确恢复。
- 清洗后的 64 位来源胶囊为 `16-bit registry id + 32-bit 截断 HMAC tag + 8-bit nonce + 8-bit checksum`；它是来源认证载荷，不再把手工图像统计量称作“语义胶囊”。32 位标签适合论文原型评估但不是长期生产安全强度，合法水印的复制/重放仍需作为独立攻击报告。
- 主后端允许演示模式降级到本地频域水印或本地攻击预览，但这些输出均应标为 `paper_eligible=false`。

### 1.2 尚未完成、不得在论文中夸大的部分

- 当前主干是 **EditGuard wrapper 基线**，不是已经训练完成的新 DFG-LocGuard 算法。
- `dfg_locguard/src/dfg/diffusion_feature_extractor.py` 仍是占位接口，启用后会抛出 `NotImplementedError`。
- `dfg_locguard/src/watermark/locguard_trainer_stub.py` 仍是训练占位器，没有完成扩散特征指导、损失函数、训练、验证和 checkpoint 选择。
- API 请求路径中的轻量语义报告不能替代完整 Stage8E/8F 批处理标定。
- 本机缺少真实 AIGC inpainting 所需的完整模型缓存/依赖时，`local_preview` 只能做界面演示，不能进入论文攻击结果。

因此论文中的方法名称应按阶段写清：

| 阶段 | 可用名称 | 论文角色 | 是否可进正式主表 |
|---|---|---|---|
| 当前 | `CogniGuard-EditGuard-Wrapper` | 已接入的真实基线与系统集成验证 | 可以，但必须满足论文严格模式 |
| 演示降级 | `Local-Frequency-Fallback` / `Local-Preview` | 系统可用性演示 | 不可以 |
| 未来完成后 | `DFG-LocGuard` | 待训练、待消融的拟议方法 | 通过实现与冻结测试门槛后才可以 |

## 2. 论文问题与实验假设

正式实验回答六个问题：

1. **R1 保真度**：嵌入后图像在自然照片、教学图表、公式页面等域上的视觉失真有多大？
2. **R2 鲁棒版权恢复**：在压缩、缩放、噪声、裁剪、组合扰动和 AIGC 编辑后，版权载荷还能否恢复？
3. **R3 篡改定位**：局部编辑区域能否被准确定位，尤其是小面积、不规则和文字区域编辑？
4. **R4 来源认证**：解出的比特是否对应服务端已登记的真实来源，而不是仅碰巧通过短校验？
5. **R5 跨域泛化**：自然照片上的结论是否能迁移到教学图、图表和文档页面？
6. **R6 系统代价**：嵌入、验证和攻击的延迟、吞吐、显存与存储开销是否可接受？

当前阶段只建立 EditGuard wrapper 的可信基线。DFG-LocGuard 的假设与提升幅度必须等训练实现完成后再注册，不能依据同一测试集反复改算法。

## 3. 数据方案：240 条学生记录不能替代图像水印数据

前面扩充的学生画像数据用于隐私、个性化和系统闭环实验；图像水印实验的单位是“图像载体—水印—攻击—验证”四元组，两者不能混为一个数据集。真实教师版权材料也不是必要条件：本项目要验证的是不同视觉内容域上的保护能力，而不是收集某位教师的私有讲义。

优先使用两类可审计数据：

- **程序化合成教学图**：由本项目脚本生成函数曲线、几何图、分数示意、统计图、概率树、电路/力学示意、公式板书、表格和幻灯片版式；不复制真实教材页面。
- **逐文件许可可核验的开放图像**：只纳入许可、作者、原始 URL 和下载时间都能落账的文件；无法核验的样本直接排除。

### 3.1 A 档：核心论文集

用于先完成一轮有统计意义、成本可控的毕业论文主实验，共 **3,000 张去重源图像**：

| 内容域 | 数量 | 建议来源 | 作用 |
|---|---:|---|---|
| 程序化合成教学图 | 1,200 | 本项目生成器 | 覆盖公式、细线、文字、几何和图表等高频教学结构 |
| 开放艺术与文物图像 | 800 | The Met Open Access 中 `isPublicDomain=true` 且有主图的 CC0 固定子集 | 扩展绘画、器物、纹理和非自然照片分布 |
| 自然照片与长尾场景 | 600 | Open Images 中逐图 CC BY 许可复核后的固定子集 | 扩展物体、纹理、光照和构图分布 |
| NASA 官方科学/航天图像 | 400 | NASA Images API 中通过媒体使用政策与来源严格审计的固定子集 | 扩展地球科学、行星、天文和卫星视觉分布 |

执行范围：3,000 张先按组完成 `70%/10%/20%` 划分；**冻结的 600 张 test** 全部跑无攻击、传统攻击和真实 AIGC 攻击。train/dev 留给未来 DFG 训练与阈值选择，不能混入当前正式测试均值。测试身份必须在首次正式运行前写入 manifest，不能依据结果更换样本。

当前生成器实际覆盖 9 个视觉域：函数图、几何、分数、统计图、物理示意、化学示意、流程图、课件页和练习页；以固定根 seed 每域生成 134 张，共 1,206 张候选图，核心 manifest 按预注册上限取 1,200 张。每张图记录模板、样本 seed、许可、来源和 SHA-256。若后续增加小学/初中/高中/大学等学段标签，它只能表达版式与知识呈现复杂度，不能混入真实学生或教师个人数据。

当前已经落地的数据状态必须与目标规模分开表述：

| 层级 | 当前/目标规模 | 实际用途 | 判定口径 |
|---|---|---|---|
| synthetic pilot | manifest 固定为 1,200 张；当前划分为 train 848、dev 117、test 235；1 个来源、9 个视觉域 | 验证 EditGuard embed→attack→verify、严格模式、日志和统计管线 | 已满足 pilot 配置的 `test>=200`、`dataset>=1`、`domain>=9` |
| external formal staging | Open Images 与 The Met 的下载/核验仍在进行中；NASA 官方 API 下载器已接入但本轮未执行下载；Wikimedia 因目标服务器连续 HTTP 503 暂时禁用 | 构建 4 来源 formal 图像池 | 未产生完整 metadata、政策/许可报告和最终 manifest 前，不得写成“下载完成”或“formal 数据已齐备” |
| formal 数据目标 | 3,000 张、4 个来源；目标划分约为 train 2,100、dev 300、test 600 | 毕业论文核心跨域测试 | 必须确认合成教学图/Open Images/NASA/The Met 分别达到 1,200/600/400/800，不能只看 runner 启动成功 |
| 当前代码最低闸门 | `test>=500`、`dataset>=4`、`domain>=4` | 防止明显不完整的作业误启动 | 仍须核验四来源分别达到预定配额及逐文件许可完整，不能只看总量 |

pilot 的 9 个域是内容/版式域，metadata 中**没有学段字段**。因此当前结果不得写成“小学、初中、高中、大学四学段实验”；学段只能在未来真正增加字段和配额后报告。

### 3.2 B 档：扩展服务器集

在 A 档管线稳定后扩到 **12,000 张去重源图像**：

| 内容域 | 数量 | 说明 |
|---|---:|---|
| 程序化合成教学图 | 4,000 | 增加不同学段、学科、布局、字体、前景/背景和图形密度 |
| The Met Open Access CC0 子集 | 3,000 | 按馆藏部门/分类分层，并保留 object URL 与开放状态 |
| Open Images 许可合格子集 | 3,000 | 保持长尾标签与场景分层 |
| NASA Images 政策审计子集 | 2,000 | 保存 NASA ID、center、来源记录、政策链接和逐文件权利筛查证据 |

执行范围：12,000 张仍按组执行 `70%/10%/20%` 划分；传统攻击和 AIGC 攻击覆盖冻结的 **2,400 张 test**，其余样本只用于训练/开发。若 GPU 预算仍充足，可扩展攻击重复次数，而不是临时更换更容易的图片。

### 3.3 数据划分与泄漏控制

- 数据按 `source_family/content_hash` 成组划分为 train/dev/test；同一原图的缩放版、裁剪版、衍生图和近重复图不得跨划分。
- 采用 SHA-256 做精确去重，pHash/CLIP 相似度只用于近重复候选发现，最后保留人工/规则审计记录。
- 建议比例为 `70%/10%/20%`。当前 EditGuard 只评测时，训练集仍保留给未来 DFG 训练，正式比较只用冻结 test。
- 攻击参数、阈值和超参数只能在 dev 上选择；test 只在配置冻结后运行一次主评估。修复代码 bug 后可重跑，但必须保留失败日志并写明原因。
- 未加水印负样本必须来自同一冻结 test，不能另挑质量更高或更容易区分的图片。

## 4. 数据许可台账与纳入门槛

COCO 图片沿用 Flickr 单图许可/使用条款，不能把“COCO 可下载”等同于所有图片版权状态一致；Open Images 官方也明确提示应逐图核验许可。NASA Images API 的“官方 API 来源”不等于所有素材一律属于公有领域，也不等于 CC0：NASA 页面可包含受保护的第三方材料，标识、人物和其他权利还有额外限制。Wikimedia Commons 的许可门槛仍然有效，当前从 formal 配置禁用它是因为目标服务器连续 HTTP 503，而不是判定其许可不合格。

每个 manifest 记录至少包含：

```text
sample_id, source_dataset, relative_path, sha256, perceptual_hash
dataset_name, dataset_version, content_domain, source_family
source_url, author_or_creator, original_title
license_id, license_url, attribution_text, modification_notice
downloaded_at, license_checked_at, checker
privacy_or_personality_risk, redistribution_allowed, included_reason
split, split_seed, synthetic_generator_version, generation_seed
generator_asset_manifest_hash, font_or_icon_license_ids
```

纳入门槛：

1. `license_id`、`license_url` 或 `provenance` 为空时构建 manifest 直接失败。
2. 真实人物、车牌、商标和敏感场所需额外记录人格权/隐私风险；开放许可不自动消除这些权利风险。
3. 程序化生成只使用项目原创几何元素或许可兼容的字体/图标；第三方生成素材仍进入 asset manifest，不能因为输出是“合成图”就省略许可审计。
4. CC BY/CC BY-SA 文件保留作者、许可链接和修改说明；具体义务以许可证和文件页为准。Creative Commons 的 [CC BY 4.0 官方说明](https://creativecommons.org/licenses/by/4.0/)明确要求适当署名、链接许可并说明修改。
5. COCO 使用其[官方网站与 Terms of Use](https://cocodataset.org/#termsofuse)核对来源；Open Images 使用[官方 V7 数据说明](https://storage.googleapis.com/openimages/web/factsfigures_v7.html)并逐图复核；NASA 通过官方 [Images API search](https://images-api.nasa.gov/search) 与 [asset 端点示例](https://images-api.nasa.gov/asset/PIA04433)取得记录和原图清单，并对每个文件保存 [NASA Images and Media Usage Guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/)链接、center、NASA ID、来源元数据哈希和 receipt。只纳入 `media_type=image`、ID/标题/center/官方来源齐全、creator 可确认为 NASA 单一来源的记录；发现 copyright、第三方 credit/courtesy、人物/隐私或品牌/Logo 词的记录直接拒绝，`license_id` 固定写为 `NASA-MEDIA-USAGE-GUIDELINES`，不写 CC0。Wikimedia 若未来重新启用，文件仍须遵循[官方复用指南](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en)逐文件登记。
6. 不能确认许可、原始来源失效、要求与实验发布方式冲突的样本进入 `rejected_manifest.jsonl`，不进入任何结果表。

这套方式不要求收集真实教师讲义。若后续确需做案例展示，只应使用导师明确授权且能形成书面记录的极小外部验证集，并与公开主数据分开报告。

## 5. 对比方法与公平性

### 5.1 正式方法矩阵

| 方法 | 版权载荷 | 篡改定位 | 当前计划 | 报告规则 |
|---|---|---|---|---|
| 无水印 | 无 | 无 | 必跑 | 测视觉上限、误报率和攻击本身的质量 |
| 可见 Logo | 可见 | 无 | 系统参考 | 只作部署参考，不与不可见水印混为同类 |
| EditGuard 官方实现/本项目 wrapper | 有 | 有 | 主基线 | 必须使用真实 checkpoint 和 `real_pipeline` |
| TrustMark 官方实现 | 有 | 无 | 版权恢复基线 | 只比较共同的保真度、检测/恢复和开销指标 |
| MBRS 官方实现 | 有 | 无 | 传统鲁棒水印基线 | 对齐输入与攻击；原生载荷长度不同则单独披露 |
| OmniGuard | 有 | 有 | 条件基线 | 只有取得可验证的官方代码、权重和许可后才纳入；否则仅作相关工作 |
| DFG-LocGuard | 计划有 | 计划有 | 待实现 | trainer、特征提取、训练日志和 checkpoint 完成前不得填结果 |

当前 `paper_benchmark.yaml` 只启用了 `editguard_wrapper`；TrustMark 等适配器仍禁用，MBRS/OmniGuard 也未接入同一 API 合同。因此当前所谓 formal run 的准确名称是“EditGuard 基线正式刻画”，**还不是多方法比较实验**。只有至少再接入一个可核验的官方实现，并在同一 manifest、攻击、载荷与预算下运行后，才能生成方法优劣比较表。

官方入口包括 [EditGuard 代码](https://github.com/xuanyuzhang21/EditGuard)及其 [CVPR 2024 论文](https://openaccess.thecvf.com/content/CVPR2024/papers/Zhang_EditGuard_Versatile_Image_Watermarking_for_Tamper_Localization_and_Copyright_Protection_CVPR_2024_paper.pdf)、[TrustMark 代码](https://github.com/adobe/trustmark)、[MBRS 代码](https://github.com/jzyustc/MBRS)和 [OmniGuard CVPR 2025 论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhang_OmniGuard_Hybrid_Manipulation_Localization_via_Augmented_Versatile_Deep_Image_Watermarking_CVPR_2025_paper.pdf)。不能把本项目自己的近似实现写成对方“官方复现”。Stable Signature 属于生成模型内生水印，任务边界不同，只适合放补充实验；其[官方实现](https://github.com/facebookresearch/stable_signature)可用于说明差异。

### 5.2 公平性约束

- 所有方法使用同一源图、同一冻结划分、同一攻击掩码/提示词/随机种子和同等攻击预算。
- 主比较统一输出分辨率；若方法只支持固定分辨率，额外报告缩放策略和原生分辨率结果。
- 尽量统一有效载荷长度。无法统一则同时报告原生容量、纠错码后有效容量和每比特恢复率，不能只写准确率。
- 版权恢复方法之间比较共同指标；不具备定位能力的方法在定位列写 `N/A`，不能记为 0 后求平均。
- 可见 Logo 与不可见水印分开报告。系统组合图可以展示“Logo + 不可见水印”，但算法主表只评不可见通道，避免把 Logo 的可见信息算成算法能力。
- `FALLBACK`、`local_preview`、`skeleton`、代理实现和手工生成的预测掩码均不得进入正式方法均值。

### 5.3 DFG-LocGuard 完成后的消融

只有训练管线完成后运行：

1. EditGuard wrapper（冻结基线）。
2. `+ diffusion feature guidance`。
3. `+ semantic consistency loss`。
4. `+ multi-scale feature fusion`。
5. `+ source-registry binding`（认证机制消融，不能把安全台账增益混作像素模型增益）。
6. 完整 DFG-LocGuard。

每个消融必须重新训练相同次数、使用相同训练步数/早停规则和开发集模型选择标准；不能从不同 run 中分别挑最优测试指标拼成一行。

## 6. 攻击矩阵

攻击应区分“无恶意的分发退化”“局部篡改”“AIGC 编辑”和“自适应去水印”，因为它们对应不同结论。

### 6.1 分发与传统信号攻击

| 家族 | 强度设置（冻结前在 dev 校准） | 主要评估 |
|---|---|---|
| JPEG | quality = 90, 70, 50, 30 | 载荷恢复、误检、视觉质量 |
| WebP | quality = 90, 70, 50 | 格式转换鲁棒性 |
| 缩放 | scale = 0.50, 0.75, 1.25, 1.50，再恢复原尺寸 | 载荷恢复、定位稳定性 |
| 裁剪 | 面积丢失 = 10%, 25%, 50%，中心和随机位置 | 载荷恢复 |
| 旋转 | 2°, 5°, 10°，固定填充策略 | 几何鲁棒性 |
| 高斯模糊 | sigma = 0.5, 1.0, 2.0 | 高频破坏下恢复 |
| 高斯噪声 | sigma = 2/255, 5/255, 10/255 | 噪声鲁棒性 |
| 亮度/对比度 | factor = 0.8, 1.2 | 光度变化鲁棒性 |
| 锐化 | mild, medium | 后处理鲁棒性 |
| 组合链 | JPEG50+resize0.75、crop25%+JPEG70、blur1+JPEG50 | 真实分发链鲁棒性 |

### 6.2 局部篡改

- 内容删除、复制—移动、跨图拼接、文字覆盖、局部模糊、局部颜色改变。
- 掩码面积分层为小 `1%–5%`、中 `5%–20%`、大 `20%–40%`；形状覆盖矩形、不规则笔刷、细长文字行和多连通区域。
- 每个样本保存二值 GT mask。掩码边界插值、羽化和攻击生成过程必须记录，避免后期手工修正真值。
- 对全图 JPEG/缩放等非局部退化，定位指标记 `N/A`；不要把整幅图当作篡改 mask 来抬高或压低 IoU。

### 6.3 真实 AIGC 攻击

- 局部 inpainting：固定模型版本、模型文件哈希、prompt、negative prompt、mask、scheduler、steps、guidance scale 和随机种子。
- 局部语义替换：对象替换、属性改变、文字/数字更改和背景修改。
- 全局重生成/扩散净化：用于测试版权载荷是否仍可恢复；全局攻击不参与局部 IoU。
- 攻击生成失败、NSFW 过滤、OOM 或输出尺寸异常均保留状态记录，不能悄悄换 seed；预先规定最多重试次数和失败后的统计处理。
- `attack_real_pipeline_available=false` 时正式任务直接失败；不能用 PIL 模糊、局部涂抹或 `local_preview` 冒充扩散攻击。

### 6.4 自适应攻击

在非自适应结果完成后，再加入知道水印检测器/模型家族的攻击：迭代去水印、代理模型迁移、扩散净化强度扫描。自适应攻击必须限制感知质量或语义保持预算，否则“把图完全毁掉”没有研究意义。攻击成功率同时附带攻击后 LPIPS/SSIM 或人工语义有效率。

## 7. 指标

### 7.1 图像保真度

- PSNR、SSIM、LPIPS；同时按内容域报告，不能只给混合平均。
- 对教学图增加文字/公式可读性：OCR 字符错误率、关键数字/符号保持率；OCR 只作辅助指标并保存引擎版本。
- 至少提供固定抽样的原图、水印图和放大残差图，不只展示最好看的样例。

### 7.2 水印检测、恢复与认证

- bit accuracy、完整消息恢复率、检测 TPR、未加水印负样本 FPR、ROC-AUC，以及固定 FPR（如 1%）下 TPR。
- 报告有效载荷长度、纠错开销和单位像素/单位比特容量。
- `integrity_check_passed` 只表示胶囊短校验一致，不等于来源真实性。
- `exact registry` 必须同时满足 `source_registry_match=true`、`exact_registry_match=true`、`correction_applied=false` 且 `auth_status=registered_source`；它表示原始恢复的完整 64 位载荷与 HMAC 注册记录一致。
- `corrected@1` 必须同时满足唯一候选、`registry_hamming_distance=1`、`correction_applied=true` 且 `auth_status=registered_source_corrected`。它只作为注册表辅助识别指标，不能计入原始 `full_payload_recovered`。同时报告未注册但校验通过、同 ID 载荷不匹配、超半径、歧义和完全无效错误率。

### 7.3 篡改定位

- pixel IoU、Dice/F1、precision、recall、false-positive rate；阈值只能在 dev 选择。
- 按掩码面积、形状、内容域和攻击家族分层报告。
- 另报 image-level tamper detection，避免只看像素 IoU 掩盖“是否发现被改”的能力。

2026-08-02 的服务器 dev 校准固定使用 117 张、候选
`{0.22, 0.26, 0.28, 0.30}`，并预先要求：clean mean FPR 不超过
`1e-4`，clean p99 与 max 不超过 `1e-3`，同时 5%/15%/25% 擦除的
mean IoU 均不低于 0.90；满足约束后选择最小阈值。唯一入选值为
`SCE_LOCGUARD_RECOVERY_THRESHOLD=0.28`，对应 clean mean/p99/max FPR
为 `0.007447%/0.054184%/0.077820%`，三档擦除 mean IoU 为
`0.91359/0.95917/0.97507`。粗粒度图像告警面积门槛冻结为 `0.001`。
主流程保留原始预测 mask，不做连通域过滤；上述 dev 结果不能混入 test
均值，test 运行后不得再改阈值。

### 7.4 系统开销

- embed/verify/attack 的 P50、P95 延迟，吞吐（images/s），峰值 GPU 显存、CPU 内存、输出存储和模型加载时间。
- 区分冷启动与模型常驻；记录 GPU 型号、驱动、CUDA、PyTorch、依赖锁文件和 Git commit。
- API 单例与 GPU 串行锁的吞吐结果单独记录。当前 JSON 注册表只适合单 API 进程；多 worker/多节点前应迁移到带唯一约束和事务的数据库。

## 8. 统计与可复现协议

1. 在配置文件中冻结主随机种子。A 档至少 3 个公开种子，B 档 5 个公开种子；示例为 `20260802–20260806`。
2. 图像是统计单位，同一图像的不同攻击/方法构成配对样本。
3. 对主要连续指标给出图像级配对 bootstrap 95% CI（建议 10,000 次）；二元成败给出置信区间，并对成对方法使用适当的配对检验。
4. 多方法、多攻击同时检验时使用 Holm 校正；同时报告差值和效应量，不能只给 `p < 0.05`。
5. 主表报告所有预先注册的攻击强度、全部有效 seeds 的均值与 CI；禁止只报 best seed、best checkpoint 或 best attack subset。
6. 失败运行进入 `raw_runs.jsonl`，记录 `status/error/retry_count`。环境故障可按预先规则重试；算法失败本身必须计入结果。
7. 总平均必须由样本级记录计算，并同时给出各数据域宏平均；不能把各子表均值和全量均值再次平均造成重复计数。

建议在正式运行前生成不可变的 `experiment_lock.json`，内容包括：manifest 哈希、代码 commit、checkpoint 哈希、配置哈希、模型缓存 revision、依赖锁、种子、攻击网格和阈值。任何一项变化都产生新的实验 ID。

## 11. dev鲁棒性预注册

这一轮调参只使用 `cogniguard_edufig/dev` 的 117 张、9 个内容域，固定 seed=`20260802`，攻击条件为 clean、JPEG70、Gaussian noise σ=5 和 resize 0.75，共预期 468 条样本—攻击记录。禁止读取 pilot test、golden test 和 formal test；候选选择完成后冻结一次，再对 untouched test 只运行一次。预注册候选保存在 `dfg_locguard/configs/image_watermark_dev_tuning_candidates.yaml`，当前默认 `enabled=false`，不表示已经完成调参或获得提升。

### 11.1 候选与安全门槛

- 基线为 identity 单视图、`r=1`。开发候选为：① deterministic multi-view + `r=1`（identity、horizontal flip、center crop 0.95，逐位多数聚合，tie 拒绝）；② identity 单视图 + `r=2`；③ identity 单视图 + `r=3`；④ identity 单视图 + `r=4`。
- 安全预注册阈值为随机误接受上界不超过 `2^-32 ≈ 2.33×10^-10`。在 64-bit 胶囊、冻结注册表最多 `M=3000` 时，并集上界 `M×Σ(k=0..r)C(64,k)/2^64` 为：

| registry 半径 | 随机误接受上界 | 预注册用途 |
|---:|---:|---|
| `r=1` | `1.06×10^-14` | dev 安全候选 |
| `r=2` | `3.38×10^-13` | dev 安全候选 |
| `r=3` | `7.11×10^-12` | dev 安全候选 |
| `r=4` | `1.10×10^-10` | dev 安全候选 |
| `r=5` | `1.35×10^-9` | 只作消融，不得成为正式解码候选 |

`r=1..4` 的“安全候选”是有条件的：每个冻结 registry 还必须实测满足 `d_min >= 2r+1`，查询只能返回唯一候选，歧义一律拒绝。任一条件不满足时，该半径不得进入正式选择。`r=5` 不仅超出安全门槛，在本次 16 个距离诊断上也相对 `r=4` 无覆盖收益，因此只保留为消融对照。

### 11.2 多视图与 registry 查询顺序

多视图只改善版权载荷解码，定位 mask 仍使用 identity 单视图，避免几何反变换引入的伪定位收益。每个视图先产生 raw bit/证据，再按预先冻结的确定性规则聚合成 **一个** 64-bit raw 候选；只对这一个聚合结果查询 **一次** registry。禁止“每个视图各查一次 registry，再挑最有利的已登记候选”，因为这会隐性扩大查询预算和误接受概率。

### 11.3 exact/raw/corrected 分报

| 报告层 | 定义 | 禁止的回填 |
|---|---|---|
| `raw` | registry 纠错前的 64-bit 输出；报 bit accuracy/BER、汉明距离、raw checksum/HMAC 状态 | 不得用 corrected bits 重算为 raw BER |
| `exact registry` | raw 64 bit 与 HMAC registry 记录完全一致，`distance=0`、`correction_applied=false`、`auth_status=registered_source` | corrected 成功不得回填为 exact |
| `corrected@r` | exact 失败后，在安全半径内只有一个已认证候选，`correction_applied=true`、`auth_status=registered_source_corrected` | 不得计入原始 `full_payload_recovered` |
| `total authenticated` | `exact + corrected@r` 的补充运维指标 | 必须与 exact、corrected 两列同时给出，不得单列冒充原始恢复率 |

最终 dev 选择顺序预注册为：先过安全上界、码本距离、唯一候选和负对照门槛；再要求 clean 指标非劣；然后用配对 bootstrap 评估攻击下改善。若多个候选在最佳值一个标准误范围内，选择半径更小、视图更少的方案。冻结后不得根据 test 结果改半径、视图或聚合规则。

- 固定 Git commit/分支，确认 `code/` 与 `dfg_locguard/` 都被纳入版本管理；不要只复制当前工作目录而丢失未跟踪源码。

### 13.4 启动验收与结果保全

- 启动 8010 后先调用 `/health` 和 `/api/v1/capabilities`，再跑 S0；不能仅看到端口存活就开始正式任务。
