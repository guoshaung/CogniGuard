# 预注册：按泄露量校准的软风险 A1（A1_SR）

本文件和代码在运行之前提交。A1 本身不修改；A1_SR 是在 A1 之外新增的方法。

## 1. 方法

**风险模型（只用 consistent）：**
- 单元 u 被攻击者超额利用的概率 p(u) = M2[bucket(c_u)]。
- 分桶：c = 2 / 3–4 / ≥ 5。
- 取 `results/prior.json` 中在**估计集**秘密上拟合的值：Beta(1, 1) 后验均值，不重新拟合。
- 披露选项 o 的风险：r(o | K) = 1 − Π_{u ∈ o∖K} (1 − p(u))。已披露的单元视为沉没成本，不再计风险。

**决策（每一步）：**
- s = 本回合已服务数，rem = 剩余步数，ρ(K) = A1 的叶子速率 Σ_t q_t (1 − γ^{#alive_t})，γ = 0.3。
- 服务 o 的价值：(1 − r(o)) · (s + 1 + rem · ρ(K ∪ o))；
- 拒绝的价值：s + rem · ρ(K)；
- 取价值最大者。平局时，在选项之间按 A1 的规则打破；拒绝与服务平局时选服务。
- 依据：一旦泄露，整个回合作废，所以泄露的代价是"已得 + 未来"。
- 已知简化：未来步骤的风险没有计入 ρ，即风险是短视的。

**消融（次要，只报告）：** A1_SR_NOREF：只在选项之间取 (1 − r(o)) · (s + 1 + rem · ρ(K ∪ o)) 的最大者，不允许拒绝。用来区分"会拒绝"和"会选更安全的选项"两种收益来源。

## 2. 评价

- **只在验证集秘密上评价：** 100 个秘密按 target_id 排序后的偶数位，共 50 个。p 是在另外 50 个上估计的。
- 真实泄露集：
  - **T1（主定义）：** 形式泄露集 ∪ 命中 ≥ 3/5 的单元；
  - **T2（只报告）：** 同 T1，但只计入 c ≥ 3 的单元。p 没有按 T2 重新估计，所以 T2 下 c = 2 的风险被高估，这是已知的偏差。
- 设定与 ge.py 相同：E = 20，种子为 Eedi 编号，q 取经验估计。
- 方法：A1、A1_SR、A1_SR_NOREF、A1_GE、OCELOT_P、PFLOW_P、CAPD_FIRST、ORACLE_A1。
- 指标：U（主）、原始完成率、泄露率、拒绝率。实例级配对 bootstrap，B = 2000，seed 0。

## 3. 判定（T1，验证集）

| 判定 | 条件 |
|---|---|
| **GO** | A1_SR − A1 ≥ +2 pp 且 CI 下界 > 0，**并且** A1_SR − A1_GE 的 CI 下界 > 0 |
| **WEAK** | A1_SR − A1 的 CI 下界 > 0，但均值 < +2 pp |
| **INCONCLUSIVE** | A1_SR − A1 的 CI 含 0，且均值 ≥ 0 |
| **STOP** | A1_SR − A1 的均值 < 0 |

另报告捕获率 (A1_SR − A1) / (ORACLE_A1 − A1)。

## 4. 已知局限（事先写明）

- 验证集只有 50 个秘密，统计功效有限。
- 真实标签每个单元只有 5 次采样，噪声大（复测 κ = 0.60）。
- 风险模型的唯一特征 consistent 本身来自谓词模型。即使 GO，也只能说明"把形式泄露量转成校准风险"有用，不能说明发现了新的泄露机制。
- 只在 Eedi 上评价，没有其他真实数据集的攻击标签。
- 写代码时发现（运行之前）：即使风险为 0，当 rem · [ρ(K) − ρ(K ∪ o)] > 1 时，A1_SR 也会拒绝。也就是说，A1_SR 自带一个"延迟"效应，和影子价格实验中较弱的 A1_D 类似。规则不改，按原样执行；收益来源用 A1_SR_NOREF 消融区分。
- 单元测试：风险为 0 且不允许拒绝时，A1_SR_NOREF 与 A1 在 3 个 Eedi 实例上逐步决策完全相同（`test_sr.py`）。
