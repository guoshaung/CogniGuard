# 预注册：≥ τ 阈值对照（在运行之前提交）

## 问题

在真实误设数据上，把泄露阈值从"> τ"改成"≥ τ"，能拿走 ORACLE_A1 相对 A1 改进空间中的多少？

## 方法

- **A1_GE：** A1 不变（γ = 0.3），只把它使用的泄露集换成 W_ge，即在所有单元子集上用同一个最小熵泄露函数计算出的、泄露量 ≥ τ − 1e-9 的极小集合。
  - 这样 consistent = 2 的单个单元也会变成泄露集。
  - 子集枚举是精确的：universe ≤ 12，最多 4096 个子集。
- 对照：A1、ORACLE_A1、CAPD_FIRST、OCELOT_P、PFLOW_P。所有方法沿用 prior.py 的设定（E = 20，种子即 Eedi 编号）。

## 真实泄露集的两种定义（两种都报告）

- **T1（预注册主定义）：** 形式泄露集 ∪ 攻击者在 5 次中命中 ≥ 3 次的单个单元。
- **T2（敏感性）：** 同 T1，但只计入 consistent ≥ 3 的单元。

## 指标与判定

- 主要报告：Δ U（A1_GE − A1），实例级配对 bootstrap，B = 2000，seed 0。
- 捕获率 = (A1_GE − A1) / (ORACLE_A1 − A1)。
- 判定：
  - **≥ τ 已足够**：T1 下捕获率 ≥ 50%，且 Δ 的 CI 下界 > 0。此时软风险方法的新意不足。
  - **仍有空间**：捕获率 < 50%。剩余空间 = ORACLE_A1 − A1_GE，单独报告。
- 另报告 A1_GE 的原始完成率与泄露率，用来看它是否靠过度拒答取胜。
