# CGC5：A1 前瞻披露与强基线对照

分支 `exp/cogniguard-cgc-v5`（从 CGC4 的 8491a84 派生）。A1 未修改：直接调用 CGC4 的 `Policy("A1", gamma=0.3)`。
种子与协议见 `SEEDS.md`，偏离与勘误见 `DEVIATIONS.md`。
结果文件：`results/test_raw.json.gz`、`results/analysis.json`、`results/scale.json`、`results/dev_choices.json`。

## 一句话结论

1. **效用：** A1 显著优于全部四个可部署强基线。
   - 三个机制代理（OCELOT_P / PFLOW_P / DYNCQE_P）：差 0.8–4.7 个百分点；
   - 在线机会成本贪心（OCOST）：在合成与 KSL 上差 0.9–1.4 个百分点，Eedi 上持平；
   - 即时 CA-PD：差 3.3–4.5 个百分点。
2. **与优化 MPC 比：** A1 只比优化后的 MPC 低 0–0.5 个百分点，但便宜 20–1,400 倍。
3. **与精确最优比：** A1 拿到了 OPT 相对 CA-PD 增益的 68–85%。
4. **决策正确性：** A1 与"同目标、全量重算"的 A1_FULL 在每个测试实例的每一步决策都相同（100%）。
5. **效率（阴性）：** A1 的增量更新和缓存没有带来任何速度或内存优势，反而比 A1_FULL 慢 1.2–3.3 倍、内存多两到三个数量级，且规模越大差距越大。
6. **勘误：** CGC4 中"比 MPC 快 15–2,000 倍"的说法因计时方式有误而夸大，见 §5。

## 1. 方法与公平性

所有方法使用相同的：

- 候选回答；
- 任务类型估计 q̂（历史经验估计 `emp`）与时长 H；
- 硬安全约束（任何组的知识不得包含见证）；
- 测试序列（与 CGC4 相同的种子，所以 CAPD_FIRST 可以直接合并）；
- 进程池与硬件。

| 方法 | 性质 | 说明 |
|---|---|---|
| A1 | 被测 | CGC4 冻结实现，γ = 0.3 |
| A1_FULL | 精确重实现 | 同一目标函数，每个候选从头重算全部任务类型的存活集，无增量、无缓存 |
| OCELOT_P | **机制代理** | 取 OCELOT 的"累计推断泄露预算 + 最小必要披露"：选泄露增量最小的可行选项。泄露 = 有秘密模型时（KSL、Eedi）为精确最小熵泄露增量，否则为见证推进比例。另有严格预算版 B = 0.8 × 最大泄露 |
| PFLOW_P | **机制代理** | 取 PrivacyFlow 的前瞻风险规划：模拟披露后的推断后果（最大见证覆盖率），选风险最小的选项，风险 ≥ ρ 时拒绝；ρ 在开发集上选出（见 D1） |
| DYNCQE_P | **机制代理** | 取动态受控查询求值的 longest honeymoon 思想：保留与历史一致的极大无见证审查集，选保留最多审查集的选项。选项单元 ≤ 14 个时精确枚举，否则用 256 个固定种子样本 |
| OCOST | 通用强基线 | 在线打包的指数定价：单元价格 Σ 2^-(剩余见证大小 − 1)，选最便宜的选项 |
| MPC_OPT | 优化实现 | 深度 d 的期望最大化搜索，跨决策和跨回合持久缓存；按"仍可被选项单元补全的剩余见证"做精确等价状态合并；叶子值用 A1 的速率；d = 3 由开发集选出 |
| OPT_CANON(_SERVE) | 精确最优 | 在规范状态上做精确 DP；带延迟 / 只服务两个版本；n > 30 时跳过 |

**三个机制代理不是原论文的复现，不能据此宣称 A1 超过了 OCELOT、PrivacyFlow 或 dynCQE 的原论文结果。** 它们只表示"把这三篇工作的核心决策机制放到同一个见证超图问题上"时的表现。

要点：

- 只服务的精确最优（OPT_SERVE）只比 A1 高 0.1–0.7 个百分点。所以在"不允许策略性延迟"的动作空间里，A1 已接近最优。剩下的差距（OPT − OPT_SERVE = 0.5–1.4 个百分点）几乎都来自延迟，与 CGC4 的结论相同。

## 4. 运行效率与内存（每次决策毫秒数 / 峰值内存；计时轮与内存轮分开）

| 条件 | A1 | A1_FULL | OCOST | MPC_OPT (d = 3) | OPT_CANON |
|---|---|---|---|---|---|
| base | 0.057 ms / 22 KB | 0.027 / 6 KB | 0.019 / 6 KB | 1.17 / 852 KB | 6.1 / 8.1 MB |
| tight | 0.046 / 19 KB | 0.025 / 6 KB | 0.024 / 6 KB | 1.19 / 1.0 MB | 6.9 / 12.6 MB |
| Eedi | 0.023 / 8 KB | 0.014 / 6 KB | 0.015 / 6 KB | 0.076 / 29 KB | 0.064 / 46 KB |

| n | A1 | A1_FULL | A1 / A1_FULL | OCOST | MPC_OPT (d = 2) |
|---|---|---|---|---|---|
| 24 | 0.023 ms / 11 KB | 0.018 / 4 KB | 1.2× | 0.018 / 4 KB | 0.17 / 163 KB |
| 60 | 0.104 / 46 KB | 0.045 / 4 KB | 2.3× | 0.040 / 5 KB | 3.8 / 1.6 MB |
| 120 | 0.201 / 185 KB | 0.119 / 4 KB | 1.7× | 0.077 / 7 KB | 42 / 11 MB |

| 400 | 1.94 / 1.0 MB | 0.597 / 4.5 KB | 3.3× | 0.480 / 16 KB | 超时（60 s） |

结论：

1. **A1 的增量更新和存活集缓存在所有测试规模上都是负优化。** 同样的决策，全量重算更快、内存几乎不变，A1 的缓存随规模线性到超线性增长。所以"增量更新带来效率优势"不成立。建议正式实现时用全量重算（不改变 A1 的目标和决策）。
2. **A1 目标（任一实现）相对优化 MPC 的效率优势是真实的，但比 CGC4 报告的小。**
   - 小实例约 20 倍；
   - large k = N 约 1,400 倍（A1_FULL 约 2,900 倍）；
   - n = 240 时 MPC d = 2 已到 555 ms，n = 400 超时。
   - 它的效用最多高 0.5 个百分点（large k = N 上反而低 0.4，CI 含 0）。
3. **OCOST 最便宜**，但效用比 A1 低约 1 个百分点。

## 5. 对 CGC4 的勘误（详见 DEVIATIONS.md D2）

CGC4 计时时 tracemalloc 处于开启状态，MPC 也未做缓存和状态合并。

| 比较 | CGC4 数值 | CGC5 修正后 |
|---|---|---|
| base 条件，A1 | 0.42 ms | 0.057 ms |
| base 条件，MPC | 81 ms | 1.17 ms |
| 小实例上 A1 相对 MPC 的加速比 | 约 190 倍 | 约 20 倍 |

"快 15–2,000 倍、内存 1/2,400–1/30"这句话应改为：

> 小实例上约 20 倍，大实例上约 1,400 倍；且优势来自 A1 的目标函数本身，不来自增量实现。

CGC4 的效用结论不变。

## 6. 局限

- 三个论文方法只是机制代理（见 §1）。
- PFLOW_P 的 ρ 选择受开发集平局影响（D1）。
- 共享笔记本的桌面负载使绝对毫秒数偏高、噪声大（D4）。比较时应看同一 worker、同一实例上的比值。
- OPT 只在 n ≤ 30 上可算。
- Sum Leaks 派生序列太短，所有方法完成率都是 100%，没有区分度。
- 扩展性基准只测时间和内存，不测效用。

## 7. 判定

| 问题 | 结论 |
|---|---|
| 决策正确性 | **成立**：与同目标全量重算 100% 一致，0 违规 |
| 长期效用 | **成立**：显著优于全部可部署基线（机制代理、OCOST、CA-PD）；与优化 MPC 差 ≤ 0.5 个百分点；拿到 OPT 增益的 68–85% |
| 运行效率 | **部分成立**：A1 目标相对 MPC / OPT 快 20–1,400 倍；但增量实现本身比全量重算慢 |
| 内存优势 | **相对 MPC / OPT 成立**；相对全量重算**不成立** |

A1 维持 **GO**（作为 CA-PD 的前瞻扩展）。贡献应表述为"目标函数（存活选项的机会损失）"，不应表述为"增量更新算法"。
