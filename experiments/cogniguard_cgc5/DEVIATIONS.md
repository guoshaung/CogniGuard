# CGC5 deviations and errata

| # | What | Why / how found | Effect on conclusions |
|---|---|---|---|
| D1 | PrivacyFlow proxy threshold ρ: the four dev values {1.01, 0.99, 0.75, 0.67} gave identical dev completion (0.881944…). The pre-set rule "max dev completion" picked 0.67 only because of a 1e-16 floating-point difference. Kept as run (no post-hoc change). | Tie in dev; ρ never binds on dev | ρ = 0.67 can only add refusals relative to 1.01, so PFLOW_P numbers are a lower bound for the proxy family on test. A1's lead over PFLOW_P should be read with this caveat; it does not affect any other method |
| D2 | **Erratum to CGC4 timing claims.** CGC4 measured runtime with `tracemalloc` active and with an MPC that re-enumerated raw knowledge states without a cache. CGC5 separates the timing pass (no tracemalloc) from a memory pass, and uses a cached MPC with exact canonical-state merging. Base condition: A1 0.42 ms → 0.057 ms; MPC (d = 3) 81 ms → 1.17 ms. The CGC4 sentence "A1 is 15–2,000× faster than MPC/Beam/SAA, memory 1/2,400–1/30" overstated the small-instance gap; the corrected small-instance ratio vs optimized MPC is about 20×. On large instances the gap remains large (large k = N: 0.21 ms vs 304 ms) | Smoke test before the CGC5 run | CGC4 utility results are unchanged; only the efficiency sentence is corrected |
| D3 | **The incremental update gives no speed or memory advantage at the tested sizes.** A1_FULL (same objective, full recompute, no cache) makes identical decisions (100% step agreement on every test instance) and is 1.6–2.1× faster on the test conditions (equal on Sum Leaks) with lower peak memory. The scaling benchmark shows the gap *widens* with size: 1.2× at n = 24, 3.3× at n = 400 (A1 1.94 ms / 1.0 MB vs A1_FULL 0.60 ms / 4.5 KB per decision). The witness-local bookkeeping and the alive-set cache cost more than they save, and the cache grows with the number of visited states | Measured in the CGC5 test and scaling runs | A1's claimed efficiency advantage over its own full-recompute version is withdrawn at these scales |
| D4 | Machine load: the shared laptop (10 cores) ran desktop applications throughout (load average 15–27) while the 9-worker test pool ran, and for about 10 minutes the P0 run of the separate latent-leakage study (2 workers) overlapped with the test pool; the scaling benchmark ran with no other job of this study, but desktop load was still present | Observed with `uptime` / `ps` | Absolute milliseconds are noisy and inflated; ratios between methods measured inside the same worker on the same instance are the reported quantity |
| D5 | `test.log` is empty: the test runner's final `print` was not flushed before the redirect was closed. `test_raw.json.gz` is complete (row counts in analysis.json) | Logging only | None |
