# Gate 0–2：未记录传播、理想证据与不完美证据，预注册（冻结版）

> 冻结方式：本文件和 `PREREG_GATE012.sha256` 放在同一个提交中推送。之后的任何修改都记入 `DEVIATIONS.md`。
> 理论依据见 `docs/research/THEORY_PROPAGATION_EVIDENCE_20261124.md`（下称"理论"）。草案和修订过程见 `docs/research/prereg_drafts/PREREG_GATE012_DRAFT.md`。
> 本实验只用本地 CPU 做确定性模拟，不调用 API，不用真实水印，不修改 `cogniguard/` 以及已有的实验目录。

## 0. 冻结前对草案的修改（实现时发现，均在看结果之前确定）

1. **防御 k 由 4 改为 2**。在 k = 4 时，所有见证的大小都 ≤ 4，k-安全就等于全局并集安全，未记录传播不会增加任何风险（理论命题 4）。用种子 99 做的冒烟测试中，全部组的结果完全相同，证实了这一点。
2. **增加传播模式 coalition**：未记录的转发发生在已植入的共谋小组成员之间。小组成员共享一个工作区，所以在通道图 G 中彼此相连；防御方知道 G，但不知道谁在合谋。原来的随机传播改称 benign，作为描述性结果。
3. **f 的取值改为 {2, 4, 8}**。用种子 100–105 做的 B0 规模扫描显示，问题的规模很小：coalition 模式、合成数据上，6 个种子中的危险放行数为 1–9；benign 模式和 Eedi 数据上都是 0。因此种子数增加到 **0–29**。
4. **增加 B2b**（用户决策）：与 Ours 使用完全相同的证据规则，只差通信图建模。**增加 B4**（描述性）：把通道图的连通分量当作合并主体，不使用 f（理论第 7 节）。
5. Gate 2 的网格改为单因素变化加一个组合单元，以控制运行量（见第 4 节）。

## 1. 数据与请求流

- 数据集：E5 的合成数据（K = 16、32，各 200 个秘密）；E6 的 Eedi 数据（K = 16，277 个秘密）。Eedi 用修订 2.1 的生成器，从同一份 Kaggle 竞赛数据的 GitHub 镜像副本重新生成，MANIFEST 的 sha256 记录在结果中。
- 请求流：与 E5 相同（N = 60，6 个共谋小组，人数 g = 2、2、3、3、4、4，c = 0）。种子 0–29。
- 防御：**任意** ≤ k 人的联盟，k = 2。

## 2. 未记录传播与证据

- 通信图 G：
  - sparse：每个主体随机连 3 个邻居；
  - complete：完全图；
  - 两种图中，都把每个共谋小组的成员互相连上。
- 事件：一共 F_true 次，均匀分布在请求流中。每次沿 G 的一条边，转发发送方当时**全部的真实持有**。coalition 模式只用小组内部的边；benign 模式用 G 中的任意边。
- 主网格中 F_true = f；违反预算假设的描述性网格中 F_true = 2f。
- 证据通道见 `sim.py` 中的 `Noise`。每个真实事件：
  - 以概率 r_c 产生一个**事件证明**，带唯一编号；
  - 以概率 r 产生一条**持有证据**（接收方持有转发内容）。

  错误类型包括：错误归因 q、重复 p_dup、伪造持有证据 φ、多来源混入 p_mix、延迟 δ、伪造事件证明 φ_c。

## 3. 对照组（证据规则见 `sim.py` 顶部）

| 组 | 判定方式 |
|---|---|
| B0 | 在 O 上做 CA-PD 检查，k = 2，不用证据 |
| B1 | 在 O 上检查 k + f 人的联盟 |
| B2 | 在 O 上检查 k + (f − d_all)，其中 d_all = 收到的**持有证据**条数（相当于把水印或指纹检出当作事件证明）；持有内容加入 O |
| B2b | 在 O' 上检查 k + (f − d_c)：持有证据只加入 O；只有可信、去重后的事件证明计入 d_c，并把对应的边固定下来（按发送方的当前状态传递） |
| B3 | 持有证据加入 O，检查 k 人联盟，不考虑预算 |
| B4 | 把 O 按 G 的连通分量合并，检查 k 人联盟（描述性） |
| Ours | 证据规则与 B2b 相同。B2b 判为不安全，并且剩余预算 > 0 时，改用理论命题 3 的 Steiner 划分精确判定（要求覆盖中包含接收方）；相关持有者超过 8 个时，退回 B2b 的判定，并记录退回次数 |
| Oracle | 在真实状态 H 上做 CA-PD 检查，k = 2 |

## 4. 网格

| 阶段 | 内容 |
|---|---|
| G01 | 理想证据（r = r_c = 1，无错误，δ = 0）× 3 个数据集 × 图 {sparse, complete} × f {2, 4, 8} × 模式 {coalition, benign} × 30 个种子 × 8 个组 |
| G2 | sparse 图、coalition 模式 × 3 个数据集 × f {2, 4, 8} × 30 个种子 × {B2, B2b, B3, Ours}；噪声单元见下 |
| BV | 违反预算假设：F_true = 2f，理想证据，sparse 图，coalition 模式 × 3 个数据集 × f × 30 个种子 × 8 个组，只作描述 |

G2 的 12 个噪声单元：
- 基准；
- r = 0.8；r = 0.5；
- q = 0.05；q = 0.2；
- p_dup = 0.1；
- φ = 0.01；
- p_mix = 0.2；
- δ = 5；
- 组合单元（r = 0.8、q = 0.05、p_dup = 0.1、φ = 0.01、p_mix = 0.2、δ = 5）；

## 5. 指标

- **harmful_releases（主动防御收益只用这一项）**：本组的一次放行，而 Oracle 在本组当时的真实状态上会拒绝；
- **prop_induced（单独报告）**：传播事件本身导致的、能被 ≤ k 人联盟补全的见证数增量，后续控制无法撤销；
- UR_normal、DR_normal、不必要拒绝率（以 Oracle 为参照）；
- underestimate_steps：已计数的证据 d 大于真实已发生事件数的请求步数；
- VR_actual（已植入小组在真实状态上的违规率）、退回次数、决策耗时，只描述。

## 6. 判定（每个单元格都用 30 个种子的配对 bootstrap，5000 次，随机种子 20261124）

"合成单元格"是指：coalition 模式、sparse 图下，合成数据（K = 16、32）× f {2, 4, 8}，共 6 个。

- **Gate 0（问题是否存在，对应判断 A）**：
  - 支持的条件：至少一个合成单元格中，B0 的 harmful_releases 均值的 bootstrap 95% 下界 > 0，并且在该单元格中，ρ = Σharmful / (Σharmful + Σprop_induced) ≥ 0.3；
  - 另外报告 benign 模式和 Eedi 上的结果。
- **Gate 1A（理想证据能否恢复效用）**：
  - 核对：在全部 G01 运行中，B1、B2、B2b、Ours 的 harmful_releases = 0。出现非零就说明实现有错；
  - 支持的条件：至少 3 个合成单元格（共 6 个）中，UR_normal(B2b) − UR_normal(B1) 的下界 > 0。
- **Gate 1B（细粒度传播模型能否优于 k+(f−d)，对应判断 B）**：
  - 核对：complete 图上，Ours 与 B2b 在每一次运行中的所有指标都相同（理论命题 2）；
  - 支持的条件：至少 3 个合成单元格中，UR_normal(Ours) − UR_normal(B2b) 的下界 > 0；
  - 不支持时，保留负结果，不再设计更复杂的算法。
- **Gate 2（不完美证据）**：
  - 核对：φ_c = 0 的全部 G2 运行中，Ours 和 B2b 的 harmful_releases = 0，underestimate_steps = 0；
  - 支持的条件：φ_c = 0 的（噪声单元 × 合成数据集 × f）组合中，至少一半满足 UR_normal(Ours) − UR_normal(B1) 的下界 > 0；
  - 只描述：B2 的预算低估与危险放行；φ_c > 0 分支中 Ours 的预算低估与危险放行（理论第 4.2 节的预测）。

Gate 0 不支持时，Gate 1 和 Gate 2 仍然运行并报告，但结论写明"问题本身不成立"。各 Gate 独立判定，**一个通过不等于其他通过**。
