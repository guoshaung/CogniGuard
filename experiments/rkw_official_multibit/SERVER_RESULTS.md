服务器直连 huggingface.co 超时。hf-mirror.com 行为核查返回 HTTP 206，首个 1 MiB 样段测得 188,072 B/s，四个 2 MiB 并发样段单流 287,316–390,156 B/s。大文件持续传输发生 503、连接重置和尾段变慢，现采用固定 revision 的续传。编码器的已收尾范围和原连续前缀保留。解码器已完整核验，两个 7B 编码器仍在传输。

官方解码器 SHA-256 `af337b5025fafc02960295fecd20a81ae983cfb3a45cf0529a4ffa5b3d8fa5e0`，大小 3,087,465,120 字节，对应正式发布 revision `79ccfb8`。官方 value head SHA-256 `41fc586b054ab18b8a22a0930d5334e33eee1da748af246d804727fa870d91aa`。BF16 CPU 用完整官方权重和上游分句、评分代码对两个原生未加水印输入打分。检测到的八位分别是 `00000000` 和 `10111011`，均与目标 `10101010` 不相等。单输入评分 0.267 秒和 0.196 秒。两个负控无法估计误接受率。 [逐条证据](results/decoder_controls.jsonl)

旧 CUDA 环境的实际 BF16 算子测试失败。已验证并下载 Torch 2.7.1 cu128 官方 wheel 的 1,039,245,529 字节与 SHA-256。隔离环境首次安装在依赖传输阶段超时，已更换依赖下载镜像重试。等全部权重和 CUDA 可用后，已部署的启动脚本才进入官方生成与逐句核验。
## CUDA 复核

Torch 2.7.1+cu128 在 5090 实测 CUDA capability 12.0。BF16 64×64 矩阵乘法返回预期结果 64。依赖由 NVIDIA 官方软件包和清华 PyPI 镜像安装。GPU 解码器使用相同官方检查点，对两条未加水印样例得到 `00000010` 和 `10111011`。16 句中 1 句的分数从 CPU 的 −0.005035 变为 GPU 的 +0.006470，对应 1 位变化。CPU 和 GPU 共四次观测的完整交替目标码匹配均为 0，但两条不同原文不足以估计误接受率。后续原生能力评测使用同设备的 BF16 分数，保留原始浮点分数。 [GPU 逐句输出](results/decoder_controls_gpu.jsonl)

编码器 0 的第 6、7 分片的续传文件因本机可用磁盘总量不足暂存在服务器 RAM 文件系统，改移前后做了逐字节比较。其余分片仍保留在系统盘和数据盘。最终运行会按官方 LFS SHA-256 验证链接指向的文件。RAM 文件系统内容会随服务器重启消失。
