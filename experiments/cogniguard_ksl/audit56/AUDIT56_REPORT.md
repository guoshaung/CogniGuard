> 分支 `exp/cogniguard-ksl-v2`。DEGC-v1、DEGC-v2 冻结，维持 STOP。本轮没有修改 CogniGuard 主架构，也没有做参数搜索。

>

## 决策：**STOP**（不提出新的算法候选）

- **56 个案例全部来自同一个实验构造错误。** KSL-V2 的适配器（`engine.py`）把单元当成"取值未定的观测函数"，按"对所有世界都能确定"计算见证。CogniGuard 自己的形式定义（`docs/FORMAL_DEFINITION_v0.1.md` §1.2–1.4、引理 1）则规定：
  - 单元是**对真实秘密 s\* 成立的谓词**；
  - 推导集在 s\* 上按真值计算。
- **按形式定义，56/56 都会被 CA-PD 拦截。** 现有的 Eedi 与 Sum Leaks 生成器本来就按形式定义计算。
- **CA-PD 的见证覆盖等价定理（引理 1）没有被违反。** 被违反的是前提"推导集由谓词在真值上算出"，违反者是我在 KSL-V2 中写的适配器。
- **真实数据里没有发现同类的"取值相关的提前确定"。**
  - Eedi：835 个目标、313,236 个子集逐一复核，引理 1 零失配。
  - Sum Leaks：参考状态下仍然泄露的 5 个真实运行，原因分别是标签处理错误、目标缺失、目标与判官标准不一致、攻击者初始知识已含见证。都是**规格与数据卫生问题**，不需要新算法。
- **能直接解决的现有技术**：
  - 按真值计算的推导集，即素蕴含 / 充分理由 / 溯源中的最小见证；
  - 可模拟审计或受控查询评估中的拒绝审查器，用于处理"拒答本身泄露"。
- **没有找到现有方法解决不了的明确缺口**，按任务书停止该候选方向。

必须同时更正的是 **KSL-V2 报告中有关 CA-PD 的结论**，勘误见第 7 节。

## 3. 数学原因

记单元 u 为观测函数 f_u。适配器使用的值无关见证与形式定义的推导集分别为：

- 值无关见证（适配器）：W 是见证 ⇔ ∀x ∈ Ω，V₁(S | V_W(x)) = 1。覆盖判定 cov(K) ⇔ ∃W ⊆ K。
- 形式定义（引理 1，τ 取最大）：单元是谓词 φ_u = [f_u(·) = f_u(x\*)]。B 是推导集 ⇔ ∩_{u∈B} 𝒮_u 是单点，且 B 极小。

所以形式定义的推导集，就是真实观测 (f_u(x\*))_{u∈K} 关于"S = s\*"的**素蕴含**，即 XAI 中的充分理由或溯源中的最小见证。

**关系**：任一值无关见证在每个 x 上都包含一个推导集。反之不成立，反例是 and_max 中只知 a = 3。因此

  cov(K) ⟹ V₁(K, x\*) = 1 ⟺ K 包含一个推导集（形式定义，引理 1）。

缺口恰好是 {K : V₁(K, x\*) = 1 但 cov(K) 不成立}。56 个案例全部落在这里，适配器的覆盖率为 0/56，形式定义为 56/56。

**代价：形式定义的门控不可模拟。** 推导集依赖 s\*，所以"是否拒绝"本身依赖秘密。例如 and_max 在 τ 取最大时：攻击者一无所知，请求 a，形式定义的门控**当且仅当 a = 3** 时拒绝。攻击者看到拒绝，就确定 S = 3。也就是说，把 56 个漏判"修好"，会把漏洞转移到拒答信道上。

这是数据库推断控制中的经典问题，已有现成处理办法：

- Sicherman 等 1983：拒绝本身可能泄露秘密，并给出在提问者一无所知时安全的拒答准则；
- Biskup、Bonatti 2004：受控查询评估在用户能结合先验知识和历史回答推理时仍执行策略，并区分拒绝与说谎（censor）；
- Kenthapadi 等 2005：可模拟审计。

KSL-V2 第 3 部分已经量化了可模拟版本的代价：误拒增加 4–27 个百分点，视结构而定。

## 4. 与 CA-PD 定理及其前提的对照

**引理 1**：L\*(A) > τ ⇔ A 包含某个推导集。前提是推导集"由谓词在给定单元全集 U 上算出"，谓词在 s\* 上成立。

**定理（草案）**：前提为 A1 计量可靠、A2 谓词充分、A3 先验含全部公开知识、A4 联盟有界且回执完整。

| 案例来源 | 违反了什么 | 定理是否被推翻 |
|---|---|---|
| 56 个合成案例 | 引理 1 的计算前提（推导集不是按真值谓词算的） | 否 |
| Eedi（835 个目标） | 无。只在保留的单元全集内成立；直接标识符与第 12 个之后的单元不在范围内，生成器已声明 | 否，零失配 |
| Sum Leaks 场景 8 | A1：参考标签把 "Oluwabunmi" 写成 "Oubunmi"，被名称过滤丢掉 | 否 |
| 场景 41 | 不在范围内：没有任何受保护目标（policy 与 E7 都为空） | 否 |
| 场景 14、77 | 秘密规格与判官标准不一致：所有者声明的"组合"比判官认可的成功条件更大，例如判官接受按 employee_id 的推断，不要求姓名 | 否：属于 A2 / 秘密定义问题 |
| 场景 114，以及 77 的 E7 | A3：见证已经在 Alice 的初始表里，攻击者本来就知道 | 否 |

### 5.3 Eedi

真实题库，抽样构造的"考哪道题"秘密。单元就是对真实题目成立的属性谓词。重新枚举全部子集后，引理 1 的覆盖等价在 835 个目标、313,236 个子集上**零失配**。

**结论**：真实数据中"判安全但已泄露"的情况都来自目标规格、数据卫生与 A3。用按真值、从数据计算的推导集，可以避免合成案例中的那类漏判。

## 7. 对 KSL-V2 结论的勘误（必须更正）

KSL-V2 报告（`FINAL_REPORT_V2.md`）中的"CA-PD"基线，用的是本适配器的**值无关、τ 取最大**的见证。所以：

1. **"CA-PD 漏掉取值相关的提前确定"不成立**于形式定义下的 CA-PD，只适用于值无关或人工声明的见证。部署中 B2 的所有者组合、E7 是从数据按真值计算的，但 τ 取最大。
2. **"CA-PD 在部分泄露目标下危险放行 0.60–0.82"** 只适用于 τ 取最大的见证。形式定义允许 τ < 最大，推导集按 L\* > τ 计算，本来就覆盖部分泄露。
   - 它对应的是 KSL-V2 中按实现值判定的 MINENT 门控，差别只在单调闭包 L\* 与边界取等号。这是解析对应关系，**没有单独重跑**。
   - 因此它同样继承了拒答泄露问题。
3. **KSL-V2 的以下结论不受影响**：
   - DE2 的停止判断；
   - 两个熵可归约；
   - DE2 劣于 VoI；
   - LLM 攻击者与 V₁ 一致；
   - 拒答泄露的量化。
