# Protocol B2：语义知识检测与保护目标完整性诊断（组会版）

> Protocol B 冻结于 `b26de9f`，**原结论不改**。本文件是离线诊断。不新增命题，不改 CA-PD 决策内核（`check_release`，k = 1）。
> **旧的 1,190 条日志视为已暴露的诊断数据**，不再称为独立留出集。在其上得到的任何改进只是诊断结果。
> 代码：`protocol_b2/{extract,gold,diagnose,regex_sensitivity,plot_b2}.py`。结果：`results/protocol_b2/`。

## 1. 核查：B 中的门控是否接入了 pe-1.0 的 BGE + NLI 确认层

**没有。** Protocol B 的门控只用了确定性表值匹配（`table_meter`：精确匹配各表独有的单元格值）。B2 原样复用 Codex 冻结的语义检测接口：

- 检索：BGE-small-en-v1.5@`5c38ec7`；
- 核验：DeBERTa-v3-base-mnli-fever-anli@`6f5cf0a`（本机下载，sha256 `06d6fd89…` 与 Codex 锁定值一致）；
- 阈值：沿用 `codex/gate-w0-real@fcf1374` 的 threshold_lock（资产检索 0.7536，NLI 0.9642）。

没有重新训练，也没有重新调阈值。

## 2. 方法

- **基础轨迹**：B 中**未设门控**的 CoT 运行（同一后端、同一任务），共抽出 217 次运行中返回给 Alice 的 576 条回答。
- **金标**（只在评分侧使用）：glm-5.2 用严格的结构化提示，标注每条回答透露了哪些表的行级内容。576 条全部可解析，其中 3 条为空。
- **检测器**：
  - 原始匹配（B 中部署的）；
  - 归一化匹配（大小写、$、千分位、k / M、%、下划线）；
  - 语义（冻结的 BGE + NLI）；
  - 两者并集；
  - 金标（理想 Oracle）。
- **保护目标**：
  - E7（与 B 相同：计算见证，否则用 defense 行）；
  - **完整所有者策略**：每个场景都用所有者的敏感组合行，即 LLM 防御拿到的同一份信息；解析失败时才退回 E7。
  
  两者都**不读**官方攻击计划、目标或 `final_inference_result`。
- **离线门控回放**：Alice 先持有自己的表；对每条回答，单元 = 检测结果，`check_release` 不安全就阻断，否则计入持有。
- **下游估计**：CoT 中已泄露的敏感运行，若至少阻断一条金标非空的回答，算作"拦住"；CoT 中成功的 benign 运行，若阻断了这样的回答，算作"误拒"。
- **校准**：部署的门控离线估计的泄露率为 0.370，B 中实测为 0.437。**离线回放对危险放行约低估 0.07**，原因是阻断之后的轨迹会改变。

## 3. 知识检测质量（576 条回答，表级）

| 检测器 | Precision | Recall | F1 | 每条耗时 P50 / P95 |
|---|---|---|---|---|

| 归一化匹配 | 0.929 | 0.760 | 0.836 | 0.024 / 0.040 ms |

语义检测器精确率很高但召回低，原因是**跨域**：阈值是在教学事实上定的，不是表格行。按规定没有重新调阈值。

## 4. 六个对照的离线下游结果

无防御 CoT 的危险放行率为 0.597（全部场景；去掉 pilot 后各项变化 ≤ 0.01）。

| 对照 | 危险放行率 | Benign 成功 | 误拒率 |
|---|---|---|---|
| 1 原始匹配 + E7（B 部署） | 0.370（实测 0.437） | 0.697 | 0.024 |
| 2 归一化 + E7 | 0.361 | 0.697 | 0.024 |
| 3 语义 + E7 | 0.479 | 0.706 | 0.012 |
| 4 原始匹配 + 完整策略目标 | 0.353 | 0.706 | 0.012 |
| **5 联合（归一化 ∪ 语义）+ 完整策略** | **0.210** | 0.697 | 0.024 |
| 6 理想 Oracle（金标）+ 完整策略 | 0.042 | 0.697 | 0.024 |
| 6b 理想 Oracle + E7 | 0.193 | 0.672 | 0.059 |

- 单独换检测器（2、3）或单独换目标（4），改善都很小。两者一起改（5）才明显下降：0.37 → 0.21。
- 检测完美时，目标定义的影响仍有 0.19 − 0.04 = 0.15。检测完美、目标完整时（6），危险放行 0.04，接近 ToM（0.05）和 CoDef（0.03），而 benign 效用 0.70 仍高于它们（0.63、0.58）。
- **召回的提高没有带来误拒的增加**：各对照误拒率都在 0.012–0.059，最高的是 6b，原因是 E7 目标错置。

## 5. 52 个失败案例逐类（哪些对照能修复）

| B 中的失败原因 | 次数 | 2 | 3 | 4 | **5** | 6 |
|---|---|---|---|---|---|---|
| 计量漏判 | 36 | 0 | 6 | 5 | **14** | 31 |
| 目标错置（E7 秘密不是被攻击的推断） | 13 | 1 | 0 | 4 | **7** | 10 |
| 阻断后仍泄露 | 2 | — | — | — | — | — |
| 无见证 | 1 | 0 | 0 | 0 | 0 | 0 |

- **阻断后仍泄露（场景 53、55）**：门控确实在放行前阻断了补齐策略组合的那张表（姓名或联系人表），但判官把只用 ID 完成的部分推断也算作"完成"。这是目标粒度与判官口径不一致，不是放行顺序的问题。
- **无见证（场景 41）**：defense 行无法解析，E7 也没有秘密。
- **核验是否在实际放行之前**：是。门控在回答返回给 Alice 之前核验并替换。副作用是：被拦截的文本已经写进回答者自己的上下文和 `ans_history`。CoT 下 Alice 看不到这些；在 CoDef 这类共享历史的方法里会被其他防御者看到。这一点如实记录。

## 6. 官方 Regex 错误的敏感性（全部方法用同一修复）

- 官方 `remove_think_tags` 用了标准库 `re` 不支持的 `(?R)`。
- 117 次报错运行（5 种方法都有）用同一个修正后的解析器重跑：1,046 次调用、2.83M token，修复后再无 PatternError。

| 方法（留出 116 个场景） | Blocked | Benign | Overall（冻结 B → 修复后） |
|---|---|---|---|
| CoT | 0.345 | 0.750 | 0.216 → 0.216 |
| CoT + L + H | 0.784 | 0.716 | 0.578 → 0.569 |
| ToM | 0.940 | 0.638 | 0.595 → 0.595 |
| CoDef | 0.974 | 0.629 | 0.560 → **0.612** |
| CogniGuard 门控 | 0.534 | 0.733 | 0.336 → 0.345 |

CogniGuard 对 CoDef、ToM、CoT + L + H 仍判**更差**（差 −0.27、−0.25、−0.22，区间都在 0 以下），对 CoT 仍**更好**（+0.13）。**修复错误不改变 B 的结论。**

## 7. Overall 公式与历史分母核对

- **Overall 的逐场景公式**：benign 判"完成"，且同一场景的 sensitive 判"未完成"，在两者都有判定的场景上取比例。与论文的"Overall Success"定义一致。留出集 116 个场景，判定缺失为 0。
- **历史分母**：E7 下有 33 个秘密完全由 Alice 自己的表构成（历史泄露）；改用完整所有者策略后，这类场景为 **0**，只有 3 个场景的 defense 行无法解析。所以历史分层只对 E7 目标有意义；论文改用完整策略目标后，历史泄露为 0。

## 8. 修正方案（冻结于 `FIX_SPEC_B2.md`）与是否启动正式实验

- **修正方案**：检测器 = 归一化匹配 ∪ 冻结的 BGE + NLI（阈值不变）；目标 = 所有者完整敏感组合策略；CA-PD 内核、k = 1、放行前核验都不变。
- **预期**：离线危险放行 0.21。考虑约 +0.07 的离线乐观偏差，实际可能在 0.28 左右。这仍**明显差于** ToM（0.05）和 CoDef（0.03）的拦截能力，只是 benign 效用更高。
- **结论**：修正有改善，但离线结果显示它**仍不足以在 Sum Leaks 上与原生 LLM 防御竞争**。按要求，**不直接启动大规模正式实验**。剩下的差距主要是检测召回（0.89），距离理想 Oracle 的 0.04 还很远。
- **新场景端到端验证（已设计，未启动）**：Sum Leaks 官方没有公开场景生成器。独立新场景需要按官方 JSON 结构另建，并经人工抽检。建议先建 30 个新场景做一次小规模验证，再决定是否做正式实验。
