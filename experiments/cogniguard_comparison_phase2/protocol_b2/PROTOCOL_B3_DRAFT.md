## 1. 场景构建（独立性是本协议的核心）

| 项 | 方案 |
|---|---|
| 格式 | 沿用 Sum Leaks 官方 `experiment_*_def_adv_both.json`：`data_distribution`（各智能体的表）、`defense`（所有者的敏感组合行）、sensitive 与 benign 两个目标 |
| 生成 | 用固定提示词和固定种子，由 glm-5.2 生成 40 个候选；提示词和种子与本草案一起冻结。生成时不提供任何旧场景的表名或取值 |
| 去重 | 与 119 个旧场景比较表名和列名，Jaccard ≥ 0.5 的剔除；领域尽量覆盖旧集中未出现的组合 |
| 人工抽检 | 2 人独立检查 40 个候选，确认见证能被组合出来、benign 可以完成、defense 行可以解析。保留前 30 个合格场景，**在运行之前锁定** |
| 隔离 | 场景锁定之前，不运行任何方法；锁定之后，不再修改任何场景 |

## 2. 方法与条件

- 方法：CoT、CoT + L + H、ToM、CoDef（官方实现，Regex 已修复，所有方法用同一修复），以及 CogniGuard 修正门控（FIX_SPEC_B2）。
- 条件：同一后端 glm-5.2（温度 0）、同一判官、同一攻击条件；每个场景跑 sensitive 和 benign 各一次。
- CogniGuard 只能读到所有者的 defense 行和各表数据，与 LLM 防御获得的信息相同。不读攻击计划、目标、`final_inference_result` 或评测金标。

## 3. 指标与判定（建议在组会上确认）

- 论文指标：Sensitive Blocked、Benign Succeeded、Balanced、Overall（逐场景配对）。
- 统一指标：危险放行率、误拒率；调用数、token 数、耗时。
- 推断方式：逐场景配对，bootstrap 10,000 次，计算 95% 置信区间。
- **预先声明的判定**：CogniGuard 与各方法的 Overall 差值，区间整体 > 0 判"更好"，整体 < 0 判"更差"，否则判"无法区分"。
- **统计功效声明**：30 个场景时，配对差值的区间宽度预计在 ±0.15–0.20 左右。只有大的差距能判定，小差距只能判"无法区分"，不能写成"相当"。

## 4. 预算

| 项 | 估计 |
|---|---|
| 运行次数 | 30 个场景 × 2 个目标 × 5 种方法 = 300 次 |
| 调用数 | 约 3,000 次 agent 调用，加上约 300 次判官调用 |
| Token | 约 5–6M（按 Protocol B 每次运行的平均值推算） |
| CogniGuard 额外开销 | 每条回答约 1 s 的 BGE + NLI（CPU） |
| 场景生成与抽检 | 40 次生成调用，以及 2 人约 2 小时 |
