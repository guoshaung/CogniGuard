## 1. 设置核对

| 项 | 内容 |
|---|---|
| 官方代码 | github.com/Vaidehi99/MultiAgentPrivacy @ `6e7af5d`，按路径导入，**未修改** |
| 替换的部分 | 只有两个模型调用函数，指向同一个后端；判官用官方 `evaluate_final_inference` 的提示 |
| 统一后端 | glm-5.2（百炼 token plan，关闭思考，temperature 0），用于全部角色 |
| 论文的设置 | Qwen3-32B 加 Gemini / GPT-5。**本表数字不与论文表直接比较** |
| 任务 | 官方循环的全部 119 个场景，每个都跑 sensitive 与 benign，共 1,190 次运行，0 次缺失 |
| **留出测试集** | 去掉开发阶段看过的 3 个 pilot 场景（5、40、100），剩下 **116 个**作为主结果 |
| CogniGuard 拿到的信息 | 场景中的表，以及从表和所有者敏感标签计算出的 E7 见证（生成器只读 `data_distribution`，审计时读 defense 行）；没有计算见证的场景用论文自带的 defense 行，与 LLM 防御拿到的信息相同。**没有使用攻击计划、目标或 `final_inference_result`（测试真值）** |
| 官方代码自身的错误 | `remove_think_tags` 用了标准库 `re` 不支持的 `(?R)`，模型输出缺少 json 代码块时官方循环会抛出 `PatternError`。另有少量 `Agent 'Bot' not found` 和嵌套深度错误。各方法都受影响（ToM 12 次，其余各 25–29 次，留出集），按原样保留，日志照常判定 |

## 2. 论文指标（留出 116 个场景，场景级 bootstrap 95% 区间）

| 方法 | Sensitive Blocked | Benign Succeeded | Balanced | Overall | 调用 / 次 | token / 次 | 秒 / 次 |
|---|---|---|---|---|---|---|---|
| CoT（无防御） | 0.388 [0.30, 0.48] | 0.707 | 0.547 | 0.216 [0.14, 0.29] | 6.8 | 12.5k | 17.3 |
| CoT + L + H | 0.793 [0.72, 0.86] | 0.698 | 0.746 | 0.578 [0.49, 0.66] | 6.8 | 13.6k | 20.0 |
| ToM | 0.948 [0.91, 0.98] | 0.629 | 0.789 | **0.595** [0.51, 0.68] | 8.5 | 14.4k | 21.2 |
| CoDef | **0.974** [0.94, 1.00] | 0.578 | 0.776 | 0.560 [0.47, 0.65] | 13.4 | 25.7k | 29.2 |
| **CogniGuard 门控** | 0.552 [0.47, 0.64] | **0.698** | 0.625 | 0.336 [0.25, 0.42] | 6.8 | 12.6k | 17.7 |

**全量预算**：119 个场景 × 2 个目标 × 5 种方法，共 10,081 次调用、18.6M token，全部走 token plan，按量付费为 0。CogniGuard 门控本身不调用 LLM，判定耗时在微秒级，开销与无防御的 CoT 相同。

**统一安全—效用口径**：Sum Leaks 只有单一对手，相当于联盟规模 k = 1。场景级危险放行率 = 1 − Sensitive Blocked，正常效用 = Benign Succeeded。有界与无界联盟的区分在这一任务上不适用，所以只报告 k = 1。

## 4. 失败案例（`protocol_b_failure_cases.json`，全部保留）

| 类型 | 原因（评分侧诊断：攻击计划只在全部决定写出之后读取，从未提供给门控） | 次数 |
|---|---|---|
| 泄露 | **计量漏判**：LLM 用转述、格式变化或综合陈述透露了表内容，表值匹配没有识别出来 | 36 |
| 泄露 | **见证与被攻击的推断不一致**：E7 每个场景只选一个秘密，它不是这次攻击的目标 | 13 |
| 泄露 | 已有阻断，但仍从其他路径或部分回答泄露 | 2 |
| 泄露 | 场景无见证 | 1 |
| benign 失败 | 没有任何门控阻断，任务本身失败（与 CoT 基线相同） | 32 |
| benign 失败 | 门控阻断了 benign 回答 | 3 |

**历史泄露与系统新增泄露（事后分层，`posthoc_historical_strata.json`）**：

- 84 个 E7 见证中，有 33 个完全由 Alice 自己的表组成，也就是对手一开始就已持有（历史泄露）。门控对这类秘密无从拦截：其他智能体的回答不会触及这些单元。在这 33 个场景中，CogniGuard 的 Sensitive Blocked 为 0.364，与 CoT 相同。
- 其余 82 个非历史场景中，CogniGuard 的 Sensitive Blocked 为 0.634，Overall 为 0.402。仍然显著低于 CoDef（0.598）、ToM（0.634）、CoT + L + H（0.585）：差为 −0.18 至 −0.23，区间都在 0 以下。**负结果不依赖 E7 的选择问题。**
- Sum Leaks 中的所有敏感推断都需要对手提问，所以第 2 节的泄露都是系统运行中新增的。

## 5. 解读（负结果如实写明）

1. **在原生 LLM 多智能体任务上，CogniGuard-NoWM 门控不如论文的原生 LLM 防御。** 它比无防御好（Overall +0.12），但对 ToM、CoDef、CoT + L + H 的 Overall 低 0.22–0.26。它在 benign 效用上保持了无防御的水平，比 CoDef 高 0.12、比 ToM 高 0.07，但拦截率差得多。
2. **主要原因是计量（A1），不是联盟判定。** 36 / 52 次泄露是因为 LLM 用自己的话透露了表内容，而确定性表值匹配没有识别出来。这与 E3b-v2 中 A1 不成立的结论一致。CA-PD 的判定本身是精确的，但"文本 → 单元"这一步在真实 LLM 输出上漏判严重。
3. **第二个原因是秘密定义**：E7 为每个场景只选一个秘密，有 13 次被攻击的推断不是它，另有 33 个场景的选定秘密本来就已被对手持有。LLM 防御直接读 defense 行，覆盖的是整个敏感组合。
4. **与 Protocol A 的关系**：Protocol A 中，单元由结构给出（计量完美），CA-PD 对 Sum Leaks 式防御有清晰优势。Protocol B 表明，一旦计量换成真实的 LLM 文本，这个优势就**不再成立**。论文必须把"判定内核的优势"与"端到端系统的效果"分开写，并把计量列为当前的主要瓶颈。
5. **开销**：CogniGuard 门控不增加 LLM 调用（6.8 次 / 运行，与 CoT 相同）；CoDef 需要 13.4 次、25.7k token，约为前者的两倍。

## 6. 局限

- 单一后端模型、单次运行（temperature 0）；
- 判官也是 LLM；
- 门控计量用确定性表值匹配。没有接入 BGE + NLI 计量，因为 NLI 的阈值是在教学事实上定的，不适用于表格，而且本轮不新增方法；
- Self-voting 没有运行；
- OCELOT 原生无法复现，仍记 NA；
- 历史分层是事后分析。
