## 3. 必须如实写明的发现（解释性分析，未预注册）

1. **H1、H3 不成立，原因是 OCELOT 选出的预算很保守。** 开发集规则选出 B = 1.0 bit，小于 τ = 2。在这个预算下 OCELOT 只放行 25–29% 的正常请求，用大量拒绝换来低泄露。所以 H1 中 recip 泄露更少，并不是因为它更好地防住了合谋，而是因为它几乎什么都不放。
2. **在这份数据上，CA-PD 与 OCELOT 取 B = τ 时等价。** 开发集网格显示：
   - CA-PD(1) 与 OCELOT-recip(B = 2.0) 完全相同，泄露 0.678、放行 0.637；
   - CA-PD(2) 与 OCELOT-global(B = 2.0) 完全相同，0.444 / 0.440。
   - 原因：测试目标的泄露集 **98% 只含 2 个单元**（1263 / 1294）。联盟规模 k ≥ 2 已经覆盖了任何泄露集所需的人数，所以 CA-PD(k ≥ 2) 等价于"全体共用账本、在 τ 处拦截"。300 个回合中有 299 个 CA-PD(2) 与 CA-PD(3) 的结果相同。
   - **结论：** 在 Eedi 上，CA-PD 的"有界联盟"没有中间地带可以发挥，它与 OCELOT 在正确的账本范围、取 B = τ 时一致。CA-PD 的独特价值只会出现在泄露集大于 k 的场景，而本实验的数据中几乎没有这样的场景。
3. **形式保证 ≠ 实际不泄露。** 即使是只对真实联盟判定的 Oracle，独立攻击者仍然在 35–45% 的回合中猜中。CA-PD(k = c) 让联盟凑齐泄露集的比例为 0（形式泄露 0.00），但攻击者的独立泄露率仍有 0.34–0.36。原因与误设先验实验一致：τ = 2 时，只剩 2 道候选题就被视为"安全"，而攻击者在这种情况下常常能猜中；此外，攻击者的能力也超出了谓词的描述。
4. **探索性口径**（5 次中命中 ≥ 4 次，不参与判定）：三个条件合并后，CA-PD(k ≥ 2) 泄露 0.24，OCELOT B = 1.0 为 0.13–0.14，ToM-R 0.57，CoDef-R 0.51。结论方向不变。

## 4. 对论文的含义

- **站得住的结论：** 确定性的、联盟感知的组合判定（大模型识别 + CA-PD），在多提问者合谋下，泄露比 LLM 原生防御（ToM、CoDef）**低约 30 pp**，正常放行率持平或更高。这一点有独立攻击者的证据，也不是靠构造得出的。
- **站不住的结论：** "CA-PD 优于 OCELOT"。在本实验和 B4 中，OCELOT 只要取对账本范围并取 B = τ，结果就与 CA-PD 相同；取更小的 B 时，它更安全，但效用很差。
- **建议的定位：** CA-PD 是联盟有界的统一表述。k = 1 对应按人记账，k ≥ 最大泄露集大小时对应共用账本。它给出可审计的形式保证和精确的判定，但不宣称在这些数据上优于 OCELOT 的预算规则。
- **局限：**
  - 后端是无法验证的第三方转发模型；
  - 场景结构是我们设计的；
  - 对手按脚本提问，不自适应；
  - 每个条件只有一个回合；
  - 攻击者判定有噪声。
