# CogniGuard Phase 2 横向对比：预注册（冻结版）

> 冻结方式：本文件与 `PREREG.sha256` 在同一提交中推送，并早于正式种子运行。方法见 `METHOD.md`，基线见 `BASELINE_AUDIT.md`。
> **不预设 CogniGuard 占优**。正式集不改参数、不改门槛、不换测试集。

## 1. 开发阶段（种子 900–909，已执行，不计入正式结果）

- **实现核对**：未授权成功为 0；CA-PD 与精确枚举在 54,000 条请求上 0 处不一致。
- **初始状态**：eedi / sumleaks 的历史违规为 0；phase1 冻结世界含历史违规，按 METHOD 第 2 节分层报告。
- **开发中发现并修正的问题**（都在冻结之前）：
  - secrets 世界最初把全部单元都发行出去，导致所有秘密一开始就可被 2 人联盟补齐；改为发行部分单元，并保证全体并集不含任何见证；
  - 增加"排除历史目标"的分层指标。
- **工作点**：已冻结于 `results/dev/operating_points.json`。正式集只评估这些点；Pareto 图另外显示全部网格点。

## 2. 正式运行

- 种子 0–29；数据集 {phase1, eedi, sumleaks} × 传播条件 {low, high} × k ∈ {1, 2, 3}；
- snapshot：全部规则与全部参数点；
- path：主要规则，以及每个参数族在"危险放行率 ≤ 5%"的工作点。

## 3. 判定（每个单元格分别判定，如实报告每一格）

| 编号 | 问题 | 判定为"支持"的条件 |
|---|---|---|
| A0 | 实现核对 | 未授权成功 = 0，且 CA-PD 与 ExactEnum 0 处不一致；否则整体无效 |
| A1 | 相对 OCELOT-PF 的竞争力 | 在 OCELOT-PF 达到"危险放行率 ≤ 5%"的工作点上（field 与 trajectory 两种范围分别判），M3 的效用 − OCELOT-PF 的效用，配对 95% 下界 > 0，**且** M3 自身危险放行率 ≤ OCELOT-PF 的危险放行率 + 0.01（配对差的上界）。若 OCELOT-PF 在开发集上达不到 5%，判 NA |
| A2 | 相对 Sum Leaks 防御（Local、CoDef、ToM 的 5% 工作点） | 同 A1 的条件 |
| A3 | 相对 Staddon 定义与 WS04 配额 | 同 A1 的条件。另外按定义预先说明：CrowdControl 防守任意规模联盟，安全目标比 CA-PD(k) 更强，比较的是"同一请求流上的安全—效用取舍"，不是同一个安全定义 |
| A4 | 相对精确枚举的开销 | 报告 P50 / P95 之比，不作判定 |

**说明**：

- k = 1 时 CA-PD 就是单主体判定，与 SumLeaks-CoDef 在定义上完全相同，此时 A2 中对 CoDef 的比较判 NA；
- eedi 与 sumleaks 的见证大小多为 2，按命题 4，k ≥ 2 时 CA-PD 与 CrowdControl 预期一致。

## 4. 结论口径（事先固定）

- 在某个单元格中"有竞争优势"，指对该基线 A1–A3 支持；
- "无优势"或"更差"都如实写出；
- 不把信息优势当作算法优势：Protocol A 中所有方法拿到同一份证据，所以差异只来自判定规则。

## 5. 局限（事先写明）

- OCELOT 只能做到 PF：成本用精确后验（对 OCELOT 有利），U_R 与必要性检查无法复现；
- Staddon 只有 DEF：令牌算法未核实；
- Sum Leaks 只有 STR；
- Protocol B 中 OCELOT 记 NA，Sum Leaks 只引用论文自报数字；
- 第二阶段（原论文数据、新留出数据的泛化）不在本轮；
- 实际教学任务完成质量本轮没有测量。
