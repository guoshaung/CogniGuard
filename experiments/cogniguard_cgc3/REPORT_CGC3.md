## 候选 A：前瞻式双量（攻击者剩余不确定性 + 未来合法任务的安全可达性）

### 数学模型

- 单个接收方，或全体联盟（k = N，此时知识状态取并集 K）。
- 合法任务按 q 独立同分布到达，共 H = 6 步。任务类型 t 有若干个互为替代的选项 O_{t,1..r}，用其中任意一个服务即可；服务后 K ← K ∪ o。
- 硬约束：L\*(K) ≤ τ。目标是最大化期望服务数。
- **第一信息量**：L\*(K)，或最终攻击者的 V₁。
- **第二信息量**：安全可达性 R(K) = Σ_t q(t)·1[t 仍有安全选项]，即在安全约束下，未来合法需求还能被满足的程度。
- 精确最优解：在 (t, K) 上做动态规划，状态数 H·2^m。

### 算法

| 名称 | 规则 |
|---|---|
| **CONFLICT**（候选） | 见证冲突预测：在所有安全选项中，选择使 (H−t−1)·R(K ∪ o) − λ·L\*(K ∪ o) 最大的那个。每次决策 O(选项数 × 任务类型数) 次 L\* 查表 |
| 对照 | 即时 CA-PD（取第一个安全选项）、最少新单元、最小泄露、随机 |
| 对照 | LA（一步前瞻，允许延迟） |
| 对照 | EXPECTIMAX2（两步贝叶斯规划） |
| 对照 | ROLLOUT（滚动时域，24 个采样未来） |
| 对照 | OPT_SERVE（只服务、不延迟的精确最优） |
| 对照 | OPT（精确最优，允许延迟）；OPT_λ（带泄露惩罚） |

### 结果

576 个实例，泄露预算 V₁ ≤ 0.25 / 0.5 / 0.75，策略评估全部用 DP 精确计算。配对 bootstrap 95% 区间如下：

| 比较 | 任务完成率差 | 最终 V₁ 差 |
|---|---|---|
| OPT − 即时 CA-PD | +0.041 [+0.038, +0.045] | −0.002 [−0.007, +0.002] |
| **CONFLICT − 即时 CA-PD** | **+0.033 [+0.029, +0.036]** | **−0.023 [−0.027, −0.018]** |
| CONFLICT − 最少新单元 | +0.017 [+0.015, +0.019] | +0.006 [+0.004, +0.009] |
| CONFLICT − 最小泄露 | +0.017 [+0.015, +0.019] | +0.009 [+0.007, +0.012] |
| OPT − CONFLICT | +0.009 [+0.007, +0.010] | +0.020 [+0.016, +0.024] |
| ROLLOUT − CONFLICT | +0.006 [+0.005, +0.007] | +0.022 |
| OPT − OPT_SERVE（延迟的价值） | +0.006 [+0.005, +0.007] | 0 |
| LA − CONFLICT | −0.022 [−0.028, −0.017] | +0.020 |

- CONFLICT 拿到了 OPT 相对即时 CA-PD 增益的 **79% [76%, 82%]**。85% 的实例存在可改进空间；只有 4.5% 的实例 CONFLICT 低于即时 CA-PD。
- **相同累计泄露下**，见图 A：
  - CONFLICT_l1：完成率 0.900，最终 V₁ 0.319；最小泄露策略：0.885，0.316。泄露几乎相同，完成率高 1.5 个百分点。
  - OPT_l0.3 位于最外侧前沿：0.910，0.313。
- **任务分布误设下的鲁棒性**（相对即时 CA-PD 的完成率增益）：

  | 规划假设 | CONFLICT | OPT | EXPECTIMAX2 | ROLLOUT |
  |---|---|---|---|---|
  | 任务分布正确 | +0.033 | +0.041 | +0.037 | +0.038 |
  | 规划用均匀分布 | +0.028 | +0.025 | +0.022 | +0.027 |
  | 规划用错误分布 | +0.025 | +0.013 | +0.006 | +0.018 |
  | 有 3 类任务规划时看不到 | +0.028 | +0.018 | +0.016 | +0.023 |

  分布一旦误设，**CONFLICT 比精确最优和多步规划更稳健**。
- **计算量**：每次决策 CONFLICT 约 0.004 ms，OPT 约 0.01 ms（m ≤ 8，2^m 很小），ROLLOUT 约 0.2 ms。OPT 的状态数随单元数指数增长；CONFLICT 不会。

### 消融：每个信息量的独立价值

| 成分 | 价值 |
|---|---|
| 前瞻可达性 R | 有：CONFLICT 比不用 R 的贪心多 +1.7 个百分点 |
| 泄露项 λ | 小：λ 从 0 增到 1，完成率 −0.002，最终 V₁ −0.007 |
| 允许延迟 | 很小：+0.6 个百分点；而近似的延迟策略（LA）反而更差 |

### 失败模式

- **整体增益幅度小**：基线完成率已有 87%，多数实例约束不紧。
- **LA 的延迟估计校准很差**，在误设分布下低于即时 CA-PD（−0.029）。
- **CONFLICT 不主动节省泄露预算**：它的泄露高于"最少新单元"策略。
- 只测试了全体联盟（并集状态）。k < N 时，每个主体各有一个状态，没有测试。
- 任务池是合成的。

### 下一步建议（未执行）

1. 查新：在线约束覆盖、带前瞻的安全集合选择等方向。
2. 在 Sum Leaks / Eedi 上构造**真实的合法任务序列**，检验约束紧的时候增益是否放大。
3. 补 k < N 的情形。

## 候选 B：双通道泄露控制（内容 + 治理行为）

### 数学模型

- 攻击者已持有视图 K0，因此知道世界落在自己的格 C 内，然后请求单元 u。
- 机制是从世界到输出的**如实信道** M(o | x)，三种输出：
  - 放行真实值 (R, f_u(x))；
  - 降级为固定的二值粗化 (D, c_u(x))；
  - 拒答 X。
- 允许 M 依赖真实世界 x。攻击者知道 M，观察到的是**联合输出** o。
- **联合泄露**直接按 o 计算，不对各通道的量求和：
  - max-case：max_o max_s P(S = s | C, o) ≤ τ；
  - expected：Σ_o max_s P(S = s, o | C) ≤ τ（作为变体）；
  - I(S; O)。
- 同时报告两种常见错误：
  - 内容单通道计账：把拒答当作不含信息；
  - 互信息相加：I(S; A) + I(S; C)。

### 算法

- **LP_JOINT（候选）**：在 max-case 约束下最大化期望效用（放行 1、降级 0.5、拒答 0）。约束是线性的：对每个输出 o 和秘密值 s，Σ_x π(x)·M(o|x)·(1[s(x) = s] − τ) ≤ 0。
- **两步版本**：对两步输出做联合 LP，前缀输出和完整输出都要满足约束。对照是逐步短视 LP。
- **对照**：
  - CAPD_VI（值无关见证）；
  - CAPD_F（形式定义）；
  - CAPD_F_DEG；
  - SIM / SIM_DEG（可模拟审计，按格内最坏情况）；
  - RAND（与 x 无关的随机放行）；
  - LP_CONTENT（约束只加在内容输出上）；
  - LP_SIMUL（动作分布与 x 无关）；
  - LP_NODEG（没有降级动作）。

### 结果

1,040 个单步实例，τ ∈ {0.34, 0.5, 0.67}。只保留"请求在格内至少一个世界里不安全"的实例，因为只有这些实例上各机制的行为不同。

| 机制 | 效用 [95% 区间] | 联合 max-case 越界比例 | 内容计账判安全、实际越界 |
|---|---|---|---|
| CAPD_VI | 0.444 | **44.4%** | 0 |
| CAPD_F（形式定义） | 0.130 | **15.0%** | 15.0% |
| CAPD_F_DEG | 0.324 | **30.7%** | 21.2% |
| LP_CONTENT | 0.325 | **28.2%** | 28.2% |
| SIM（可模拟） | 0.000 | 0 | 0 |
| SIM_DEG = LP_SIMUL | 0.163 [0.149, 0.177] | 0 | 0 |
| RAND（max-case 下） | 0.000 | 0 | 0 |
| LP_NODEG | 0.107 | 0 | 0 |
| **LP_JOINT** | **0.285 [0.270, 0.300]** | **0** | 0 |

**配对差**：

| 比较 | 效用差 [95% 区间] | 含义 |
|---|---|---|
| LP_JOINT − SIM_DEG | +0.122 [+0.110, +0.134] | 允许"依赖秘密、但联合安全"的动作，带来的价值 |
| LP_JOINT − LP_NODEG | +0.178 [+0.164, +0.192] | 降级动作的价值 |
| LP_JOINT − CAPD_F（只看 CAPD_F 联合安全的 85% 实例） | +0.209 [+0.194, +0.224] | |
| 两步：联合 LP − 逐步短视 LP | +0.115 [+0.089, +0.142]（两步合计；平均每步效用 0.398 对 0.340） | |
| expected 约束：LP_EXP − 随机门控 | +0.106 [+0.100, +0.112] | |

**互信息相加不正确**：对 LP_JOINT，I(S;A) + I(S;C) = 0.598，而 I(S;O) = 0.452。各机制都存在这种偏差，相加会把泄露算多。

### 消融

- **治理通道建模**：
  - 去掉治理通道约束（LP_CONTENT）：效用升到 0.325，但 28% 的实例实际越界；
  - 改成可模拟（LP_SIMUL）：安全，但效用 −0.122。
  - 所以联合建模既保证安全，又避免了过度保守。
- **降级动作**：是效用的最大来源。

### 失败模式与局限

- **方法上没有新算法**：这是标准的最优信道 / 机制设计 LP。贡献只能写成"在治理中正确地联合计账，并给出可行的最优机制"。
- **假设治理方确切知道攻击者视图 K0**。在 CGC 中 K0 不确定（参见 L3h）；鲁棒版本要求约束对所有可能视图同时成立，没有实现。
- **多步时**，联合 LP 的输出数随步数指数增长：两步最多 77 个输出，每个实例约 40 ms。更长时域需要近似。
- max-case 约束下，随机门控毫无用处；只有在 expected 约束下随机化才有价值。
- 降级的设计（固定二值粗化）是任意设定的。

### 下一步建议（未执行）

1. 查新：最优信道设计、按输出约束的 LP、受控查询评估中的说谎 / 拒答审查器。
2. 实现"攻击者视图未知"的鲁棒 LP，在 L3h 的知识状态后验上检验代价。
3. 研究多步近似：滚动 LP，或对前缀分解。

## 候选 C：个体与联盟的协同信息控制（PID）

### 数学模型

- N = 1–4 个主体，各自持有 K_i。请求 (i, u) 是主体 i 的合法任务。
- 门控只用**信道层面**的信息量（在先验上取平均），所以决策不依赖真实秘密，没有拒答侧信道。
- 对源 V_i'（放行后的主体 i）和 V_{−i}（其余主体合并），分解
  I(S; V_i', V_{−i}) = Red + Unq_i + Unq_{−i} + Syn。
- 冗余量用两种定义：I_min（Williams & Beer）和 MMI。
- 安全目标（k = N）：I(S; V_all) ≤ b。可选地再加个体目标 I(S; V_i) ≤ b_i。

### 算法

| 门控 | 规则 |
|---|---|
| SYN（候选） | Syn ≤ b_s |
| SYN_IND（候选） | Syn ≤ b_s 且 I(S; V_i') ≤ b_i |
| COAL | I(S; V_all') ≤ b |
| COAL_IND | COAL 加个体约束 |
| IND | 只有个体约束 |
| CAPD_VI | 值无关见证 |

### 结果

864 个 episode，阈值全面扫描。"保证"指在**所有** episode 中联盟泄露都不超过 b。

| 设置 | 目标 | COAL / COAL_IND | SYN_IND（I_min） | SYN_IND（MMI） | SYN 单独 | IND 单独 |
|---|---|---|---|---|---|---|
| N = 1–4 合并 | 联盟 ≤ 0.3H | 0.353 | 0.353（相同） | 0.353 | 无法保证 | 无法保证 |
| | 联盟 ≤ 0.5H | 0.562 | 0.546（−0.017 [−0.021, −0.012]） | 0.549（−0.014） | 无法保证 | 无法保证 |
| | 联盟 ≤ 0.7H | 0.702 | 0.654（−0.048 [−0.056, −0.040]） | 0.657（−0.045） | 无法保证 | 无法保证 |
| N = 4（全体联盟） | 联盟 ≤ 0.7H | 0.698 | 0.615（**−0.083** [−0.105, −0.060]） | 0.622（−0.076） | 无法保证 | 无法保证 |
| 加个体 ≤ 0.3H | 联盟 ≤ 0.5H | 0.360 | 0.358（−0.002） | 0.353（−0.008） | — | — |

- **N = 1** 时没有其他主体，协同量恒为 0，所有方法退化为同一个。
- **只限协同量（SYN）在任何阈值下都无法保证联盟安全。** 原因是独有信息和冗余信息不受约束。
- **PID 与见证结构**：在全部"把单元分给两个主体"的方案中（1,148 种），
  - 协同量预测"跨主体见证"的 AUC 只有 0.57；
  - 不跨主体的方案里，58% 的协同量仍大于 0.1H。

### 数学原因

联盟互信息恰好等于四个 PID 分量之和，所以对联盟目标而言，直接约束联盟互信息就是精确条件。单步决策中，COAL 接受的请求集合，就是"满足联盟目标"的最大集合。任何基于 PID 的门控只能二选一：

- 拒绝更多（效用更低）；
- 或者接受会越界的请求（不安全）。

在序列决策中，我们也没有观察到 PID 门控起到"前瞻"的作用。PID 本身没有唯一定义（多源情形的冗余定义有争议），但这里两种定义的结论一致。

### 结论：**STOP**

协同信息没有提供超出"个体互信息 + 联盟互信息"的决策价值。

### 失败模式记录

- PID 门控在宽松预算下损失最大，−8.3 个百分点（N = 4）。
- 只限协同量不安全。
- 协同量与见证跨主体关系弱。
