# 预注册：LP 对偶影子价格 vs A1（在生成任何 P0 / P0b / 测试数据之前提交）

分支 `exp/cogniguard-shadow-price`，从 `exp/cogniguard-cgc-v5` @ 53a1b60 派生。
A1 来自 CGC4 冻结实现，原样使用：`a_engine.Policy("A1", gamma=0.3)`。CGC4 和 CGC5 的文件不做任何修改。

## 1. 方法（定义见 `sp.py` 文件头）

| 名称 | 角色 | 动作空间 |
|---|---|---|
| **SP_LP** | **主方法**：流体 LP 对偶（左导数）给出的单元价格，取价格最低的可行选项 | 只服务 |
| SP_DISP | 消融：位移成本 LP(s) − LP(s ∘ o) | 只服务 |
| SP_MYOPIC | 消融：LP 只包含当前请求（n = 1） | 只服务 |
| SP_D | 次要：SP_LP + 延迟（价格 > 1 时拒答） | 允许延迟 |
| A1_D | SP_D 的公平对照：A1 + 延迟（rem·Δrate > 1 时拒答） | 允许延迟 |
| A1、OCOST、MPC_OPT（d = 3，CGC5 开发集选定）、OPT_CANON_SERVE、OPT_CANON | 基线 / 上界 | — |

**没有可调参数。**
- 命题 1（MATH_SP.md）：只服务动作空间下，SP_LP 和 SP_DISP 的决策与 LP 时域 h 无关。
- 因此任务书中的"时域 ∈ {全时域, 10 步}"不需要开发集选择，固定 h = 剩余步数。
- SP_D 的接受阈值 1 就是即时奖励，也不调。

**对偶退化处理（测试阶段发现，在任何数据之前确定）**
- 推导集行的右端统一收紧 EPS = 1e-5，使对偶取左导数，即"消耗一单位剩余容量的边际损失"。
- 单单元残差行不进入 LP（其单元不在任何存活选项中）。

## 2. 场景与种子

**原场景**（与 CGC5 相同；测试集种子和任务序列也相同）

| 场景 | 开发集 | 测试集 |
|---|---|---|
| base / tight / overlap / conflict | 种子 0–39，E = 8 | 种子 100000–100059，E = 20 |
| KSL | 种子 0–59 | 种子 100000–100119 |
| Eedi 派生 | 偶数 id | 奇数 id |

**压力场景**（CGC4 生成器加上新参数；参数现在冻结，运行时注入，不修改 CGC4 文件）

| 场景 | 设置 |
|---|---|
| long | base，H = 24 |
| tight_conflict | m = 32，conflict = 0.9 |
| k1_N3 | base，N = 3，按主体分组（k = 1） |

**相对任务书的偏离（数据前声明）**
1. 不做"重尾任务价值"场景。CGC4/5 的奖励是每服务一次记 1，A1 的目标函数不含价值；加入价值就必须修改 A1 的目标，这违反"不修改 A1"。
2. 用 k1_N3 替代 large_kN：large_kN 的 n = 80，无法计算 OPT，也就没法测改进空间。
3. A1_FULL 不再运行：CGC5 中它与 A1 的逐步决策 100% 相同。
4. 原场景下 MPC_OPT 和 OPT 的测试结果直接取自 CGC5 的 `test_raw.json.gz`（种子和序列相同）。本轮重跑的 A1 必须与 CGC5 中的 A1 逐回合完全一致，否则原场景全部重跑。

## 3. 判定门

**P0（开发集，A1 轨迹上的状态）**
- LP 退化 STOP：λ 全为 0 的状态比例 ≥ 80%，且 LP 值 ≥ 全部存活需求的状态比例 ≥ 80%。
- 等价 STOP：在多选项状态上，SP_LP 与 A1 的决策一致率 = 100%，或与 OCOST 的一致率 = 100%。
- 报告 LP(H)/OPT 比值，表示松弛的强度。

**P0b（开发集）**
- 只服务分支：存在至少一个场景，OPT_CANON_SERVE − A1 ≥ 1.0 pp（开发集均值）→ 运行只服务的 SP 方法。
- 延迟分支：存在至少一个场景，OPT_CANON − A1_D ≥ 1.0 pp → 加跑 SP_D 与 A1_D。
- 两个分支都不满足 → STOP，不运行测试。

**P1（测试集，主判定只看 SP_LP vs A1）**
- 统计方法：配对 bootstrap，按实例重抽 2000 次，种子 0，取 95% CI。
- 记 Δ = SP_LP − A1（单位 pp），捕获率 = Δ / (OPT_SERVE − A1)。

| 判定 | 条件 |
|---|---|
| GO | ≥ 2 个场景同时满足 Δ ≥ +0.5、CI 下界 > 0、捕获率 ≥ 50%；其中至少 1 个是原场景；且没有任何场景 CI 上界 < −0.3 |
| 限定 GO | 同上，但达标场景全部是压力场景 |
| MERGE | 不满足以上两条，且（全部多选项步与 A1 的一致率 > 95%，或所有场景的 Δ 的 CI 都含 0） |
| STOP | 其余情况 |

- SP_D vs A1_D 作为次要比较，用同样的门单独报告。
- SP_DISP 和 SP_MYOPIC 只作为探索性结果报告，不参与判定。
- 测试之后不改门槛、不增删场景、不调参。
