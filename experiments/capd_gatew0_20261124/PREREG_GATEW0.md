# Gate W0：水印相对内容指纹的额外信息价值，预注册（冻结版）

> 冻结方式：本文件与 `PREREG_GATEW0.sha256` 放在同一个提交中推送。之后的任何修改都记入 `DEVIATIONS.md`。
> 草案见 `docs/research/prereg_drafts/PREREG_GATEW0_DRAFT.md`；理论依据见 `docs/research/THEORY_PROPAGATION_EVIDENCE_20261124.md` 第 4、5 节。
> 只用本地 CPU，不训练水印模型，不使用 GPU，不调用付费 API。**不预设水印优于内容指纹。**

## 0. 冻结前对草案的修改（均在看到结果之前确定）

1. **BGE 嵌入检索（F4）和语义重排序（F5）记为 NOT_RUN**：本环境中无法下载这两个模型，以后由本机的 Claude 补跑。在 F4、F5 补齐之前，**W0-1 的最终结论一律记为"无法判定"**，只报告相对"目前可运行的最强指纹"的**暂定**比较。不得据此宣称水印不可替代。
2. **增加 C\***：理想的**内容身份**通道。它的可恢复范围与 W\* 完全相同，但只恢复内容（单元），不恢复发行 ID。**W\* 与 C\* 之差，就是"发行身份"本身对联盟决策的价值**（用户决策第 4 条）。
3. **控制层使用合成数据**，因为只有合成数据上存在危险放行（见 Gate 0–2 冻结前的规模扫描）。每段发行文本都带上它所属秘密的上下文，例如 "In item set 16.3: …"。原因是：合成模板中，同一句话会原样出现在许多秘密里；如果不带上下文，就会出现"同一内容对应多个单元"的人为现象。这时用发行 ID 把它"缩小"为一个单元，在语义上是**不安全的**：持有相同文本，就等于持有相同信息。这一点作为理论注意事项写进 RESULT，不作为水印的优势。
4. **归因层使用 Eedi 的单元文本**，构造 S1–S4 四类场景。

## 1. 控制层（主要判定）

- 复用 Gate 0–2 的世界：合成数据 K = 16、32；sparse 图；coalition 模式；f = F_true = 8；k = 2；种子 0–29。
- 每次未记录的转发都会产生一段**观察文本**。它由发送方持有的每个单元的发行文本拼接而成，再经过一种变换：
  - identity：原样；
  - paraphrase：确定性的同义替换和语序规则，数字和集合编号保留；
  - fragment：每句只保留最后 5 个词，句首的上下文会因此丢失。
- 证据方法会从观察文本中恢复出单元，作为接收方的**持有证据**，按 B3 规则加入账本（k = 2，不使用预算）。

| 组 | 恢复方式 |
|---|---|
| none | 不用证据（等同 B0） |
| F1_sha | 按句子做 SHA256 精确匹配 |
| F2_minhash | 字符 5-gram MinHash（64 个排列），最高相似度 ≥ 0.5 时，取所有并列最高的候选 |
| F3_bm25 | 按词做 BM25，"最高分 ÷ 该候选与自身匹配的得分" ≥ 0.5 时，取所有并列最高的候选 |
| F4_bge、F5_bge_rerank | **NOT_RUN** |
| A1_minhash、A1_bm25 | 主动文本变体：每个接收者拿到的是按接收者确定选择的模板改写版本，再用 F2 或 F3 检索 |
| Cstar | 理想内容身份：只要片段还有 ≥ 4 个词，就恢复出真实单元 |
| Wstar | 理想水印：可恢复的范围与 Cstar 相同，此外还恢复发行 ID |
| F3_plus_Wstar | F3_bm25 与 Wstar 的并集 |
| Oracle | 在真实状态上判定 |

- 指标：
  - harmful_releases（危险放行）；
  - UR_normal；
  - 不必要拒绝率（以 Oracle 为参照）；
  - 单元级的恢复 Precision 和 Recall。

## 2. 归因层（描述性，Eedi）

- 用 Eedi 的单元文本构造四类场景：
  - S1：唯一内容，200 段；
  - S2：重复发行，60 段文本，每段发给 3 个接收者；
  - S3：高度相似内容，同一模板、只有内容不同的文本对，100 对；
  - S4：多来源融合，观察文本由 2 段发行文本的片段拼接而成。
- 每类再叠加三种变换：identity、paraphrase、fragment。
- 指标：
  - 发行 ID 的 Precision 和 Recall；
  - 内容（单元）的 Precision 和 Recall；
  - **歧义消除率**：返回的发行集合恰好只有一个，并且是正确的那一个。

## 3. 判定

- **W0-0（分解核对）**：在每次运行中，Wstar 与 Cstar 的控制层指标完全相同。理论第 5 节预测：持有证据只取决于内容身份，所以发行身份不会改变联盟决策。如果出现差异，要逐个列出原因。
- **W0-1（主假设，暂定）**：以 F_best 作为参照。F_best 是 F1–F3 中，在每个（数据集, 变换）单元格里危险放行均值最低的那个方法；若并列，取不必要拒绝率较低的。比较 F3_plus_Wstar 与 F_best：
  - 判"暂定有额外价值"的条件：至少有一个单元格，harmful_releases 之差（F_best − F3_plus_Wstar）的配对 bootstrap 95% 下界 > 0，并且在该单元格里，F3_plus_Wstar 的不必要拒绝率不高于 F_best；
  - 否则判"暂定无额外价值"；
  - **最终结论**：F4、F5 补跑之前一律记为"无法判定"。
- **W0-2**：比较 Wstar 与 A1_*。如果在所有单元格中，Wstar 的控制层指标都不优于 A1_* 中较好的那一个，就说明收益来自主动编码，而不是水印。
- **停止规则**：等 F4、F5 补跑之后，如果 W0-1 判为"无额外价值"，就停止水印拓展，不投入 GPU。
