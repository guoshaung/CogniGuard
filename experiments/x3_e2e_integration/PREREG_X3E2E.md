# X3-E2E：真实来源证据进入联合安全控制（预注册，冻结版）

> 冻结方式：本文件与 `PREREG_X3E2E.sha256` 同一提交推送。之后的修改记入本目录 `DEVIATIONS.md`。
> 接口：pe-1.0（`docs/integration/PROVENANCE_INTERFACE.md`）。代码：本目录 `run.py`（治理，无金标）、`score.py`（唯一读金标）、`grid.py`（网格与判定）、`build_education.py`、`adapters/codex.py`。
> **不预设 X3 成立，不把理想来源证据的收益当成真实收益。** Gate W0、并行扫描 X3 的历史 STOP 不变；本实验是新实验。

## 1. 问题

1. 真实来源证据（指纹、检索、签名凭证）进入动态安全状态后，能否减少危险放行（H-Evidence）？
2. 在最强真实内容证据之上，真实水印（M1）、知识绑定水印（M2、M3）、水印加内容核验（M1+source）能否再减少危险放行，且不降低效用（H-WM）？
3. 静态治理与动态治理的三个部件（知识更新、预算抵扣、疑似层）各自贡献多少（消融 A-*）？
4. 理想来源证据离真实证据还有多远（UB-IDEAL，只作上界）？

## 2. 对照组与治理模式

证据臂（`arms.py`）：每臂只读自己的通道，**不用其他通道补缺**。

| 臂 | 读取的证据 | 角色 |
|---|---|---|
| R0_receipts | 无 | 只有回执的基线 |
| F_STRONG | fingerprint + retrieval（SHA256、MinHash、主动变体、发行查表、BM25、BGE、BGE 重排序，取并） | **最强内容指纹** |
| CRED | signed_credential | 签名凭证（真实数据中无此通道时该臂与 R0 相同，如实报告） |
| WM_REAL | watermark（KBPW M1） | 真实水印 |
| KBW_REAL | knowledge_bound_watermark（KBPW M2、M3） | 候选知识绑定水印 |
| JOINT | joint（M1+source） | 普通水印 + 内容核验（联合证据） |
| CONTENT_ALL | F_STRONG ∪ CRED | 最强真实非水印证据 |
| CONTENT_ALL_WM | CONTENT_ALL ∪ WM ∪ KBW ∪ JOINT | 全部真实内容证据（联合证据） |
| LOG | trusted_log（模拟签名通道日志，覆盖率 0.5） | 事件证明；**单列**，不进入内容对比（最坏情况入账会压倒任何内容信号） |
| ALL_REAL_LOG | CONTENT_ALL_WM ∪ LOG | 描述 |
| IDEAL | ideal（由标注构造的真实持有与发行） | **理想来源证据，只作上界**，不作为任何方法的结果 |

治理模式（`cogniguard/provenance/decision.py`）：`static`、`dyn_knowledge`、`dyn_full`、`dyn_conservative`，定义见接口第 6 节。每个证据臂 × 每个模式都运行。

## 3. 数据

### 3.1 教育四 Agent 场景（主场景）

- **真实部分**：Codex KBPW 真实传播试点（`codex/hsw-st`），12 份 OpenStax 来源、15 条传播链（转发、摘要、轻改写、强改写、截断，融合 1–3 源），Qwen2.5-7B 第 1–5 跳文本；第 1、3、5 跳终点的逐条事实保留标注；各检测器在同一批文本上的输出。
- **构造部分**（`build_education.py`，规则固定）：
  - 主体：教师 T（全部资源的所有者）、学生 SA、SB、助教 Agent TA、无授权外部 Agent EXT。issuer-a / issuer-b 的发行分给 SA / SB（种子决定对应关系）。
  - 回执：被发行的学生持有该来源的全部事实单元。
  - 传播持有者：第 1、2 跳 TA，第 3、4 跳另一名学生，第 5 跳 TA；每一跳都是未登记传播。
  - 秘密叠加：每个事实 f 配一道考试题 q(f)，目标见证为 {f, q(f)}（知道该事实的人拿到对应考题即泄露考试）。
  - 请求：每个终点的持有者请求本链来源每个事实对应的考题（同一主体对同一考题只请求一次）；再请求 3 道与本链无关来源的考题（效用分母）；EXT 请求 1 道（授权核对）。
  - 链的处理顺序按种子打乱，时间 = 100 × 序号 + 跳数，请求在观测后 0.5。
- **金标**（`gold/gold.json`，只给 `score.py`）：终点真实保留的事实（未登记获得）、终点的真实发行历史与来源、请求角色。

### 3.2 变体

`plain`、`M1`、`M2`、`M3` 四套文本各建一个场景。水印臂只在自己的变体上有观测；内容臂在每个变体上都有。**主比较都在同一变体、同一批文本内进行。**

### 3.3 证据映射（`adapters/codex.py`，固定）

方法 → 类型见适配器表。所有方法使用同一规则产生单元声明：所返回来源的全部登记事实 + 方法自报的事实（`pred_fact`）。核验器用同一知识核验（包含度 ≥ 0.95）决定哪些确认。检测器阈值沿用 Codex 已在校准分区冻结的阈值，**本实验不调任何检测阈值**。

### 3.4 软件工程资产保护场景

协议、臂、指标、判定完全相同，用现有 `code-domain adapter` 的资产。**当前阻塞**：没有任何检测器在代码产物上的真实输出。在 Codex 提供代码产物上的 pe-1.0 观测之前，不运行、不报告软件场景的正式结果；届时按本协议另建 `build_software.py`，变更记入 `DEVIATIONS.md`，在运行前推送。

## 5. 指标

| 指标 | 定义 |
|---|---|
| 危险放行 | 放行且已授权，但在决策时刻的真实知识上 `check_release(k)` 不安全 |
| 错误授权（未授权成功） | 放行但 `AccessRegistry` 不授权 |
| 误拒 | 拒绝，但真实知识上授权且安全 |
| 效用 | 1 − 误拒 / 真实可放行数（合并各簇） |
| 联盟违规（描述） | 结束时由放行造成、≤ k 人联盟可补齐的见证数；含决策后才发生的未登记获得，不可在决策时预防 |
| 错误归因率（描述） | 观测的发行候选中含非真实发行的比例 |
| 开销 | 每次决策耗时中位数（检测耗时由 Codex 单列） |

## 6. 判定（`grid.py`，主单元格 (1, 0)；其余单元格同规则报告）

- **H-Auth（实现核对）**：全部运行未授权成功 = 0。否则判实现失败，整个实验停止。
- **H-Evidence**：CONTENT_ALL vs R0_receipts（`dyn_knowledge`），危险放行减少量的 95% 下界 > 0 且效用下降 ≤ 0.01 → 支持；只满足前者 → "仅安全"。
- **H-WM（主）**：在 M1、M2、M3 上，CONTENT_ALL_WM vs CONTENT_ALL（`dyn_knowledge`）。规则同上；**基线危险放行已为 0 → STOP（基线已安全）**。至少一个变体"支持"才可写"真实水印在最强内容证据之上有增量"。
- 描述性对比：WM_REAL、KBW_REAL、JOINT 各自对 F_STRONG。
- **消融**：A-dynamic（CONTENT_ALL_WM：dyn_knowledge vs static）、A-suspected（dyn_conservative vs dyn_knowledge）、A-log（LOG vs R0）。
- **A-credits 只描述**：本场景每条链有 5 次未登记传播，未登记事件总数远超 f，理论 4.2 的条件 1（f 可强制执行）**按构造不成立**，k + (f − d) 没有安全保证；只报告其后果。
- **UB-IDEAL**：IDEAL vs CONTENT_ALL_WM，只作上界，不能写成任何方法的收益。

## 7. 失败判据与公平性

**停止 / 无效**：
1. 任何运行出现未授权成功；
2. 治理侧读取金标（运行器没有金标参数；场景、观测含金标字段即拒收；`test_x3e2e.py`）；
3. 正式运行中出现 mock 记录；
4. Codex 观测未通过提供方契约；
5. 基线已安全的单元格对应假设判 STOP。

**公平性**：
- 所有臂使用同一批产物、同一核验器与知识核验、同一请求序列、同一 `check_release`；
- 每臂只读自己的通道；
- CONTENT_ALL_WM 与 CONTENT_ALL 只差水印通道；
- 检测阈值不在本实验调整；
- 理想证据单列为上界；
- 耗时在同一机器上测。

**Grok 的治理实现**：若以 `DisclosurePolicy` / `StateUpdater` 接入并通过消费者契约，作为额外治理模式运行，与参考模式并列报告；不通过则不纳入。

## 8. 冻结前空跑（种子 99，已执行）

704 次运行（4 变体 × 4 (k, f) × 11 臂 × 4 模式），未授权成功为 0；所有单元格都可判定（0 个"无法判定"）。

空跑中发现两处问题，都在冻结前改掉：
1. LOG 的最坏情况入账压倒内容信号，于是把 LOG 从内容对比中拆出；
2. f = 0 时预算抵扣无意义，A-credits 改到 (1, 1) 并只作描述。

空跑数值不报告。
