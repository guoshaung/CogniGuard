## 2. Issue #16 的 C5 失败

集成侧在 Issue #16 对本地提交 `0e48995` 做了只读探针（`integration/provenance-governance@eec96b6`）：薄适配之后，消费者契约只剩 C5 失败，现象是已核验的内容持有不进入知识状态。后续说明（`b23c42c`）写明：按本设计，NLI 证据不进入知识状态。

C5 的检查写在集成树 `cogniguard/provenance/contract.py`。夹具对持有者 B 的水印观测给出单元 U2，文本核验判定该单元出现在产物中。动态模式必须因此把“向 B 再放行 U3”从允许改成拒绝。静态模式不读确认层，被豁免。失败句是：动态模式忽略了已核验持有。

本分支的知识合并只接受带持有者的 `trusted_log` 或 `ideal` 行（`source_state.py`）。水印和指纹即使 `verification_status=verified`、`confidence=1`，`is_trusted_event()` 仍为 false，单元不进入传给 `check_release` 的知识字典。`ProvenanceLink` 把这两类保持为候选或未知，`ledger_writable` 为 false。模式 `real` 不接纳 ideal。签名凭证可以核实发行身份，不确认后续一跳，也不写持有事实。

NLI 蕴含与上述内容核验是同一类观测。pe-1.0 把“词面包含度至少 0.95，或 NLI 判为 entailment”定义成确认单元 C_o。本仓库的证据类型里没有 NLI 通道。把蕴含标签标成一条已核验水印或指纹，仍然到不了知识状态。这个 C5 失败是该规则的直接结果。本次不改规则去通过 `check_consumer`。

## 3. 不允许 NLI 核验知识进入状态的依据

依据来自已经写明的不确定状态约束，不是一条新定理。`docs/research/NEW_DIRECTION_UNCERTAIN_STATE_20261124.md` 仍是候选笔记，本文不把它采纳为定理。其中与本决定有关的三条是：

1. 证据只能抬高知识下界，不能证明某个主体不知道什么。恢复失败、neutral、contradiction 都不是“未持有”。下界一旦被降低，`check_release` 会漏掉真实联盟。所以未恢复来源的 `propagated` 保持 `None`，后一轮缺失解码也不擦除先前由可信事件写入的持有。
2. 若不确定集必须覆盖一切未记录传播，则内容证据揭示的传播已经在该集合之内，不能单独产生安全收益。能收紧不确定预算的，是端点已知、签名有效、去重后的传播事件。内容判断没有端点签名，不能充当这个事件。
3. 内容检出说明的是文本与某个单元或回执的关系，不是“名为 h 的主体经一次传播获得了单元 u”。独立生成、公开转述、复制标记都可以在文本上成立，同时没有这一跳。假归因把持有估高。在单调的联盟检查上，估高只会把允许变成拒绝，伤害的是可用性。漏检才会在乐观入账时伤害安全性。

NLI 是两个文本之间的模型判断。它不提供持有者、发行身份和传播事件这三项里的任何一项。把它写入联盟状态，等于把一条可能为假的文本关系当成 `check_release` 已无法再区分的持有事实。pe-1.0 的性质 B2 要求确认单元是持有者真实持有的子集，确认层才不增加相对真实状态的误拒。NLI 不满足这一个前提。集成报告把由此产生的误拒记为 Codex 报告、尚未推送的 4/835；本分支没有这些逐条判定，不引用 99/137、F1 0.825 或 137→38 作为结果。拒绝入账不依赖那个未复核数字：前提不成立时，入账就不再是下界更新。

## 4. 与 pe-1.0 确认层的区别

pe-1.0 的确认层 K^c 在回执之外，写入两样东西：核验器判定出现在产物中的单元 (h, u)，以及签名事件的最坏情况闭包。疑似层再并上未核验声明。状态只增不减。授权只看 `AccessRegistry`。内容证据，包括 NLI，对预算抵扣 d 的贡献恒为 0。性质 B1 保证知识变大只会把允许变成拒绝。C5 要求动态模式消费这个变大，从而忽略已核验内容持有即为失败。

本设计与它对齐的部分是：证据不授权；未核验和冲突不成为账本事实；内容证据不产生预算抵扣；缺失不是删除。分歧只有确认层的成员资格。pe-1.0 认为“产物里核验到该事实”本身就是持有事实，证据类型不限。本设计认为进入 `check_release` 知识字典的新增持有，必须是带持有者的可信日志或理想证据。NLI、水印和指纹停在观测侧。因此同一条已核验内容持有，在 pe-1.0 的动态模式里会收紧决定，在本影子路径里不改变相对注册表基线的允许位。C5 失败标出的就是这一条成员资格差异。通过契约需要把内容核验写入状态，那会改掉第 3 节的入账条件。本次不改。

## 6. 最终结论

在与注册表基线相同的信息下，X3 没有独立增益。判定保持 STOP。不新增命题，不用联动测试的通过标准改写入账语义。

来源治理若要产生新的拒绝，只能来自注册表之外的可信事件，或来自理想证据这种上界。普通水印、指纹和 NLI 蕴含都不是这种事件。pe-1.0 确认层选择把内容核验写入 K^c，并用单调性把假阳性限制成误拒；本影子路径不写入。两条设计可以并存为对照，不能把其中一条改写成另一条来换取 C5 通过。

工程集成、适配器和本次推送都不是科研贡献。真实水印试点仍为 ABSENT。在 Codex 推送可复核的逐条检测之前，不运行 X3-E2E 联动实验，也不把本分支合并进主分支。
