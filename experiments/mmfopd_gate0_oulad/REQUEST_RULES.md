# MM-FOPD Gate 0 请求规则与闸门（冻结）

本文件在查看任何推断结果之前写定。写定之后不得改规则、换标签、换课程、换模型或换阈值来凑通过。本文件的 SHA-256 记在 `DATA_FREEZE.json` 的 `documents` 里，不写在本文件内部。

阶段 B 只执行这里写明的步骤。做不到或必须偏离时，停止并写入 `DEVIATIONS.md`，不悄悄改规则。

## 1. 人群

课程选择只看注册人数，不看敏感标签，也不看模型。

在 `code_presentation = 2014J` 的课程里，按 `studentRegistration` 行数从多到少取前 3 门。人数相同则按 `code_module` 字母升序。结果是：

| 顺序 | code_module | code_presentation | 注册行数 | module_presentation_length |
|---|---|---|---:|---:|
| 1 | CCC | 2014J | 2498 | 269 |
| 2 | FFF | 2014J | 2365 | 269 |
| 3 | BBB | 2014J | 2292 | 262 |

分析单位是一条注册：`(code_module, code_presentation, id_student)`。三门课共 7155 行，7019 个学生。136 个学生各出现在其中两门课，没有学生三门都出现。同一学生的所有行进入同一个训练或测试侧。

`studentInfo` 与 `studentRegistration` 在这 7155 个键上一一对应。退课日期不使用，退课的学生仍留在人群里。

## 2. 训练与测试

按学生划分，不按注册行划分。预期大约 6:4，由哈希决定，不另设随机种子。

```text
train if int(sha256(ascii(str(id_student))), 16) % 10 < 6
else test
```

`id_student` 先变成不含符号的十进制字符串，再做 SHA-256。同一个学生永远在同一侧。划分在拟合任何模型之前就固定。

## 3. 周次

日期是相对开课日的整数。第 t 周（t 从 1 起）包含：

- t = 1：所有 `date < 7`，包括开课前的负日期
- t ≥ 2：`7 * (t - 1) <= date < 7 * t`

观察点只有四个。事件进入该观察点的条件：

- 第 4 周：`date < 28`
- 第 8 周：`date < 56`
- 第 12 周：`date < 84`
- 全学期：`date < module_presentation_length`

晚于课程长度的记录不进入任何观察点。

## 4. 三个 Agent

请求只使用分数、提交时间和点击。敏感标签和其他被标为禁止使用的字段不得读取。Exam 整类排除。`is_banked = 1` 的提交整行排除。对不上 `vle.activity_type` 的点击排除。

资源类型词表按字母序固定为这 16 个，只来自这三门课的 `vle` 行：`dataplus`、`dualpane`、`forumng`、`glossary`、`homepage`、`htmlactivity`、`oucollaborate`、`oucontent`、`ouwiki`、`page`、`questionnaire`、`quiz`、`repeatactivity`、`resource`、`subpage`、`url`。

### 辅导 Agent

每一周看截至该周末已经提交、并且有分数的 TMA 和 CMA。排序键是 `date_submitted` 升序，相同时 `id_assessment` 升序。

- 最近一次分数 `< 40`：该周发出 1 次 `tutoring`。
- 至少已有 3 次分数，且最后两次都是严格下降：该周发出 1 次 `review_session`。
- 两个条件可以在同一周同时成立。没有可用分数的周，两个请求都是 0。

### 教务 Agent

对每一次落入该周的 TMA 或 CMA 提交，如果 `date_submitted > assessments.date`，发出 1 次 `extension`。同一周多次迟交就累加。分数缺失不影响迟交判断。

提前提交且分数 `>= 80` 不发请求。准时、提前但分数不足 80、以及其他没有迟交的提交，也不发请求。教务 Agent 没有第二种请求。

### 资源 Agent

只看这一周的点击，不累加更早的周。学生在各资源类型上的点击占该周总点击的比例，与同一门课、同一个开课期里“该周至少有 1 次点击”的学生的中位数比较。中位数用该课全体学生的点击计算，包括测试集学生，但不使用任何标签。它是课程侧的统计，不是攻击模型的参数。

该周总点击 `>= 10`，且某个类型的占比与中位数的绝对差 `>= 0.20`，就发出 1 次 `format_<activity_type>`。高于或低于中位数都算。一个周可以对多个类型各发一次。总点击不足 10，或该周没有点击，则不发。

## 5. 攻击特征

接收方看不到原始分数、点击和标签，只看到请求计数。观察点上的特征是从第 1 周累加到该观察点的计数。没有请求的位置记 0，不留空。

- 单个 Agent：只用该 Agent 的请求类型。
- 两两合谋：拼接这两方的计数，不放入第三方的列。
- 三方合谋：拼接三方全部计数。

列名在 `per_student.csv` 里写成 `w4__tutoring`、`w8__review_session`、`w12__extension`、`wfull__format_forumng` 这种形式。观察点记号是 `w4`、`w8`、`w12`、`wfull`。

训练集上整列都是 0 的请求类型，从该次拟合的特征里去掉，测试集也去掉同一列。全部列都被去掉时，该格的 AUC 记为无法计算，不能据此通过闸门。

## 6. 模型和对照

依赖版本以 `DATA_FREEZE.json` 里的记录为准，阶段 B 不升级。

逻辑回归：`LogisticRegression(solver="lbfgs", C=1.0, max_iter=1000, random_state=20261116)`。不设置 `penalty`、`class_weight`。特征先在训练集上用 `StandardScaler` 拟合，再变换测试集。只对逻辑回归做标准化。

决策树：`DecisionTreeClassifier(max_depth=3, random_state=20261116)`，其余用 scikit-learn 1.9.1 的默认值。用原始计数，不标准化。

两个模型都只在训练侧的学生上拟合。

对照 A 是上界，直接用行为，不用请求，也不用敏感标签。每个观察点、每条注册包含：

- 该观察点内的总点击 `clicks_total`
- 16 个资源类型各自的点击
- 有分数的 TMA/CMA 提交次数 `n_scored`
- 这些提交的平均分 `mean_score`；没有提交时记 0
- 迟交次数 `n_late`
- 平均迟交天数 `mean_lateness`，即 `date_submitted - assessments.date` 的平均；包含早交的负数；没有可比较的提交时记 0

列名同样带观察点前缀，例如 `w4__clicks_total`、`w4__clicks_forumng`、`w4__n_scored`、`w4__mean_score`、`w4__n_late`、`w4__mean_lateness`。

对照 B 是下界。每个标签单独打乱，只打乱一次：训练集用 `numpy.random.Generator(numpy.random.PCG64(20261116))`，测试集用种子 `20261117`。打乱的是该标签已有取值的那些行。然后用同一套特征和同一套模型拟合、评估。

## 7. 指标

每个标签只保留该标签有定义的行。

- `disability`：`Y` 为 1，`N` 为 0。
- `imd_band`：`0-10%` 或 `10-20` 为 1，其他非空取值为 0，空值整行不参与这个标签。
- `age_band`：`55<=` 为 1，`0-35` 和 `35-55` 为 0。

阳性类是 1。AUC 用 `roc_auc_score`。平衡准确率的分类阈值，逻辑回归是预测概率 0.5，决策树是预测类别。测试集只有一个类别时，该格无法计算，不能通过闸门。

报告的分母是：该标签在测试集中有定义的注册行数，以及这些行里不同的学生数。训练集的同样两个数也要写上。

95% 区间按学生重抽样。从该标签的测试学生中有放回抽取同样人数，抽 1000 次。一个学生被抽中 k 次，其全部注册行就重复 k 次。一次抽样里不足两个类别则丢弃。有效抽样少于 900 次时，区间记为无法计算，该格不满足“下界 > 0.55”。区间是有效抽样的 2.5 和 97.5 百分位。点估计仍用完整测试集，不用抽样均值。AUC 和平衡准确率都给区间；闸门只看 AUC 的区间。

## 8. 闸门

闸门对逻辑回归和决策树分别判断，不把一个模型的 AUC 和另一个模型的区间混在一起。单 Agent 的比较也在同一个模型内部进行。

设某个标签、某个观察点、某个模型上，三方合谋的 AUC 为 C，三个单 Agent 的 AUC 最大值为 S。

- **通过**：至少存在一个标签、一个观察点和一个模型，同时满足 `C >= 0.65`、该模型 AUC 的 95% 区间下界 `> 0.55`、以及 `C >= S + 0.03`。S 只在三个单 Agent 里都能算出 AUC 的那些值中取最大。三个都无法计算时，这一格不能通过。
- **部分通过**：没有达到通过，但至少有一个标签、一个观察点、一个单 Agent、一个模型的 AUC `>= 0.65`。部分通过不要求区间，也不要求合谋有提升。
- **失败**：通过和部分通过都不成立。

判断顺序是先看通过。已经通过时不再记成部分通过。失败时写 `final_decision.md`，说明每个标签的最好结果和分母，然后停止这一方向。

`RESULT.md` 的主表是标签 × 观察方 × 观察点 × 模型。观察方包括三个单 Agent、三个两两组合、三方合谋、对照 A 和对照 B。对照不参与闸门。

## 9. per_student.csv

一行一条注册。至少包含：`id_student`、`code_module`、`code_presentation`、`split`、三个标签列 `disability_y`、`imd_low`、`age_55`，以及第 5 节和第 6 节列出的全部计数和行为列。标签缺失留空，不填 0。请求计数和行为计数没有缺失，没有发生就写 0。

阶段 B 报告里的每个 AUC、平衡准确率和区间，都必须能只靠这个文件和本节写明的模型重新算出来。
