# 相对阶段 A 冻结规则的偏离

阶段 A 提交 `0e1036eb567b362a4fdc38aa4d01f23ec528820e` 里的课程、标签、阈值、模型和闸门数字仍然有效。确认冻结版本之后，阶段 B 开始前要求对齐下面四条口径。这里只记录这些预先写明的偏离，不根据推断结果再改。

## 1. 课程 one-hot 进入所有攻击模型

冻结规则里的攻击特征只有请求计数。现改为：每个单 Agent、每个两两合谋、三方合谋、对照 A 和对照 B，都额外带上课程身份的 one-hot。列名是 `course_BBB`、`course_CCC`、`course_FFF`，取值 0 或 1，三列都保留。

两两合谋和两个对照本来不在这句原文里。它们使用同一组公开课程列，避免对照和合谋比较又混进课程基线。闸门仍只看单 Agent 和三方合谋。

## 2. 观察周只使用当时已经能看到的记录

冻结规则的第 4、8、12 周上界是 `date < 28/56/84`。现改为含边界：观察周 \(W\) 只使用 `date <= 7W` 的记录。因此第 4、8、12 周的上界分别是 28、56、84，当天包含在内。`date <= 7` 仍算第 1 周，开课前的负日期也算第 1 周。第 \(t\) 周（\(t>1\)）是 `7*(t-1) < date <= 7*t`。

全学期没有一个整数 \(W\)。它的上界仍是 `date < module_presentation_length`。全学期的“当周”指该课最后一天所在的那一周，不是第 12 周。

`extension` 按“截止日已到且当时看不到按时提交”触发，而不是等以后的 `date_submitted` 出现再追认。一条 TMA 或 CMA，在 `deadline <= 7W` 且 `deadline < module_presentation_length` 时才可能计入观察周 \(W\)：若存在 `date_submitted <= deadline` 的非 banked 提交，则不算 extension；否则算 1 次。触发周是截止日期所在的周。同一次评测只计一次，不在之后的周重复累计。判断时不读取 `date_submitted > deadline` 的行，因此也不会读取 `date_submitted > 7W` 的迟交。Exam 和 `is_banked = 1` 仍然排除。

辅导 Agent 的分数序列只保留 `date_submitted <= 7W` 且分数非空的 TMA/CMA。更晚的分数不能改写更早一周的触发。某一周的触发用该周末的上界计算，之后不再回写。

对照 A 的 `n_late` 使用同一个未交定义。`mean_score` 和 `mean_lateness` 只统计 `date_submitted <= 7W` 的提交。

## 3. 资源中位数只用训练集

冻结规则用同一门课全体学生的点击计算中位数，包括测试集。现改为：每个课程、每一周、每种资源类型的占比中位数，只在该课训练集里、且该周至少有 1 次点击的注册上计算。训练行和测试行都用这个训练集中位数来决定是否发出 `format_<type>`。测试集点击不进入中位数。某一周没有符合条件的训练注册时，该周不发资源请求。

占比、绝对差至少 0.20、该周点击至少 10、双侧偏离，这几条不改。

## 4. 特征里同时放累计次数和当周状态

冻结规则只有截至观察点的累计计数。现改为每个请求类型两列：

- `w4__tutoring` 这种列是第 1 周到该观察周的累计次数。
- `w4__tutoring_now` 这种列是该观察周是否新触发，0 或 1。

教务在同一周有多次未交时，累计次数加上次数，当周状态仍记 1。辅导和资源每个类型每周最多触发一次。全学期的 `_now` 是课程最后一周的状态。

第 4、8、12 周和全学期四个观察点都这样生成。模型先丢掉训练集上整列为 0 的列，逻辑回归再做 `StandardScaler`。这些处理不改。

## 5. 达标是否连续出现

单点闸门的数字不改：仍是同一个模型上 \(C \ge 0.65\)、AUC 的 95% 区间下界 \(> 0.55\)、\(C \ge S + 0.03\)。

另外标注稳定：观察点顺序是第 4 周、第 8 周、第 12 周、全学期。同一标签、同一模型在相邻两个观察点都满足上面三条，才算达标信号连续出现。这只是标注，不把单点通过改写成必须连续。单 Agent 的 AUC \(\ge 0.65\) 是否在相邻观察点连续出现，另行标注，不并进三方合谋的稳定判定。
