# Chronology 单轮诊断与有限多轮验证

在同一公开 Llama 3.2 1B 权重、同一 27 状态码本和同一组种子下，分别生成偏置 0 与偏置 2 各 6 份单轮输出。每组预设两个发行者身份各出现 3 次。三种观测使用同一次生成，分别读取原始生成 token、去除特殊符号后的 token，以及公开文本重新分词的 token。完整码本的准确率以唯一最高票的正确状态计算。另报一个已知轮数的限制候选集诊断。

- 偏置 0 的完整码本唯一准确数为原始、去特殊符号、公开三个视角均 0/6。限制为第一轮格式后为 3/6。
- 偏置 2 的完整码本唯一准确数为三个视角均 5/6。限制为第一轮格式后为 6/6。唯一失误的目标码字与最高票并列，按固定顺序选中了另一状态。
- 12/12 份输出的可见 token 与公开重分词 token 完全一致。原始 token 中含特殊符号时，本样本中三个视角的最高票选择仍相同。

偏置 2 达到预设单轮门槛，即至少 5/6、超过无偏置组，且公开结果和原始结果最多差一个。随后继续首两个固定次序的试次，两轮后和三轮后的真实历史前缀均为 0/2。

- 第一条链首轮并列后选中空身份。第二轮解码以 26 票的差距正确恢复了当轮嵌入状态，但嵌入已经携带错误前缀。第三轮继续丢失新增身份，目标码字比胜出码字少 23 票。
- 第二条链首轮正确。第二轮生成 3 个原始 token，去掉特殊符号只剩 2 个公开 token，解码并列。第三轮以 31 票差正确恢复了已被上轮破坏的历史。
- 这四个后续输出的可见 token 与公开重分词 token 也完全一致。首轮并列、短输出和反馈中的错误继承足以解释这两条链的失败。全部 16 个输出出现代码围栏，续写风格偏离原任务。

这是已知精确作者代码缺失时的论文重实现诊断。码本宽度和模型细节承接原 Pilot 的实现选择。单轮使用六样本批生成和交替指定身份，续跑只用两个观察样本，无法估计可靠的三轮准确率。单轮总生成耗时约 98.0 秒，CPU 每样本摊销约 8.17 秒，GPU-hours 为 0。首个诊断进程因 NumPy 布尔值序列化失败未留下结果行。修正后在独立目录以相同实验配置完成。
