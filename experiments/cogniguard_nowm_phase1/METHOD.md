# CogniGuard-NoWM 综合实验 Phase 1：方法

> 完整方法暂名 **CogniGuard-NoWM**：BGE + 原版 NLI 驱动的动态知识状态 + CA-PD 有界联盟判定。**不含任何水印**，也不代表包含 RKW 的最终系统。
> 复用：`check_release`（CA-PD 内核）、`AccessRegistry`、pe-1.0 的 `SecurityState` / `RuleVerifier`、`NliReplayChecker`、Codex 冻结证据。没有修改任何历史实验。

## 2. 统一场景（`world.py`）

- **主体（9 个）**：学生 S1–S6、助教 Agent TA、辅导员 Agent COUNSELOR、外部 Agent EXT（无授权）；资源所有者为教师 T。
- **授权**：学生和 TA 对全部教学来源有 `study` 授权；TA 和 COUNSELOR 对每个学生画像有 `support` 授权。请求流过半时，**撤销** TA 对 4 个教学来源的授权（策略版本提升），之后 TA 对这些来源的请求、以及基于派生产物的请求，都由注册表拒绝。
- **发行**：12 个来源各发给一名学生，每名学生 2 个来源、6 个单元。
- **教师保密知识**：10 个秘密，见证大小为 2、2、3、3、3、4、4、4、5、5。每个见证取自不同来源的事实，至少跨 2 名发行学生；不同见证不共用单元。所以任何单个主体在初始时都补不齐。
- **学生画像敏感属性**：每名学生 1 个秘密，见证大小为 3、3、4、4、5、5，由合成信号单元组成，初始无人持有。
- **跨主体共享与多轮累积**：每条真实传播链从其来源的发行学生出发，第 1、3、5 轮终点依次落到按种子抽取的 3 个其他主体手中。持有者真实获得的是该终点**标注保留的事实**（真实知识丢失），属于未记录传播。
- **未记录传播条件**：
  - `low`：只有第 1 轮终点（15 次）；
  - `high`：第 1、3、5 轮全部（45 次），再加 6 次合成画像泄露（辅导员把 1–2 个信号转给同伴，没有文本，也没有任何证据）。
- **请求流（300 条）**：
  - 55%：学生学习请求（随机事实）；
  - 15%：TA 学习请求；
  - 20%：画像请求（TA、辅导员、或无授权同伴）；
  - 10%：EXT 越权请求。

## 3. 知识状态层（`simulate.py`）

所有规则都从**同一种**状态层读知识，所以"规则不同"等于算法差异，"层不同"等于信息差异。

| 层 | 内容 | 用途 |
|---|---|---|
| `receipts` | 发行回执 + 本次运行已放行的交付 | 只有回执 |
| `nli` | receipts + BGE 候选中经 NLI 确认的单元（pe-1.0 `SecurityState` 的 confirmed 层，证据到达时更新） | 动态知识状态 |
| `true` | receipts + 全部未记录获得（真实保留事实 + 合成泄露） | 上界；Oracle 用这一层 |

NLI 不产生事件，也不抵扣预算；证据永远不授权。

## 4. 规则（`policies.py`）

每条规则都先要求 `AccessRegistry` 授权。

| 组 | 规则 | 默认读取的层 |
|---|---|---|
| B0 | 传统访问控制：只看授权 | — |
| B1(b) | 累计披露预算：接收者持有的受保护单元数 ≤ b；b ∈ {2, 4, 6, 8, 10, 12, 16, 20, 24, 32} | nli（同证据） |
| B2 | 固定配额（Woodruff–Staddon 2004 §8）：每个见证 W，单人至多 ⌊(\|W\| − 1)/k⌋ 个单元 | nli |
| B3 | 成对联合泄露控制（结构代理，**不是 OCELOT**）：只对大小 ≤ 2 的见证做 k 联盟检查 | nli |
| B4 | 全局知识并集：全体持有之并加本次放行，不得补齐任何见证 | nli |
| M1 | 动态知识状态 + 单主体组合判定（CA-PD，k = 1） | nli |
| M2 | 仅回执 + CA-PD（k） | receipts |
| M3 | **CogniGuard-NoWM**：NLI 动态知识状态 + CA-PD（k） | nli |
| Oracle | 真实持有 + CA-PD（k），即相同授权下的精确判定 | true |

**证据消融**：B1–B4、CA-PD(1)、CA-PD(k) 都在 receipts、nli、true 三层各跑一次。

## 5. 指标

| 指标 | 定义 |
|---|---|
| 危险放行率 | 放行的危险请求 / 危险请求。危险请求 = 已授权，且在决策时刻的真实状态上 CA-PD(k) 不安全 |
| 正常任务效用 | 1 − 不必要拒绝 / 安全请求。安全请求 = 已授权，且在真实状态上安全 |
| 不必要拒绝率 | 1 − 效用 |
| 未授权成功率 | 放行的未授权请求 / 未授权请求 |
| 组合泄露违规率 | 运行结束时，因本次运行的放行而变得可被 ≤ k 人联盟补齐的秘密所占比例。其中包括放行之后才发生的未记录获得，所以 Oracle 也不为 0；论文中报告相对 Oracle 的超出量 |
| 判定时间 | 每次规则判定的 P50 / P95（微秒，不含证据检测） |

## 6. 正确性与非退化检查（`checks.py`，冻结前已执行）

- CA-PD 的 DP 与独立的暴力联盟枚举：4,000 / 4,000 一致；
- 满足 WS04 配额的状态都是 k-安全的：3,225 / 3,225；
- 非退化（每个传播条件 × k 单元格）：
  - Oracle 同时有安全请求与危险请求；
  - k ≥ 2 的危险请求中，联盟需要补的缺失单元数为 1–4，不止 1 个；
  - k < w 的危险请求占多数。
