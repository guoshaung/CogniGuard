## P1 伪造 / 窃取攻击（最重要；只需 CPU，加少量 3B 打分）
目的：检验"锚点密钥"能否防止攻击者从大量输出中学出水印词表。
- 攻击者模型：攻击者拿到同一密钥下的 N 份带水印输出（N = 10、50、200；从第 1 批及 T5 的水印输出中按种子抽取），不知道密钥。
  - 统计句首连接词的出现频率，减去未加水印背景中的频率，取超出最多的前 m 个词（m = 4、8）。
- **伪造（spoofing）**：在 200 篇**未加水印**的 in-domain 文本中，按与原方法相同的规则（句首、不进题干标题）插入学到的 m 个词。
  - 用真实密钥的检测器检测，报告被判为"有水印"的比例。
  - CertInsert 和 RC 各跑一遍；RC 使用其全局密钥对应的检测器。
- **擦除（scrubbing）**：从 200 份带水印输出中删除学到的 m 个词，报告删除后仍能检出的比例。
- 每个格子都要报告 k/n，以及按源文本聚类的 bootstrap 区间。
- 预期结果写在协议里：RC 的伪造成功率随 N 上升，CertInsert 应明显更低。**不论结果如何都如实报告。**

## P2 受保护区域被修改的统计（只需 CPU）
对第 1 批 RC 和 CertInsert 的全部水印输出，统计每份输出的插入落在哪类区域：
- 标题 / 小节标签；
- 题干（problem statement）；
- 讲解正文；
- 与知识锚点相邻（同一句内含公式或数值）。

报告"至少有一处插入落在标题或题干中的输出比例"。CertInsert 应为 0，RC 如实报告。

## P3 T5：LLM 生成讲解（7B，需 GPU）
- 本地 7B 模型只看 OpenStax 题干生成讲解，200 篇（不够就按实际数量）。题干来源与 T1–T4 的章节不重叠。
- 生成参数冻结，不重试、不修复；解析器使用 EVAL-02 已适配 Markdown 的冻结版本。
- 跑 CertInsert、RC、指纹；攻击做无攻击、OCR、开头 / 中段 100 词摘录。
- 按长度分箱报告覆盖率。

## P4 人工盲评（由两位合作者完成，不需要 GPU）
- 抽样：从 T4 + T5 中 CertInsert 和 RC 都成功加水印的源里按种子抽 50 个；不足 50 就全取。
- 每个源准备 3 个版本：原文、CertInsert、RC，随机打乱，评审者看不到方法名和插入标记。
- 两位评审各自独立评分，每个版本标注：
  - (a) 自然度 1–5 分；
  - (b) 是否引入原文没有的关系（时间先后、因果、强调、对比），标是或否，标"是"时写出具体句子；
  - (c) 是否有知识错误。
- 报告：每种方法的均值和分布、(b) 的比例、两人的一致性（Cohen's kappa）。
- 评审包里不得出现密钥、方法名或插入位置信息。

## P5 配对基线（7B，需 GPU；有余力再做）
- KGW 和 Unigram 只在 CertInsert 成功加水印的源上运行：第 1 批的 39 个，加上 P3 中成功的部分。必须全部跑完。
- 攻击：无攻击、OCR、两种摘录、70% 压缩（每源 1 次）。压缩输出要记录实际长度比和数值公式是否完整。
- 指纹在全部压缩输出上统计来源识别。

## P6 扩大背景对照（只需 CPU）
从同批教材的非例题正文中抽取 ≥500 段 in-domain 背景段落，与所有测试集不重叠。报告 CertInsert 和 RC 的误报率，以及 1000 个随机 key 的经验 p 值校准。
