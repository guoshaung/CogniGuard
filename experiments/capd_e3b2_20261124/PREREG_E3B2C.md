# E3b-v2 对照：把改写换回原始模板文本，A2 再测一次——预注册

> 这是在看到 E3b-v2 的 H3 结果（36% 的单元视图超标）**之后**设计的后续实验，但在运行之前冻结。冻结方式同前：本文件和 `PREREG_E3B2C.sha256` 放在同一个提交中推送。
> 目的：分清 H3 的超标来自哪里——是**改写带出了额外信息**，还是**攻击者靠题目内容（例如自己解题）做出了谓词以外的推断**，后者即使不改写也会出现。

## 1. 设计

与 E3b-v2 的 A2 完全相同，只有一处不同：**视图文本用数据集原始的模板句**，不用 P1 改写。
- 相同的内容：100 个秘密、攻击顺序、攻击者（token plan 上的 `glm-5.2`，temperature 0.7，关闭思考模式）、提示词、每个视图 5 次采样、合法性规则。
- V0 与主实验共用，不重复跑。
- 视图：unit 702 个、combo 100 个、decoy 100 个，都用原文。

## 2. 统计量（与 H3 相同）

对每个单元视图，取 p(s\*) 的均值和 t 上界（自由度 n − 1）。阈值是 1/|𝒮_u| + 0.15。合法采样少于 3 次的视图不参与判定。

## 3. 判定

- **C2（主）**：只看两次都参与判定的单元视图。对每个视图记下"是否超标"（按 t 上界），计算"改写 − 原文"的差的均值；按秘密重抽 5000 次（种子 20261125），取 95% 区间。
  - 区间下界 > 0：**改写带出了额外信息**；
  - 区间上界 < 0：**改写透露的反而更少**；
  - 其余情况：**无显著差别**。
  - 同样的分析用点估计（均值 > 阈值）再做一遍，只报告，不判定。
- **C1**：原文单元视图的超标比例（按 t 上界）。> 10% 时记为"原始文本也超标"，即不经改写，攻击者也能从题目内容中推出谓词以外的信息。
- **按单元类型分开**（描述性）：点估计超标比例，改写与原文对照列出，重点看正确答案类单元。

**解读规则（事先定好）**：

| C1 | C2 | 结论 |
|---|---|---|
| 原文也超标 | 无显著差别 | H3 的超标主要来自攻击者对题目内容的推断，与改写无关 |
| 原文也超标 | 改写带出额外信息 | 两种来源都有 |
| 原文不超标 | 改写带出额外信息 | H3 的超标主要来自改写 |
| 原文不超标 | 无显著差别或更少 | 两次都处在临界状态，无法归因；如实报告 |

## 4. 冻结前的空跑（已执行）

在主样本以外的 3 个秘密上，用原文跑了一次：29 个单元视图都可以判定，175 次采样全部合法。主实验的空跑用的是 kimi-k3，没法配对，所以空跑只检查 C1 能否判定。
