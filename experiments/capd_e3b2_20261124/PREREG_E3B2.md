# E3b-v2：真实改写文本上的计量器（A1）与谓词充分性（A2）——预注册

> 冻结方式与 E5、E6 相同：本文件和 `PREREG_E3B2.sha256` 放在同一个提交中推送。之后的修改记入 `DEVIATIONS.md`。
> 依据：用户的任务书 `E3B2_TASK_FOR_CLAUDE.md`。与任务书不同之处（模型替换、温度、攻击规模）见第 6 节和 `DEVIATIONS.md`。旧的 E3b 目录不动，也不复用它的预注册。

## 1. 数据

- E6 的 Eedi「考哪道题」秘密（`../cogniguard_data/eedi_exam`），**只用 K = 8**。
- 用种子 2026 从 283 个 K = 8 秘密中抽出 100 个（`sample.py`）。每个秘密的文本：
  - 全部 `unit` 文本（共 702 段）；
  - 用种子 `2026/<target_id>` 选出 1 段 `combo`、1 段 `decoy`。
  - 合计 902 段。
- 候选题的显示顺序按秘密用种子打乱，正确答案落在第几个位置大致均匀。
- 题目原文和改写文本只放在 `../cogniguard_data/e3b2/`，不进仓库。

## 2. 改写

- P1 = DeepSeek 官方 API 的 `deepseek-flash`。官方目前只提供 `deepseek-flash` 和 `deepseek-v4-pro` 两个模型，前者是通用模型。
- P2 = 百炼 `qwen3.7-plus`。
- 两者都关闭思考模式：试调 5 次，`reasoning_content` 均为空。temperature 0.7，每段文本、每个模型各改写 1 次。
- 提示词见 `prompts.py`：在任务书原文的基础上加了"用英文输出"，因为题目、单元名称和两个计量器都是英文的。
- 事实检查（只描述）：原句与改写之间的 4-gram 字符覆盖率，报告分布。

## 3. 计量器（A1）

- `LexicalMeter`、`PredicateMeter`，都用默认参数，存储方式与 E6 预注册完全相同：
  - lexical：单元库存放该单元类型模板 0 的渲染结果；
  - predicate：槽位别名和取值别名都设为显示值。
  - **运行前不调参。**
- 计量范围：该秘密的全部单元。
- 标准单元：沿用原文本的 `gold_units`，即假定改写保留了全部事实；这个假定的可信度由事实检查描述。

## 4. 攻击者（A2）

- 攻击者 A = 百炼 `kimi-k3`，关闭思考模式（试调 5 次，推理 token 为 0，JSON 全部合法）。
  - 任务书指定的 `glm-5.3` 在百炼上**无法关闭思考模式**（平台报错：`enable_thinking` 只能设为 True），所以按任务书第 6 节改用 `kimi-k3`。
  - `kimi-k3` 不接受 temperature 0.7，所以使用平台默认温度。
- 输入：8 道候选题的题干和选项，加上一段视图文本。要求输出 JSON（所选编号，以及 8 道题的概率），解析规则见 `prompts.parse_attack`。
- 视图：
  - V0 空视图；
  - 每个 unit 的 **P1 改写**；
  - combo 的 P1 改写；
  - decoy 的 P1 改写。
  - 只攻击 P1 的改写，原因是预算（第 6 节）；P2 只用于 A1。
- 每个（秘密, 视图）采样 N = 5 次。
- 预测值：1 / |𝒮_A|。其中 A 是该文本的标准单元集合；V0 和 decoy 的 |𝒮_A| = 8。

## 5. 假设与判定

- **H1（A1，主假设）**：对 P1、P2 分别计算 `PredicateMeter` 在 unit + combo 改写文本上的单元漏判率。点估计 ≤ 0.05，并且 bootstrap 95% 上界 ≤ 0.10（按秘密重抽 5000 次，种子 20261124，取第 97.5 百分位）。两个模型都满足才判支持。`LexicalMeter` 只报告。
- **H2（先验核对）**：V0 上的命中率，bootstrap 95% 上界（按秘密重抽）≤ 1/8 + 0.15。
- **H3（A2）**：对每个单元视图，取 5 次采样中攻击者给真实取值的概率 p(s\*)，用 t 分布（自由度 n − 1）计算 95% 上界。超过 1/|𝒮_u| + 0.15 的视图记为超标；超标视图占比 ≤ 10% 时判支持。超标视图逐个列出。合法采样少于 3 次的视图不参与判定，单独计数。
  - **与任务书的差别**：任务书写的是"命中率的上界"。但每个视图只有 5 次采样时，即使 0 次命中，Wilson 上界也有 0.43。这已经超过 |𝒮_u| ≥ 4 的视图的阈值，这些视图会被机械地判为超标，H3 实际上无法判定。
  - 这里改用 p(s\*) 的均值：它就是"按攻击者给出的分布随机猜"的期望增益，与 `FORMAL_DEFINITION.md` 第 4 节的 V̂ 一致。只要文本没有透露谓词以外的信息，任何策略的期望增益都不超过 1/|𝒮_A|。
  - 按命中率加 Wilson 上界的版本作为敏感性分析报告，不用于判定。
- **H4（描述性）**：combo 视图的 p(s\*) 和命中率，减去 1/|𝒮_A|；decoy 视图的同样两个量，减去 1/8。

一律按"支持 / 不支持 / 无法判定"报告。不得在看到结果之后改动阈值、统计量或样本。

## 6. 预算与攻击规模（按费用事先确定的规则）

- 上限 50 元，全部模型合计，**包括试调和空跑**。单价按 2026-11-24 查到的价格中偏高的一端计（见 `budget.py`）：
  - kimi-k3：每百万 token 输入 20 元、输出 100 元（百炼价格页）；
  - qwen3.7-plus：2 / 8 元（原价，不计限时折扣）；
  - deepseek-flash：按高峰价 $0.30 / $1.20 计。
- 实测：每次攻击调用约 0.025 元。100 个秘密 × 约 10 个视图 × 5 次 ≈ 5000 次调用，约 125 元。即使降到任务书允许的 60 个秘密也要 75 元左右，都超过上限。
- **规则**：
  - 改写和 A1 用全部 100 个秘密（不到 1 元）；
  - 攻击按固定顺序逐个秘密进行（种子 `2026/attack-order` 打乱 100 个秘密的顺序），每开始一个秘密前检查"已花费 + 该秘密的预计费用 + 1 元余量"是否超过 50 元，超过就停止；
  - 已完成攻击的秘密就是 H2–H4 的样本。预计约 34 个，实际数字在 RESULT 中报告。
  - 这条规则只取决于费用，与任何结果无关。
- 并发：每个模型最多 8 个请求同时进行；限流或 5xx 错误时指数退避，最多重试 5 次。仍然失败的调用记为缺失，**不用其他模型的结果补上**。

## 7. 冻结前的空跑（已执行）

- 从主样本以外抽 3 个 K = 8 秘密（种子 `2026/dry-run`），共 35 段文本，走完改写、攻击、分析全流程，只看能否判定。
- 结果：
  - H1：P1、P2 各有 35 个标准单元，可以判定；
  - H2：3 个秘密，可以判定；
  - H3：29 个单元视图参与判定，没有合法采样不足的视图；
  - H4：combo、decoy 视图各 3 个；
  - 改写缺失 0 段，攻击输出不合法 0 次。
- 空跑和试调累计费用 4.97 元，计入 50 元上限。
